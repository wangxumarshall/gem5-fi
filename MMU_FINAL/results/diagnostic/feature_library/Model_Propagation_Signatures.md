## Key discriminators

- **M01**: tlbi_match; tlbi_suppressed; mmu_fault_arm; mmu_fault_disarm; fault_site=tlb flush suppression
- **M02**: refill_pfn_corrupt; old_pfn!=new_pfn at refill; PTE memory value unchanged
- **M03**: candidate_asid (foreign); lookup_outcome=false_hit; candidate_entry_id/generation
- **M04**: tlb_entry_lineage; fault_entry_consume on resident entry; no PTW before activation
- **M05**: partial_entry_insert; next_table_pa_before/after; decoy_va
- **M06**: fault_state_consumed; fault_result_propagated; exception_delivery; pte_memory_written=0
- **M07**: permission_before=false; permission_after=true; permission_eval deny; no address corruption

## Confusable propagation paths

- **M02 vs M08** — both W10 read contexts end in a wrong PA/sentinel 0x60  
  Separator: M02 has refill_pfn_corrupt with old_pfn 0x834b2 -> 0x834b3; M08 keeps PFN and changes Request PA at setPaddr (request_pa_before 0x834b2000 -> 0x834b3000).
- **M01 vs M03** — both consume a stale/foreign TLB entry without a fresh walk  
  Separator: M01 has tlbi_match + tlbi_suppressed + mmu_fault_disarm and a retained L2 entry; M03 has candidate_asid != request ASID and lookup_outcome=false_hit, with no suppression.
- **M02 vs M04** — both substitute a PFN in a TLB entry  
  Separator: M02 activates at refill after ptw_start/pte_read; M04 activates on a real resident hit (tlb_entry_lineage, fault_entry_consume) with no PTW.
- **M03 vs M04** — both redirect a translation to another allocated page  
  Separator: M03 candidate ASID differs from the request ASID; M04 candidate/decoy PFN has the same ASID and a lineage join.
- **M05 vs M02** — both reach a wrong leaf PFN through the walker  
  Separator: M05 corrupts the intermediate next-table base (next_table_pa_before/after, decoy_va) at L2; M02 corrupts the completed leaf PFN at refill.
- **M06 vs all** — M06 is a detection signature, not a silent wrong value  
  Separator: fault_state_consumed + fault_result_propagated + exception_delivery; terminal DETECTED_CONTAINED.
- **M07 vs all** — M07 changes only the permission decision  
  Separator: permission_before=false -> permission_after=true with an unchanged VA/PA/PFN; control SIGSEGV permission fault.

## Similar features across models (low specificity)

These are shared by many models and must **not** be used alone for root-cause diagnosis: `translation_result`, `lsu_request`, `cache_request/lookup/response`, `memory_response`, `rf_writeback`, `commit`, `consumer`, `chain_end`. The W10/W10S oracle sentinel pattern is also shared by M02, M06 and M08. The wrong-PFN outcome is shared by M02, M04 and M05; the foreign/stale entry consumption is shared by M01 and M03.

## Features suitable for root-cause diagnosis (ranked)

1. **Trace fault site + activation kind** — highest specificity (`mmu_fault_arm`, `refill_pfn_corrupt`, `tlb_lookup_miss_false_hit`, `tlb_lookup_hit_pfn_subst`, `ptw_insertPartialTableEntry`, `ptw_doLongDescriptor_valid_clear`, `mmu_checkPermissions64`, `mmu_translate_set_paddr`).
2. **Activation state delta** — the old/new PFN, descriptor, permission, next-table-PA or request-PA fields and the entry/ASID relations; these separate M02/M08, M03/M04, M05/M02 and M07.
3. **Upstream path** — PTW before activation (M02/M05/M06) vs resident hit (M04) vs TLBI suppression (M01) vs permission eval (M07).
4. **Terminal/containment pattern** — DETECTED_CONTAINED + exception_delivery (M06), SQUASHED before arch update (M03 R01-R04), silent SDC (the rest).
5. **Downstream event kinds** — lowest specificity; useful only after the origin is anchored. Literal VA/PA/PFN/entry IDs/ticks are context values, not stable diagnostic features.

## TraceCompleteness is not PropagationStatus

M03 R01-R04 are `TraceCompleteness=COMPLETE` with `PropagationStatus=PARTIAL` and `TerminalState=SQUASHED`; their real squash is preserved. M06 R01-R05 are COMPLETE + FULL + DETECTED_CONTAINED. The library keeps both dimensions separate.

## Honesty notes

- `ManifestationType` is an added diagnostic dimension; the original `TerminalState` is never overwritten.
- M04 tags almost every post-arm event with `fault_id=1`; the library therefore anchors relevance on the activation translation/VA and the frozen chain, and caps non-chain selection. The chain join still has zero mismatches.
- M07 R04/R05 require a co-temporal join (`translation_id=0` on the fetch activation); the strict chain supplies it and the join is not inferred from event order.
- Nodes not emitted by the frozen binary are listed per sample in `NodesNotEmittedByFrozenBinary`; they are not fabricated.
