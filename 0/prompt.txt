一、ITEM-289（L03-F6）

禁止将“内存序违规”近似映射到 SqForward。

原因：
- SqForward 与内存序违规不是同一微架构事件；
- 近似映射会改变模型语义，使结果不可解释；
- 不能为了让项目产生激活而把现有事件冒充目标事件。

当前处理：

1. 将 ITEM-289 正式标记为：
   capability-gap / design-blocked / 当前实现不可激活。

2. 本轮16项中：
   - 15项按载体事件供给不足路线继续；
   - ITEM-289不得进入现有重跑批次；
   - 不得计入“已修复并完成重跑”的项目。

3. 后续采用独立的 MemoryOrderViolation 事件源解决：
   - 不修改现有四种F6事件源的含义；
   - 不复用 SqForward 名称或统计；
   - 明确定义事件产生条件、触发位置、eligibility、故障写入点和守恒关系；
   - 能区分 event_seen、eligible、triggered、fault_applied、faults_injected；
   - 必须提供正对照、负对照、count-only、最小注入和确定性重放；
   - 作为模型语义变更单独提交，不能夹在OBS补丁或普通接线修复中。

建议提交标题：
[LSU][SEM-F6] Add explicit memory-order-violation event source

在该设计和验证完成前，ITEM-289保持capability-gap，不得用替代事件生成结果。
