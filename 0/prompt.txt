一、决策点1：不扩充L5终类

保持L5五类闭集不变：

- Masked
- SDC
- Crash
- Timeout
- sim_fail

NoInjection、InvalidInjection、NoEffect不属于程序执行终态，而属于“注入是否有效”的资格维度。不得把它们添加成第六种L5结果，否则会混淆注入有效性与注入后的架构结果，并破坏既有统计口径。

采用正交的注入有效性字段。correction overlay至少记录：

- raw_class：原始分类，永久保留；
- trigger_observed：是否触发；
- fault_write_attempted：是否执行故障写入；
- fault_effective：目标状态是否实际改变；
- valid_for_l5：是否有资格进入L5分类及其统计分母；
- exclusion_reason：无效原因；
- evidence_path：判定证据；
- corrected_class：仅valid_for_l5=true时填写，否则为null。

exclusion_reason至少区分：

- pre_filter_rejected_after_trigger
- fault_write_not_applied
- fault_write_noop
- missing_effective_write_evidence
- other_invalid_injection

统计规则：

1. 只有fault_effective=true且证据闭环的样本才计入activated；
2. 只有valid_for_l5=true的样本才进入L5五类分母；
3. invalid样本不设置新的L5终类，corrected_class=null；
4. 原始raw_class不得删除或覆盖；
5. 报告同时给出：
   attempted / triggered / write_attempted / effective_activated /
   invalid_excluded / valid_L5_denominator。
6. 不得把幻影样本从Masked改成Inactive来绕过schema限制；
7. 不得把noop写入继续算作有效Masked。

因此当前暂定口径为：

- ITEM-271：effective_activated暂定16/30；
- ITEM-279：effective_activated暂定19/33；
- ITEM-019：31/33；
- ITEM-022：32/33。

“暂定”只有在逐样本证据确认后才能转为最终值。

如果中央共享schema目前无法承载上述字段：

- 本轮先在correction overlay中实现；
- 不要在golden运行期间修改共享schema；
- oracle冻结后，单独提交最小、向后兼容、只增字段的schema变更方案；
- 旧记录读取必须保持兼容；
- 在修改共享runner/campaign/classify/schema之前再次汇报变更范围。

[LSU][DATA]提交不得修改原始runs/results.jsonl，只能增加overlay、审计报告、勘误和离线汇总工具。
