四、资源安全与并发硬限制

以下是硬限制，不是建议。资源安全优先于持续推进；达到门禁或熔断条件时必须暂停，不得为了保持任务运行而绕过限制。

1. 编译并发：
   - scons、make、ninja 等编译命令并发数不得超过 8，默认使用 -j8 或更低。
   - 禁止裸 -j、-j$(nproc)、-j126、根据 CPU 核数自动计算并发，或任何等价的超限方式。
   - 同一时刻只允许一个编译任务。
   - 启动新编译前，必须确认没有仍在运行的 scons、make、ninja、gcc、g++、clang 或 cc1plus 进程树。
   - 未经我明确批准，不得提高编译并发上限。

2. 实验并发：
   - 未完成资源画像的新编译方式、新 workload、新 checkpoint 或新实验类型，只能单实例运行。
   - 实验默认并发度为 1；完成资源画像后最多为 2。
   - 实验并发超过 2 必须先报告实测峰值资源和预算，并得到我明确批准。
   - 同一时刻最多存在一个未经资源画像的重任务。

3. 多 Agent 约束：
   - 只有主协调 AI 可以分配编译槽和实验槽。
   - 子 Agent 默认只能读取、分析、审查和准备方案；没有获得主 AI 分配的唯一资源槽时，不得启动编译、gem5 仿真、批量测试或实验。
   - 所有 Agent、worker 和 shell 共享一个编译槽、统一实验并发上限和同一套资源预算，不得各自计算并发。
   - 禁止多个 Agent 在同一或不同工作目录中同时启动重叠的 gem5 编译。

4. 后台任务和重复启动保护：
   - 重任务必须使用单实例锁或等效互斥机制。
   - 锁和 progress.md 必须记录 owner、PID、PGID、任务类型、Checklist ITEM、RunID、启动时间和日志路径。
   - 后台命令启动后必须立即核验 PID/PGID。
   - 工具调用返回、终端无输出、命令超时、队列为空或文件出现，均不等于任务已退出；必须检查进程树和完成标记。
   - 在前一个同类任务明确退出前，不得提交第二个任务。
   - 如果锁对应进程仍存在，必须拒绝重复启动；只有确认 PID 已不存在且任务状态已记录后，才能处置陈旧锁。

5. 启动前资源门禁：
   每次启动编译、gem5 仿真、批量测试或实验前，必须记录 MemAvailable、SwapFree、load 1/5/15、blocked 进程、磁盘剩余空间、现有重任务和锁状态。

   出现以下任一情况，不得启动新的重任务：
   - MemAvailable 小于 12 GiB；
   - SwapFree 小于 4 GiB；
   - 存在持续换页、明显内存抖动或大量 blocked 进程；
   - 已存在编译任务或已达到实验并发上限；
   - 无法确认现有后台任务、进程或锁的归属和状态；
   - 无法为操作系统和其他用户预留至少 8 GiB MemAvailable 的保守预算。

   不得只根据 CPU 空闲、free 列或单次 load average 判断资源安全；应以内核 MemAvailable、swap、进程树和连续采样为准。

6. 运行中监控和熔断：
   - 编译、gem5 仿真和实验运行期间至少每 60 秒采样一次资源，并写入任务专属资源日志。
   - MemAvailable 小于 10 GiB 时进入 WARNING：禁止启动任何新重任务，并检查当前任务的增长趋势。
   - 以下任一条件触发 TRIP：MemAvailable 连续两次低于 8 GiB；任一次低于 6 GiB；SwapFree 低于 2 GiB；持续高频换页；blocked 进程大量增加。
   - TRIP 时只能终止有明确证据属于本任务的 PID/PGID 进程树：先 TERM 并等待，必要时才对同一已核实进程树使用 KILL。
   - 禁止杀死归属不明或其他用户的进程。如果资源压力来自他人或来源不明，暂停新任务，记录证据并报告 BLOCKED。
   - TRIP 后不得按原参数自动重试。必须立即更新 progress.md 和 findings.md，保留资源日志，并降低计划内并行度重新画像或提出 DECISION REQUEST。

7. 资源画像：
   - 首次单实例运行必须记录峰值 RSS、峰值 Committed_AS、最低 MemAvailable、最大 swap 使用量、运行时间和退出状态。
   - 只有实测证明持续满足安全水位后，才可在硬上限内提高并发。
   - G0-10 必须验证：编译不超过 8 且单实例；实验默认 1；锁、PID/PGID、60 秒监控、启动门禁、WARNING/TRIP 和安全终止逻辑均可审计。

- 覆盖或删除不属于本任务的修改；
- 为解决冲突而静默丢弃远端或本地内容；
- 未验证就提交“完成”状态；
- 将凭据、受许可证限制的 workload、镜像、checkpoint 或超大原始日志直接提交到 Git。

代码、配置、manifest、分析脚本、资源守卫脚本、progress.md、findings.md、结果摘要和小型可复核产物应提交。

大型原始日志、资源监控日志、镜像和 checkpoint 如果仓库没有明确的 Git LFS 或数据存储规范，不得直接提交；应保留在服务器稳定路径，并在 findings.md 中记录路径、大小、哈希和对应 ITEM。

如果远端分支在执行期间出现新的提交，禁止强推或盲目覆盖。先暂停提交，记录本地/远端 commit，分析冲突后再决定。
