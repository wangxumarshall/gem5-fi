- **提交时的目的值**：从物理寄存器堆读，`cpu-&gt;physRegFile().getReg(phys_reg)` → `RegVal`（`cpu/o3/regfile.hh:239`）；向量走 `getReg(phys, void*)`（`regfile.hh:282`）+ `vecRegBytes()`（`regfile.hh:183`）。访问器 `CPU::physRegFile()` 在 `cpu.hh:483`。参考现有读法 `CHAOSPhysReg.cc:336/387`。另一路 `CPU::getWritableReg()`（`cpu.hh:339`）。
- **RAT 推进序**：`setEntry` 在 `commit.cc:1273`，**晚于** 1259、早于 1283。钩在 1271 前 = 旧 RAT；钩在 1274 后 = 新 RAT。注意 `UnifiedRenameMap::setEntry` 内含 CHAOSRenameMap post-write 钩（`rename_map.hh:289-297`），注入器可**改写**本次映射，故 1274 后读到的是注入后的 RAT（正是 W2 要观测的）。physRegFile 值读取不受影响。

**c. 输出机制** — 用 `simout.create(name, false, no_gz)`（`base/output.hh:222`；`CHAOSProbe.cc:40` 现有用法），`.gz` 后缀自动 gzip（`output.hh:207/218`、`output.cc:231`），zlib 是 gem5 硬依赖（`SConstruct:837-841`）。写用 `*(log_stream-&gt;stream()) &lt;&lt; ...`（`CHAOSProbe.cc:157-158`、`CHAOSIQ.cc:49`）。**现有 CHAOS 组件无逐指令 trace 流**，只有单行 summary。体积：~64B/条 × 10M ≈ 640MB 原始，gzip 后约 60–130MB；减速主要来自格式化+IO，缓冲写估计 2–5×，逐条 flush 会更差（W2.1 验收要求实测减速比，见 `docs/gem5-fi/ooo/06-implementation-plan.md:116`）。

**d. commit 序号** — **无全局 commit 计数器**。可用：`commitStats[tid]-&gt;numInsts`（`commit.cc:1365`，逐线程、跳过 microop）与 `numOps`（`:1372`）；`lastCommitedSeqNum[tid]`（`commit.hh:448`，`:1038` 赋值，逐线程且是 seqNum 非计数）。全局单调 seqNum 在 fetch 分配：`CPU::getAndIncrementInstSeq()`（`cpu.hh:298`）/ `globalSeqNum`（`cpu.hh:601`），**squash 会留空洞**。建议 CommitTrace 自持计数器。

## 2. CHAOSMicroSnap（L1 快照）

**a. RAT 快照** — `SimpleRenameMap` **有公开迭代器**：`begin/end/cbegin/cend`（`rename_map.hh:156-165`）+ `numArchRegs()`（`:152`）+ `lookup(RegId)`（`:130`）。但 `UnifiedRenameMap` 的 `std::array&lt;SimpleRenameMap, CCRegClass+1&gt; renameMaps` 是**私有**（`rename_map.hh:179`），**无 per-class 公开 accessor**（现有 CHAOSRenameMap 指针 `:189-200` 只用于钩子，不可迭代）。**最小 patch 位置**：`rename_map.hh:204` 的 public 块加 `SimpleRenameMap &amp;map(RegClassType c)` 和/或 `forEachArchReg(c, fn)`，内部 `map[c].begin()..end()` 产出 `(arch_idx, PhysRegIdPtr)`。

**b. 可直接复用 CHAOSProbe 的读取代码** — ROB 占用 `o3cpu-&gt;o3ROB().countInsts()`（`CHAOSProbe.cc:99`；`rob.hh:268`）；IQ `o3cpu-&gt;o3IEW().instQueue.getCount(0)`（`CHAOSProbe.cc:101`；`inst_queue.hh:391`）；freelist `o3cpu-&gt;physFreeList().numFreeRegs(class)`（`CHAOSProbe.cc:103-107`；`free_list.hh:255-257`）；容量推导 `CHAOSProbe.cc:64-67`；halt 检测 `anyThreadActive()`（`CHAOSProbe.cc:82-90`）。**ROB head/tail 公开**：`readHeadInst(tid)`（`rob.hh:136`）、`readTailInst(tid)`（`rob.hh:153`）、`getEntryAtDistance(tid,D)`（`rob.hh:309`，`rob.cc:270`，现用法 `CHAOSROB.cc:113`）→ 取 `-&gt;seqNum`。

**c. 采样触发** — 无全局 commit 计数（见 1d），**周期事件+读计数需逐 tid 累加 `commitStats[tid]-&gt;numInsts`**，且与 commit 序号非严格对齐。**推荐 commit 侧计数器**：MicroSnap 暴露 `void sample(uint64_t commit_seq)`，由 commit.cc 钩子（与 CommitTrace 同一落点）每 N 条调用；`curTick()` 在钩子内即可取，无需额外事件（周期事件仅作兜底）。注入器指针挂法照抄 `commit.hh:356-363`。

## 3. 两遍法与对齐

对齐主键 = **commit 序号**（自持计数器），无需 gem5 侧额外输出。每条记录必须含 **tick**（`curTick()`）：既支撑「执行时间错」分类，也用于潜伏期/停顿诊断；另带 `seqNum`（诊断 squash 空洞）、`tid`（SMT 消歧）、PC/opcode。第二遍同 seed 只对 SDC/Crash/Hang 样本开 trace（`06-implementation-plan.md:82/116-118`）。trace 钩子必须纯读、不产生额外事件，保持与无 trace 遍零回归（CHAOSProbe 已证此模式）。

## 5. 偏差与诚实说明

1. **外部竞态（非我代码问题，已实证+已加固）**：C 臂首跑（00:46-00:54）期间并行 W2.4 代理再次重建 gem5.opt，rep1 重放与 §1.5 复查撞上 `PermissionError: [Errno 13] Permission denied: '.../gem5.opt'`（bad_runs.log 两条 traceback 为铁证）→ 产生 `MISMATCH(Crash-&gt;SimulatorError)` 与 frozen=yes。**这不是 gem5 非确定性**。现场保留于 `runs|artifacts/w23-toy-bm-rat.race1/`。由此新增了参照溯源 sidecar + 二进制交换守卫（见变更摘要）。
2. **真 bug 发现并修复**：`count_trace_lines` 原只 catch `OSError`；Crash rep 的 trace 是 abort 前部分 flush 的截断 gzip，读它抛 `EOFError` → runner 在 RESULT 与 CTRACE 之间崩溃、丢 L2RESULT（C2 rep1 的 `replay_ctrace/commit_diff` 双 null）。修复（catch EOFError + `lines=unreadable`）已用真实截断文件单测验证；C2 现场保留于 `.eofbug`。
3. **Crash rep 的 trace 截断是 W2.3 管线的真实发现**：gem5 abort 不 flush gzip 流（本例 2.3MB/约 20.96 万条幸存），Crash 类 rep 的 L2 五分类目前只能得 `l2_error`；如需 Crash rep 的完整 trace，CHAOSCommitTrace 需周期性 flush（gem5 侧改动，属后续工作，未越权处理）。
4. **确定性结论（正面）**：所有重放遍 determinism 全 match（smoke 3/3、bm-rat 2/2）；rep0 的首分歧点 seq=210665 在两次 W2.4 二进制（00:39:57 与 01:01:39 构建）上逐字段复现（同为 `3ca26881→1eb1`）。

## 二、机制设计（与计划的偏差均在源码核实后决策）

- **EMI 通路**：`orig-&gt;asBytes(buf,8)` 取回完整 8B ExtMachInst（低 32 位 `instBits` 为真实编码，高 32 位是原译码所带元数据 sveLen/fpscr/itstate——re-decode 必须原样携带）→ 改 instBits → `decodeChaos` → 替换。`BasicDecodeCache` 经核实是纯缓存（无盖章副作用），`decodeInst` 即原始分派。
- **排除项**：Thumb（emi.thumb）、非 AArch64、macroop/microop 原指令；替换指令若为 macroop 则由 fetch 循环既有 isMacroop 分支自然处理（日志记 `macroop_new`）。predictedBranch 按计划"看原指令"（`this_pc.branching()` 在替换前已由 decoder 设置，无需干预）。
- **候选位集**：opcode={31,30,29,28-24,21}；reg=Rd[4:0]∪Rn[9:5]∪Rm[20:16]；imm=[21:10]（imm12/immr+imms/imm6 主区间）。
- **reg/imm 语义验证**（超出计划的强化）：位翻转后 re-decode 须满足 mnemonic 不变且（reg 模式）寄存器操作数指纹改变 /（imm 模式）指纹不变——保证"寄存器号翻转"不混入 opcode/imm 效应。单 bit 在有效位上均匀采样；双 bit 有界拒绝采样（≤16 次），无有效位=诚实放弃本次（不耗 fault 配额）。
- **D03 互换表**：9 条 (mask,match,xor) 规则**全部用主机 gcc+objdump 真实编码核验**（`/tmp/w6b1_swap/pairs.s`）：ADD↔SUB(imm/reg/ext, bit30)、AND↔ORR/BIC↔ORN/EOR↔ANDS/EON↔BICS(bit29)、AND↔ORR imm(bit29)、MOVN↔MOVZ(bit30)、STR↔LDR uimm(bit22)；非法象限（MOVK、LDRSW 等）用掩码排除，保证换值后必为合法编码。
