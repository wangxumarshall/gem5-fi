# R6-A2 A05 操作数级寻址（2026-10-28）

## 已真实实现：A05-d pre/post EA 反转

`maybeCorruptPre` 现在能拿到真实 `DynInst`，识别
`ArmISA::MemoryPreIndex64 / MemoryPostIndex64`，读取**真实指令立即数**并反转
变址语义：

- pre 指令：`EA = base + imm` → 反转为 post 语义 `EA = base = old_EA - imm`
- post 指令：`EA = base` → 反转为 pre 语义 `EA = base + imm`

写回 microop 不动（本微架构两种模式的写回值相同，均为 base+imm；时序差
在本模型不可观测，已在报告与代码注释中标注 `writeback_time_modeled=false`）。

真机 canary（binary `a1f85a08…`，W3 seed1，F0 span=243）：

```
mode=a05_prepost old_addr=0x4932f8 new_addr=0x493300 old_size=8
submodel=a05d
CHAOS_LSU_TRIGGER attempted=2819 eligible=243 injected=1
链 118 事件 → terminal=full
```

指令形态不匹配（非 pre/post、imm=0、或 DynInst 缺失）在 trigger 决策前
被拒，**不消费注入预算**。

## 未完成：A05-a/b/c（精确架构限制，非宣称实现）

尝试的路径（已实测）：在 `LSQ::pushRequest` PRE 读取
`DynInst::getRegOperand(slot 0/1)`，配合 `MemoryReg64::baseReg()/offsetReg()/
extendType()/shiftAmount()` 重建 EA。结果：microop 的源操作数槽位不是稳定
API，实测 **SIGSEGV**（W0 `a05_base_index`/`a05_shift` 触发即崩溃），无法
保持实验语义。因此 a/b/c 当前在资格判定处一律 `ineligible`（绝不注入、
绝不消费预算），不使用低字节旋转等代理。

### 最小未来实现方案（已定位）

按 Lane B 设计 A：在 `arch/arm/isa/insts/ldr64.isa` / `str64.isa` 的
`buildEACode()` 生成代码中，EA 表达式**之前**插入操作数钩子：

- 拿到局部 `XBase/XOffset` 与成员 `type/shiftAmt`（必须复制到局部再改，
  StaticInst 成员跨动态实例共享）；
- 实现 base/index 互换（仅 shift!=0）、UXTW↔SXTW（仅 W-index 且 bit31=1）、
  shift 另一合法值（0 ↔ log2(size)）；
- pre/post 已有 d 的真实 EA 反转，可与该方法统一。

代价：改 2 个 ISA 模板 + 新 `chaos_agu_operands.{hh,cc}` + 全 ARM 重新生成；
这是下一轮的最小完整方案。
