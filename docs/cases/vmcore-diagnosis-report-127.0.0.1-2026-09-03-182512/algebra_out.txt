B. 故障点寄存器代数闭合（撕裂移位族）
========================================================================
x1  (模板 &runqueues) = 0xffffc9e8a3cd96c0
x20 (实收偏移)        = 0x00ffffb617dd3940   <-- 应为 __per_cpu_offset[12]
x25 (i = 迭代 CPU 号) = 0xc = 12（x0/x3/x6 同为 0xc，四寄存器互证）
x27 = x1 + x20 (mod 2^64) = 0x00ffc99ebbaad000
崩溃块 x27                = 0x00ffc99ebbaad000   逐位相等: True
FAR_calc = x27 + 0x120 = 0x00ffc99ebbaad120
崩溃 FAR（dmesg 文本）  = 0x00ffc99ebbaad120
FAR_calc == FAR（逐位，含高 16 位 00ff）: True
注：本案 x27 高 16 位 = 00ff（撕裂值高 16 位 00ff 直通），FAR 完整 64 位
    逐位打印——与 08-31 案（高 16 位 a000 不入 dmesg 打印）形态不同，如实记录

C. 内存真值对照（crash 从 vmcore 读出，内存完好）
========================================================================
__per_cpu_offset[12]  真值 = 0xffffb617dc4d6000   (x25=i=12 → 本指令应取此槽)
__per_cpu_offset[179] 真值 = 0xffffb617ddb04000  (崩溃执行核 179 → 计划要求对照)
__per_cpu_offset[0]   真值 = 0xffffb617dc33e000
数组等差步长: off[1]-off[0] = 0x22000; off[12]-off[0] = 0x198000 = 12*0x22000: True; off[179]-off[12] = 0x162e000 = 167*0x22000: True
x20 实收 0x00ffffb617dd3940 ≠ 真值 0xffffb617dc4d6000 → 装载撕裂
汉明距离 popcount(x20 ^ off[12])  = 26
          popcount(x20 ^ off[179]) = 29
          popcount(x20 ^ off[0])   = 31

========================================================================
D. 撕裂形态判定（字节流非对齐窗口匹配 —— 复用第 7 次案方法）
========================================================================
x20 LE 字节序列（内存序）: 40 39 dd 17 b6 ff ff 00
在 192 槽数组字节流中搜索: 命中 [(123, 1)]（全数组唯一）
  → 命中位置 = 槽 123 起始 + 1 字节（数组基址 + 123*8 + 1 = 基址 + 985 字节）
等价公式: (off[123]>>8) | ((off[124]&0xFF)<<56)
  = (0xffffb617dd394000 >> 8) | ((0xffffb617dd3b6000 & 0xFF) << 56)
  = 0x00ffffb617dd3940   == x20: True
crash 实读（crash_session2.log）: rd -64 ffffc9e8a40d59a9 2
  → 首字 = 0x00ffffb617dd3940   == x20: True
  （ffffc9e8a40d59a9 = &__per_cpu_offset + 985 字节 = 槽123 LE 字节 1 处）

撕裂形态结论：
  08-25-15:58 案形态 = offset[0] >> 8（槽内 1 字节相位，槽 0 起点）
  08-31 案形态   = +2 字节相位、跨槽 125/126 边界
  本案形态 = 槽 123 起点 +1 字节相位的非对齐窗口（不跨槽，窗口完整落在
  槽 123/124 边界前 7 字节内——实为 123 槽内 1 字节相位 + 顶入 124 槽首字节）
  撕裂相位谱：1 字节（08-25-15:58, 本案）→ 2 字节（08-31）→ 半字旋转（08-14）
与 off[12] 的字节旋转族比对: 无 1~7 字节旋转匹配（非 08-14 案 ROL16 形态）

E. 反事实验证（若 ldr 交付真值则不崩）
========================================================================
x27_true(i=12)  = &runqueues + __per_cpu_offset[12]  = 0xffff8000801af6c0
x27_true(i=179) = &runqueues + __per_cpu_offset[179] = 0xffff8000817dd6c0

  vtop 0xffff8000801af6c0  → PHYSICAL 37ffe2e6c0, PTE e80037ffe2ef03 (VALID|SHARED|AF|NG|PXN|UXN|DIRTY)  ← VALID
  vtop 0xffff8000817dd6c0 → PHYSICAL 6057ffe026c0, PTE e86057ffe02f03 (VALID|SHARED|AF|NG|PXN|UXN|DIRTY)  ← VALID
若收到真值，故障装载将读 rq(12)->cfs.avg.load_avg（+0x120 处）= 1023（实例健全）

→ 正确数据下指令平静完成，异常的唯一必要条件是装载结果被腐化
