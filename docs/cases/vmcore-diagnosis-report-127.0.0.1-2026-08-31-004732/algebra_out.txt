========================================================================

FAR_calc 低 48 位 == FAR 低 48 位: True

========================================================================
D. 撕裂形态判定（字节流非对齐窗口匹配 —— 本案核心新证据）
========================================================================
x20 LE 字节序列（内存序）: 25 fb 56 be ff ff 00 a0
在 192 槽数组字节流中搜索: 命中 [(125, 2)]（全数组唯一）
  → 命中位置 = 槽 125 起始 + 2 字节（数组基址 + 125*8 + 2 = 基址 + 1002 字节）
等价公式: (off[125]>>16) | ((off[126]&0xFFFF)<<48)
  = (0xffffbe56fb258000 >> 16) | ((0xffffbe56fb27a000 & 0xFFFF) << 48)
  = 0xa000ffffbe56fb25   == x20: True
crash 实读（crash_session4.log）: rd -64 ffffc1a9862559ba 2
  → 首字 = 0xa000ffffbe56fb25   == x20: True
  （ffffc1a9862559ba = &__per_cpu_offset + 1002 字节 = 槽125 LE 字节 2 处）

撕裂形态结论：
  既往 08-25-15:58 案形态 = offset[0] >> 8（槽内 1 字节相位，槽 0 起点）
  本案形态 = 字节流 +2 字节相位、跨槽 125/126 边界的非对齐窗口
  （不是对某槽的算术移位，而是把数组当作字节流在错误相位上取的 8 字节）
  与既有撕裂移位族同构（数据源相位错位），但相位从 1 字节变为 2 字节、
  且窗口跨过槽边界——撕裂相位谱新增一个数据点。
与 off[60] 的字节旋转族比对: 无 1~7 字节旋转匹配（非 08-14 案 ROL16 形态）
