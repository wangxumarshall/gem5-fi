========================================================================
x9 锚定 KASLR      = 0x4fd326520000
sym 锚定 KASLR     = 0x4fd326520000
runqueues 咬合     = 0x4fd326520000  (应等于 KASLR)

五路一致: True
x21 = 0xffffcfd3a847fcb0 == &nr_cpu_ids(运行期): True

B. 故障点寄存器代数闭合（撕裂移位族）
========================================================================
x1  (模板 &runqueues) = 0xffffcfd3a80896c0
x20 (实收偏移)        = 0x2cd80e2000ffffb0   <-- 应为 __per_cpu_offset[151]
x25 (i = 迭代 CPU 号) = 0x97 = 151（x0/x6 同为 0x97，三寄存器互证）
x27 = x1 + x20 (mod 2^64) = 0x2cd7ddf3a9089670
崩溃块 x27                = 0x2cd7ddf3a9089670   逐位相等: True
FAR_calc = x27 + 0x120 = 0x2cd7ddf3a9089790
崩溃 FAR（dmesg 文本）  = 0x2cd7ddf3a9089790
FAR_calc == FAR（全 64 位）: True
注：本案 dmesg 以 16 位十六进制打印完整 FAR 2cd7ddf3a9089790（非既往 12 位截断形态），
    与 x27+0x120 的全 64 位值逐位相等——FAR 非规范大值形态在打印层面即完整保留

========================================================================
D. 撕裂形态判定（字节流非对齐窗口匹配 —— 本案核心新证据）
========================================================================
x20 LE 字节序列（内存序）: b0 ff ff 00 20 0e d8 2c
在 192 槽数组字节流中搜索: 命中 [(9, 5)]（全数组唯一）
  → 命中位置 = 槽 9 起始 + 5 字节（数组基址 + 9*8 + 5 = 基址 + 77 字节）
等价公式 1（跨槽非对齐窗口）: (off[9]>>40) | ((off[10]&0xFFFFFFFFFF)<<24)
  = (0xffffb02cd80c0000 >> 40) | ((0xffffb02cd80e2000 & 0xFFFFFFFFFF) << 24)
  = 0x2cd80e2000ffffb0   == x20: True
等价公式 2（单槽字节旋转）: ROL3B(off[10]) = (off[10]<<24)|(off[10]>>40)
  = 0x2cd80e2000ffffb0   == x20: True
crash 实读（crash_session3.log）: rd -64 0xffffcfd3a848561d 2
  → 首字 = 0x2cd80e2000ffffb0   == x20: True
  （0xffffcfd3a848561d = &__per_cpu_offset + 77 字节 = 槽 9 LE 字节 5 处，跨槽 9/10 边界）

撕裂形态结论：
  既往 08-25-15:58 案形态 = offset[0] >> 8（槽内 1 字节相位，槽 0 起点）
  既往 08-31 案形态（第 7 次）= 槽 125 起点 +2 字节（跨槽 2 字节相位）
  本案形态 = 槽 9 起点 +5 字节（跨槽 5 字节相位），同时等价于槽 10 自身的
  ROL3B（3 字节循环左移）——既是'错相位的字节流窗口'又是'旋转形态'，
  两种描述在本案的数组几何下数值同一（因相邻槽高 3 字节相同 ffffb0）。
  撕裂相位谱从 1 字节、2 字节扩展到 5 字节（旋转等价 3 字节）。
与 off[151]/off[179]/off[0] 的 1~7 字节旋转族比对: 全部不匹配
全 192 槽 × 1~7 字节旋转（ROL/ROR 双向）扫描: 唯一命中 slot 10 ROL3B（即 ROR5B）
