案 #28 代数闭合复算（mod 2^64）+ crash 实测真值对照
==============================================================================

[输入] x27=0xffffcad705af96c0  x20=0x0000000000000000  x1=0xffffcad705af96c0  x17=0xffffb5297bce4000
[输入] x25=0x0000000000000007(7)  FAR=0xffffcad705af97e0
[crash 实测] __per_cpu_offset[7]=0xffffb5297a60c000  [179]=0xffffb5297bce4000
[crash 实测] runqueues[7]=0xffff8000801056c0  [179]=0xffff8000817dd6c0

------------------------------------------------------------------------------
一、加法器闭合 #1：x27 == x1 + x20 (mod 2^64)   ← add x27, x1, x20
------------------------------------------------------------------------------
  x1  = 0xffffcad705af96c0
  x20 = 0x0000000000000000
  和  = 0xffffcad705af96c0
  x27 = 0xffffcad705af96c0
  闭合判定: x27 == x1 + x20 → True
  x20 零塌缩使加法退化为恒等：x27 == x1（canonical）。

------------------------------------------------------------------------------
二、加法器闭合 #2：FAR == x27 + 0x120 (mod 2^64)
------------------------------------------------------------------------------
  x27      = 0xffffcad705af96c0
  x27+0x120= 0xffffcad705af97e0
  FAR      = 0xffffcad705af97e0
  闭合判定: FAR == x27 + 0x120 → True
  反证非移位 imm=0x48: x27+0x48 = 0xffffcad705af9708 ≠ FAR（排除）
  crash vtop 实测（crash_session.log）：
    vtop ffffcad705af96c0: PGD/PUD/PMD 有效 → PTE = 0（L3 断链）
    vtop ffffcad705af97e0: 同上——与 ESR FSC=0x07 level 3 完全一致。

------------------------------------------------------------------------------
三、致命装载指令槽位解码 + 真值对照【本案核心：crash 实测】
------------------------------------------------------------------------------
  Code: f9400782 f879d814 2a1903e0 8b14003b (f9409377)
  括号内 f9409377 = ldr x23, [x27, #0x120]  (288 字节偏移)
  前一条 8b14003b = add  x27, x1, x20
  再前 2a1903e0   = orr  x0, wzr, w25 (w25=0x7 → x0=7, 与 x0 dump=0x7 吻合)
  再前 f879d814   = ldr  x20, [x0, x25, sxtw #3]  ← __per_cpu_offset[7] 装载

  【真值对照——9 案中唯一可实测者】
  x20 实收（dmesg dump）   = 0x0000000000000000
  __per_cpu_offset[7] 真值 = 0xffffb5297a60c000  （crash p 实测）
  真值 - 实收 = 0xffffb5297a60c000（64 位全异）
  → 零塌缩实锤：内存真值非零、canonical、4K 对齐（低 12 位=0x000），
    装载返回 0 与真值 64 位全异——『内存完好、返回值坏』的直接实测证明。

------------------------------------------------------------------------------
四、x17 残留发现：寄存器快照中的『上次正确装载』化石
------------------------------------------------------------------------------
  x17（dmesg dump）        = 0xffffb5297bce4000
  __per_cpu_offset[179] 真值 = 0xffffb5297bce4000  （crash p 实测）
  x17 == __per_cpu_offset[179] → True

  解读：x17 恰好等于 CPU179 自己的 percpu 偏移槽真值——
  这是此前某次正确执行时残留的旧值（find_busiest_group 循环中
  曾经正确装载过槽 179 的偏移到某寄存器/由调用方留下）。
  它在崩溃快照中『作证』：同一颗核、同一指令族、同一数组，
  此前亿万次装载返回的都是正确值——唯独致命这一次返回 0。
  这直接排除了『该数组/该内存区系统性坏』的假设。

------------------------------------------------------------------------------
五、反事实推演【crash vtop 实测版】
------------------------------------------------------------------------------
  若 x20 装载返回真值：
    x27 = x1 + __per_cpu_offset[7] = 0xffff8000801056c0
    对照 crash 实测 runqueues[7]   = 0xffff8000801056c0
    一致? True   ← x1 语义钉死：x1 即 &runqueues percpu 模板基址
    ldr x23,[x27,#0x120] 有效地址 = 0xffff8000801057e0（rq->cfs.avg 字段）
    该地址位于 runqueues[7] percpu 区（已映射有效，非空洞）

  另证 x1+off[179]：
    x1 + __per_cpu_offset[179] = 0xffff8000817dd6c0
    对照 crash 实测 runqueues[179] = 0xffff8000817dd6c0
    一致? True

  结论：真值路径 100% 有效（两级 percpu 换算均与 crash 实测逐位闭合）；
  实际路径 FAR=x1+0+0x120 落入 PTE=0 空洞 → L3 fault。
  崩溃 100% 归因于那一次装载读回返回 0——反事实从『推断』升级为『实测』。

七、最终闭合判定汇总
==============================================================================
  (1) x27 = x1 + x20 (= x1)      : 闭合
  (2) FAR = x27 + 0x120          : 闭合
  (3) x20 = 0 vs 真值 0xffffb5297a60c000：零塌缩【实锤-crash实测】
  (4) x17 == __per_cpu_offset[179]：上次正确装载残留，数组完好的活证
  (5) 反事实 x1+off[7]+0x120 = 0xffff8000801057e0 有效（== runqueues[7]+0x120）【实测】
  (6) FSC=L3（pte=0）与零塌缩几何一致；vtop 双地址 PTE=0 实测

  推理链：x20 装载返回 0（零塌缩，真值 crash 实测为非零 canonical）
          → add 恒等 → ldr 以 x1+0x120 寻址 → FAR canonical 但 PTE=0
          → L3 translation fault → Oops。除 x20 装载本身外，
          每一步均被代数闭合 + crash 实测双重验证为正确执行。
