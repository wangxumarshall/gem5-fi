==============================================================================
案 #24 代数闭合复算（mod 2^64）
==============================================================================

[输入] x27=0x00ffc7a7ac4a3900  x20=0x00ffffb810e4a240  x1=0xffffc7ef9b6596c0
[输入] x25=0x0000000000000032(50)  x23=0x0000000000000400(1024)  FAR=0x00ffc7a7ac4a3a20

------------------------------------------------------------------------------
一、加法器闭合 #1：x27 == x1 + x20 (mod 2^64)   ← add x27, x1, x20
------------------------------------------------------------------------------
  x1  = 0xffffc7ef9b6596c0
  x20 = 0x00ffffb810e4a240
  和  = 0x00ffc7a7ac4a3900
  x27 = 0x00ffc7a7ac4a3900
  闭合判定: x27 == x1 + x20 → True
  【实锤】ALU 加法器与操作数装载完全正确；
          x27 的异常形态 100% 来自 x20（percpu 偏移装载返回值），
          而非加法指令本身。

------------------------------------------------------------------------------
二、加法器闭合 #2：FAR == x27 + 0x120 (mod 2^64)  ← ldr x23, [x27, #288]
------------------------------------------------------------------------------
  x27      = 0x00ffc7a7ac4a3900
  imm      = 0x120 (=288, LDR unsigned offset 0x48<<3)
  x27+0x120= 0x00ffc7a7ac4a3a20
  FAR      = 0x00ffc7a7ac4a3a20
  闭合判定: FAR == x27 + 0x120 → True
  反证非移位 imm=0x48: x27+0x48 = 0x00ffc7a7ac4a3948 ≠ FAR（排除）

------------------------------------------------------------------------------
三、致命装载指令槽位解码
------------------------------------------------------------------------------
  Code: f9400782 f879d814 2a1903e0 8b14003b (f9409377)
  括号内 f9409377 = ldr x23, [x27, #0x120]  (288 字节偏移)
  前一条 8b14003b = add  x27, x1, x20
  再前 2a1903e0   = orr  x0, wzr, w25 (w25=0x32 → x0=50, 与 x0 dump=0x32 吻合)
  再前 f879d814   = ldr  x20, [x0, x25, sxtw #3]  ← __per_cpu_offset[50] 装载
  x25=50 → __per_cpu_offset[50]，即 CPU50 的 percpu 偏移槽（跨槽：本核 179 未读自己的槽）
  x20 装载返回 = 0x00ffffb810e4a240 —— 即被腐化的 __per_cpu_offset[50] 读出值

------------------------------------------------------------------------------
四、x20 = 00ffffb810e4a240 位级 16 位段分析（标签错位形态）
------------------------------------------------------------------------------
  x20 = 0x00ffffb810e4a240
    [63:48] = 0x00ff   ← 非 canonical 内核标签（真值此段应 0xffff）
    [47:32] = 0xffb8   ← 0xffb8：含 ff 沾染段
    [31:16] = 0x10e4   ← 0x10e4
    [15: 0] = 0xa240   ← 0xa240，页对齐段异常（真值低 16 位应为 0x0000）

  -- 对照：x1 = ffffc7ef9b6596c0（rq->cfs 指针，canonical 真值）--
  x1 = 0xffffc7ef9b6596c0
    [63:48]=0xffff [47:32]=0xc7ef [31:16]=0x9b65 [15:0]=0x96c0

  -- x27 = x1 + x20 的逐段进位传播 --
  x27 = 0x00ffc7a7ac4a3900
    [63:48]=0x00ff [47:32]=0xc7a7 [31:16]=0xac4a [15:0]=0x3900

  逐段加法（低段→高段，含进位）：
    [15: 0]: 0x96c0 + 0xa240 + c = 0x3900 (进位输出 1)
    [31:16]: 0x9b65 + 0x10e4 + c0 = 0xac4a (进位输出 0)
    [47:32]: 0xc7ef + 0xffb8 + c = 0xc7a7 (进位输出 1)
    [63:48]: 0xffff + 0x00ff + c = 0x00ff (进位输出 1)
  重算 x27 段值 = ['0x00ff', '0xc7a7', '0xac4a', '0x3900']  vs dump x27 段值 = ['0x00ff', '0xc7a7', '0xac4a', '0x3900']

  关键观察：
  1. x20[63:48]=0x00ff —— canonical 内核指针此段必为 0xffff；
     这里是 00ff：ff 标签出现在 bit47..40，位置比真值低 8 位，
     即『ff 标签右移一个字节段』（错位沾染），与案22/23 的 ff 迁移谱同族。
  2. x20[47:32]=0xffb8 —— ff 出现在次高 16 位段，进一步证明 ff 沾染
     跨越段边界（bit47..32 区间内 ff 前缀 + 尾随 b8）。
  3. x20[11:0]=0x240 ≠ 0 —— percpu 偏移真值低 12 位恒为 0（4K 页对齐；
     谱系实测真值低 16 位有 e000/4000/8000 等，故不变式取低 12 位），
     该 0x240 是注入位，且经加法污染 x27[15:0]=0x900+0x240+进位路径。

五、ff 标签位置迁移谱（同日四连崩 + 谱系前案对照）
------------------------------------------------------------------------------
  坏值(x20 或等价)          [63:48] [47:32] [31:16] [15: 0]  ff/ffff 沾染段
  案22 09-11-14:31 x20=9226e000ffffa4bd

  案24 09-11-17:06 x20=00ffffb810e4a240
    0x00ffffb810e4a240  0x00ff   0xffb8   0x10e4   0xa240   00FF@0, FFxx@1
  案25 09-11-17:58 x20=0000000000000000
    0x0000000000000000  0x0000   0x0000   0x0000   0x0000   (无 ff 沾染——零塌缩)

  谱系结论：
  - 案22 (9226e000 ffff a4bd)：0xffff 完整标签出现在 [31:16] 段；
  - 案23 (ffa9..e000ff)：0xff 前缀钉在 [63:56]，0xff 尾缀落在 [15:8]；
  - 案24 (00ffff b8..)：0xffff 标签迁移到 [47:32]，且 [63:48] 残留 00ff 半标签；
  - 案25：全零塌缩（对照项，无标签保留）。
  同日 3.45h 内 4 崩（14:31→17:58），同一 0xff/0xffff 沾染模式在不同
  16 位段之间迁移，唯一自然解释是装载返回通路（L1D 出口→bypass/移位
  网络→RF 写口）的 lane 选通错位：数据未变，『哪个字节进哪个槽』错了
  ——固定坏位无法产生这种段间迁移。
  案24 的 00ff|ffff 双段形态是迄今最直接的『标签跨段错位』活体样本：
  真值高 16 位 0xffff 的一半(00ff)留在顶段，另一半(ff)已溢出到次高段。
==============================================================================
六、最终闭合判定汇总
==============================================================================
  (1) x27 = x1 + x20            : 闭合
  (2) FAR = x27 + 0x120         : 闭合
  (3) x25 = 50 → __per_cpu_offset[50]（跨槽：CPU179 读 CPU50 的槽，调度域遍历正常行为）
  (4) x23 = 0x400 未见使用异常（致命装载目标寄存器，值未落地）
  (5) x20 低 12 位 = 0x240 ≠ 0：percpu 偏移 4K 页对齐不变式被破坏【实锤】
  (6) x20[63:48] = 0x00ff ≠ 0xffff：canonical 标签错位【实锤】

  推理链：x20 装载返回坏值 → add（纯正确指令）传播 → ldr 以坏 x27 寻址 →
          FAR 非法 → L0 translation fault → Oops。除 x20 装载本身外，
          每一步均被代数闭合验证为正确执行。
