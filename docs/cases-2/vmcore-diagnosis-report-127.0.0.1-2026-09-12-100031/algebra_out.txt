案 #27 代数闭合复算（mod 2^64）
==============================================================================

[输入] x27=0xd73fd531b2dc658c  x20=0xd74000ffffabcecc  x1=0xffffd431b33096c0
[输入] x25=0x0000000000000014(20)  x23=0x0000000000000400(1024)  FAR=0x003fd531b2dc66ac

------------------------------------------------------------------------------
一、加法器闭合 #1：x27 == x1 + x20 (mod 2^64)   ← add x27, x1, x20
------------------------------------------------------------------------------
  x1  = 0xffffd431b33096c0
  x20 = 0xd74000ffffabcecc
  和  = 0xd73fd531b2dc658c
  x27 = 0xd73fd531b2dc658c
  闭合判定: x27 == x1 + x20 → True
  【实锤】ALU 加法器与操作数装载完全正确；
          x27 的异常形态 100% 来自 x20。

------------------------------------------------------------------------------
二、闭合 #2 与 FAR 顶字节截断：FAR vs x27 + 0x120
------------------------------------------------------------------------------
  x27      = 0xd73fd531b2dc658c
  x27+0x120= 0xd73fd531b2dc66ac
  FAR      = 0x003fd531b2dc66ac
  逐位闭合判定: FAR == x27 + 0x120 → False
  XOR      = 0xd700000000000000
  低 48 位一致? True
  反证非移位 imm=0x48: x27+0x48 = 0xd73fd531b2dc65d4 ≠ FAR（排除）

  『不闭合』假象解剖（与案 #22 同模式）：
  - 差异仅在高 16 位：computed [63:48]=d73f vs FAR [63:48]=003f；
    XOR=0xd700000000000000，即只有顶字节 [63:56] d7→00，次字节 3f 保留；
  - 低 48 位（d531b2dc66ac）逐位一致——装载定序（基址+偏移）无错；
  - 案 #22（09-11-14:31）：computed 9226bb43eeea3c9d vs FAR 0026bb43eeea3c9d，
    XOR=0x9200000000000000——同样只有顶字节 92→00，次字节 26 保留；
  - 两案 XOR 模式严格同构（仅顶字节清零）→ 非规范 VA 进入翻译路径时
    顶字节被截断/替换是【系统性硬件行为痕迹】，不是随机错误；
  - 该痕迹不改变定罪：即使以 FAR 反推 x20，其低 48 位 00ffffabcecc
    仍非任何合法 percpu 偏移形态（页对齐破坏 + 标签错位不变）。

三、致命装载指令槽位解码
------------------------------------------------------------------------------
  Code: f9400782 f879d814 2a1903e0 8b14003b (f9409377)
  括号内 f9409377 = ldr x23, [x27, #0x120]  (288 字节偏移)
  前一条 8b14003b = add  x27, x1, x20
  再前 2a1903e0   = orr  x0, wzr, w25 (w25=0x14 → x0=20, 与 x0 dump=0x14 吻合)
  再前 f879d814   = ldr  x20, [x0, x25, sxtw #3]  ← __per_cpu_offset[20] 装载
  x25=20 → __per_cpu_offset[20]，即 CPU20 的 percpu 偏移槽（跨槽：本核 179 未读自己的槽）
  x20 装载返回 = 0xd74000ffffabcecc —— 即被腐化的 __per_cpu_offset[20] 读出值

四、x20 = d74000ffffabcecc 位级 16 位段分析（00ff|ffxx 相邻双段 + 高段注入）
------------------------------------------------------------------------------
  x20 = 0xd74000ffffabcecc
    [63:48] = 0xd740   ← d740：无 ff——标签完全离开顶段（高段随机注入，案 #22 的 9226 同型）
    [47:32] = 0x00ff   ← 0x00ff：ff 对齐到 bit39..32
    [31:16] = 0xffab   ← 0xffab：ff 又出现在 bit31..24
    [15: 0] = 0xcecc   ← 0xcecc：低 12 位=0xecc，页对齐段异常

  -- 与案 #24（09-11-17:06，00ff|ffb8 相邻双段）形态对照 --
  案24 x20 = 0x00ffffb810e4a240   段: 00ff | ffb8 | 10e4 | a240
  案27 x20 = 0xd74000ffffabcecc   段: d740 | 00ff | ffab | cecc
  结构对照：
    00ff 段位置 : 案24 在 [63:48]，案27 在 [47:32] —— 整体再下移 16 位
    ffxx 段位置 : 案24 在 [47:32]（ffb8），案27 在 [31:16]（ffab）—— 同步下移
    两案均为『00ff 与 ffxx 相邻』的双段结构，错位窗口整体漂移 16 位；
    案27 顶段被随机值 d740 占据（标签完全离开顶段）。

  -- 对照：x1 = ffffd431b33096c0（rq 指针，canonical 真值）--
  x1 = 0xffffd431b33096c0
    [63:48]=0xffff [47:32]=0xd431 [31:16]=0xb330 [15:0]=0x96c0

  -- x27 = x1 + x20 的逐段进位传播 --
  重算 x27 段值 = ['0xd73f', '0xd531', '0xb2dc', '0x658c']  vs dump x27 段值 = ['0xd73f', '0xd531', '0xb2dc', '0x658c']

  关键观察：
  1. x20[63:48]=0xd740：无任何 ff——canonical 标签从顶段完全消失；
     顶段被高熵随机值占据（与案 #22 顶段 9226 同型：高段注入）。
  2. 00ff|ffab 相邻双段（[47:32]+[31:16]）：ff 对连续出现在 bit39..32 与
     bit31..24——与案 #24 的 00ff|ffb8（[63:48]+[47:32]）同构，整体下移 16 位。
  3. x20[11:0]=0xecc ≠ 0：percpu 偏移 4K 页对齐不变式破坏【实锤】
     （谱系实测真值低 16 位有 e000/4000/8000 等，不变式取低 12 位；
     本机 dmesg percpu 4K 页 fallback 直接证据）。

六、最终闭合判定汇总
==============================================================================
  (1) x27 = x1 + x20            : 闭合
  (2) FAR vs x27 + 0x120        : 顶字节截断（XOR=0xd700…，低 48 位闭合）
