## 1. 摘要与置信度

开机 **35000 秒（9.72 小时）**后，CPU179 上的用户进程 neon_rot_ldr_at（PID 741633）在 **exit 系统调用退出路径**（`__arm64_sys_exit → do_exit → do_task_dead → __schedule → newidle_balance → load_balance → find_busiest_group`）中，执行 `__per_cpu_offset[]` 装载指令 `ldr x20, [x0, x25, sxtw #3]`（x25=0x14=20，读 CPU20 的槽，跨槽），**装载返回值 x20 = d74000ffffabcecc 被结构性腐化**：canonical 顶段被随机值 d740 占据（标签完全离开顶段，与案 #22 的 9226 同型高段注入），ff 对以 `00ff|ffab` 相邻双段形态出现在 [47:32]+[31:16]（与案 #24 的 `00ff|ffb8` 同构、整体下移 16 位），且低 12 位被注入 0xecc。该坏值经纯正确指令传播为非规范地址，触发 L0 translation fault。**FAR 顶字节呈现与案 #22 严格同模式的截断**（computed d73f… vs FAR 003f…，XOR=0xd700000000000000，仅顶字节 d7→00，次字节 3f 保留；案 #22 为 XOR=0x9200…，仅 92→00，26 保留）——两案互证这是非规范 VA 进入翻译路径时的**系统性硬件行为痕迹**而非随机错误。此前 676s 内爆发 **17 次 spurious 前兆**（全部 CPU179、`show_interrupts` 路径、『临终双簇』节奏），末次距致命 15.931s。RAS/EDAC/GHES 全程零上报；taint `G W` 与 17 次 WARNING 自洽。

neon_rot_ldr_at 的进程身份需如实澄清：它是 **openEuler 内存在线诊断工具 opendcdiag 派生的每核满载压测进程**（"NEON 旋转 load 地址"负载通路压测；谱系 #11 案 crash 实测确认 191 核各一个实例、父进程 opendcdiag）——**非本仓库 fi_research/probes 部署的探针**（计划勘察表中"本仓库满载探针"表述有误，本报告以 dmesg/谱系实测为准修正）。其首次成为致命受害者仍有诊断价值：谱系 #11 案中它是满载背景（受害者为 sftp-server），本案它自己死在退出路径上——**压测进程自身也被同一缺陷击中，排除"压测进程免疫/专属"的任何特殊解释**。

**三级置信度**：
- 现象层（17 次前兆 + x20 装载返回结构化坏值 → 传播 → 致命缺页 + FAR 顶字节截断痕迹）：**【实锤】**——dmesg 前兆全谱 + 寄存器 dump + mod 2^64 代数闭合（algebra_out.txt 第一~三节）。
- 通路归属（CPU179 核内装载返回通路 + PTW 读出通路的 lane/选通错位）：**【强推】**——形态结构化 + 与案 #22/#24 跨案同构复现 + 17 次前兆同核 + RAS 零上报；无 vmcore 无法实测真值，降一级。
- 物理位点：**【假设】**——软件不可分辨。

## 3. 指令级解剖

### 3.1 Code dump 五指令窗口反汇编（dmesg L3403）

```
f9400782   ldr  x2, [x28]                  // +0x128（上文，未参与致命链）
f879d814   ldr  x20, [x0, x25, sxtw #3]    // +0x130 ← __per_cpu_offset[x25] 装载（腐化点）
2a1903e0   orr  x0, wzr, w25               // +0x134（dump 时 x0=0x14）
8b14003b   add  x27, x1, x20               // +0x13c ← x27 = rq 基址 + percpu 偏移
(f9409377) ldr  x23, [x27, #0x120]         // +0x140 ← 致命装载（offset 288）
```

x0 dump 值 0x14 与 x25=0x14 逐字吻合——寄存器快照内部自洽。

### 3.2 x25=20 跨槽——正常行为

CPU20 属 Node 0，CPU179 属 Node 7——顶层调度域遍历跨 NUMA 读槽的标准动作（案 #25 读 CPU6 同理）。跨槽无异常，异常仅在装载返回值。

### 3.3 代数闭合与 FAR 顶字节截断（algebra_out.txt 第一~三节）

1. **x27 = x1 + x20**：`ffffd431b33096c0 + d74000ffffabcecc = d73fd531b2dc658c` ——**逐位闭合（True）**。加法器与两个源操作数读出全部正确。
2. **FAR vs x27 + 0x120**：computed = d73fd531b2dc66ac，FAR = 003fd531b2dc66ac ——**不逐位闭合，但差异完全受控**：
   - XOR = 0xd700000000000000——只有顶字节 [63:56] d7→00，次字节 [55:48] 3f 保留；
   - **低 48 位逐位一致**（d531b2dc66ac）——装载定序（基址+偏移）无错；
   - 与案 #22 严格同模式（XOR=0x9200000000000000，仅 92→00，26 保留）——**两案互证：非规范 VA 进入翻译路径时顶字节被系统性截断/替换**，是地址通路的硬件行为痕迹，不是另一次随机错误；
   - 定罪不受影响：即使以 FAR 反推，x20 低 48 位 `00ffffabcecc` 仍非任何合法 percpu 偏移形态（标签错位 + 页对齐破坏不变）。
3. **反证非移位偏移**：x27+0x48 ≠ FAR，排除解码错误。

**结论**：腐化点唯一且收口于 `ldr x20` 装载返回通路；FAR 顶字节截断为非规范 VA 翻译路径的伴生痕迹（与案 #22 合并观测）。

## 5. 前兆谱：17 次『临终双簇』

### 5.1 统计（dmesg_forensics.txt C 节）

- 17 次 `spurious`，全部 `CPU: 179`（17/17），地址全部 ffff6040 前缀（canonical）；
- 首次 34323.57s，末次 34983.61s，**末次距致命 15.931s**；
- 受害：PID 13780（pmdalinux）×16 + PID 9692×1，路径 `show_interrupts → seq_printf → __memcpy`（读 /proc/interrupts，与案 #7/#26 同路径）；
- 聚类（<60s）：**簇 1**（t=34324s，13 次，持续 100s）+ **簇 2**（t=34954s，4 次，持续 30s）。

### 5.2 节奏解读：9.5 小时静默后的临终双簇

开机 0~34323s（9.5h）**零前兆**，全部 17 次集中在致命前 676s 内，两簇间隔 630s。与案 #26 的三段式对照：本案是"超长静默 + 临终爆发"变体——**前兆不再分布全运行期，而是紧贴致命**。这加强"前兆与致命同发作窗"模型：缺陷被某种慢变量调制成发作窗，窗内 PTW 段（前兆）与数据返回段（致命）被先后击中；窗的位置可早可晚、可多可少，但**末次前兆总在致命的几十秒~几分钟内**（案 #20 0.72s、#26 1.75s、本案 15.9s、#8 21.2s）。

### 5.3 uptime=35000s：谱系第 4 长

谱系 uptime 谱（418s~6.21d）中 9.72h 位居第 4（次于 #3 6.21d、#2 66.5h、#1 31.6h 量级段），再次覆盖长运行段——触发与运行时长无关的又一数据点。

## 6. 反事实与软件排除

### 6.1 反事实推演（无 vmcore，不变式替代实测——降级声明重申）

- **若 x20 装载返回真值**（形如 `ffff_d4xx_xxxx_x000`）：x27 为 canonical 已映射地址，无 fault。正确执行永不崩溃。
- **真值侧补偿**：canonical 顶段 + 4K 页对齐双不变式同时破坏（4.1 节），且顶段为高熵随机值——"x20 ≠ 内存真值"仍为【实锤】。

### 6.2 软件成因排除

| 软件假设 | 排除证据 |
|---|---|
| 内核 bug | ① 官方 build #1（L3371），W taint 仅由 17 次 spurious WARNING 累积（自洽）；② 191 颗其他核同路径零异常，仅 CPU179 崩（谱系含本案 19/19 案同核）；③ 软件 bug 不挑核 |
| 坏页/页表被改 | ESR=0x96000004、S1PTW=0（L3361）——fault 为地址 noncanonical（between，L3367）；17 次前兆均"重走成功"（PTW 瞬时错、页表有效） |
| 竞态/内存序 | 纯读侧受害；坏值为结构化标签错排而非过期值 |
| 编译器/解码错 | Code 五指令窗口与符号偏移逐条吻合；x0=0x14 与 w25 自洽；imm 反证闭合 |
| 压测进程专属缺陷 | neon_rot_ldr_at 只是恰好运行在 CPU179 的 191 个满载实例之一；谱系受害者横跨 kworker/rcu_sched/swapper/sftp-server/mi-scavenger/claude 等 7+ 种进程——缺陷挑核不挑进程 |

### 6.3 硬件侧非核内通路排除

- **DIMM/内存控制器**：RAS 全程零上报（3406 行 hardware error 匹配 0）；19 案锁定 CPU179 与 DIMM 对称受害预期矛盾。
- **缓存一致性**：受害数据为内核全局数组元素读出；191 核对称受害预期与观测矛盾。
- **满载压测致扰**：NEON 满载下读通路多位腐化曾在谱系 #8 案记录；但 #11/#27 两案显示压测进程自身也受害、且零前兆案（#22-25）无压测背景时同样崩溃——压测非必要条件，至多为发作窗调制变量之一。

## 7. 根因三级置信判定与跨案对照

### 7.1 判定

1. **现象层【实锤】**：CPU179 上 17 次 spurious 前兆（34324-34984s，临终双簇）后，`__per_cpu_offset[20]` 装载返回结构化坏值 x20=d74000ffffabcecc（高段注入 + 00ff|ffab 相邻双段 + 页对齐破坏），经代数闭合传播为 L0 fault，开机 35000s 致命；FAR 顶字节截断（XOR=0xd700…）与案 #22 同模式。
2. **通路归属【强推】**：CPU179 核内装载返回通路 + PTW 读出通路的 lane 选通/定序间歇错位（SDC，无检错覆盖）。
   - 证据：与案 #22/#24 跨案三重同构（4.2/4.3 节）；17 次前兆同核临终双簇（5.2 节）；RAS 零上报 + 软件排除（6.2/6.3 节）。
   - **降级说明**：无 vmcore，真值对照不可执行。
3. **物理位点【假设】**：lane 选通/定序逻辑 + 非规范 VA 翻译路径顶字节处理。验证：offline CPU179；裸机 load-verify；厂商 shmoo/MBIST。
