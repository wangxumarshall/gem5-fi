==============================================================================
案 #25 代数闭合复算（mod 2^64）
==============================================================================

[输入] x27=0xffffdee405e696c0  x20=0x0000000000000000  x1=0xffffdee405e696c0
[输入] x25=0x0000000000000006(6)  x23=0x0000000000000400(1024)  FAR=0xffffdee405e697e0

------------------------------------------------------------------------------
一、加法器闭合 #1：x27 == x1 + x20 (mod 2^64)   ← add x27, x1, x20
------------------------------------------------------------------------------
  x1  = 0xffffdee405e696c0
  x20 = 0x0000000000000000
  和  = 0xffffdee405e696c0
  x27 = 0xffffdee405e696c0
  闭合判定: x27 == x1 + x20 → True
  【实锤】ALU 加法器与操作数装载完全正确；
          x27 == x1 —— x20 零塌缩使加法退化为恒等，
          x27 的值即 x1 原值（canonical），非法性 100% 来自
          x20 的零值（percpu 偏移装载返回 0）。

------------------------------------------------------------------------------
二、加法器闭合 #2：FAR == x27 + 0x120 (mod 2^64)  ← ldr x23, [x27, #288]
------------------------------------------------------------------------------
  x27      = 0xffffdee405e696c0
  imm      = 0x120 (=288, LDR unsigned offset 0x48<<3)
  x27+0x120= 0xffffdee405e697e0
  FAR      = 0xffffdee405e697e0
  闭合判定: FAR == x27 + 0x120 → True
  反证非移位 imm=0x48: x27+0x48 = 0xffffdee405e69708 ≠ FAR（排除）

------------------------------------------------------------------------------
三、致命装载指令槽位解码
------------------------------------------------------------------------------
  Code: f9400782 f879d814 2a1903e0 8b14003b (f9409377)
  括号内 f9409377 = ldr x23, [x27, #0x120]  (288 字节偏移)
  前一条 8b14003b = add  x27, x1, x20
  再前 2a1903e0   = orr  x0, wzr, w25 (w25=0x6 → x0=6, 与 x0 dump=0x6 吻合)
  再前 f879d814   = ldr  x20, [x0, x25, sxtw #3]  ← __per_cpu_offset[6] 装载
  x25=6 → __per_cpu_offset[6]，即 CPU6 的 percpu 偏移槽（跨槽：本核 179 未读自己的槽）
  x20 装载返回 = 0x0000000000000000 —— 即被腐化为全零的 __per_cpu_offset[6] 读出值

------------------------------------------------------------------------------
四、x20 = 0 零塌缩形态分析 + FSC=L2 的页表几何
------------------------------------------------------------------------------
  x20 = 0x0000000000000000
  真值应为 __per_cpu_offset[6]（canonical 内核地址、4K 页对齐、非零——
  percpu 偏移在 192 核系统上不可能为 0：percpu 区与静态区不同址）。

  零塌缩的两条不变式破坏：
  1. 顶段 0xffff → 0x0000：canonical 标签塌缩【实锤】
  2. 真值非零 → 0：__per_cpu_offset[] 全数组在 smp 初始化后无零元素
     （谱系 #4/#10/#11 案 crash 实测各槽真值均 ffff 开头非零）【实锤】

  零塌缩的传播几何（本案特有，与 L0 案不同）：
  x20=0 → x27 = x1 + 0 = x1（恒等） → FAR = x1 + 0x120
  FAR = ffffdee405e697e0 是 canonical 地址——
  所以本案 FSC = 0x06 level 2 translation fault 而非 L0/between：
  内核页表 walk（L2591-2592）: pgd=...f403(有效) pud=...e403(有效)
  pmd=0x0000000000000000 ← L2 断链，该地址落在未建立 PMD 映射的空洞

  语义解读：x1 是 percpu 静态基址形态的 canonical 指针（ffffdee4....），
  本应加上 __per_cpu_offset[6] 平移到 CPU6 实例地址；零偏移使寻址
  落回『静态区某空洞 + 0x120』——数据通路腐化被页表几何忠实记录。

六、最终闭合判定汇总
==============================================================================
  (1) x27 = x1 + x20 (= x1)      : 闭合
  (2) FAR = x27 + 0x120          : 闭合
  (3) x25 = 6 → __per_cpu_offset[6]（跨槽：CPU179 读 CPU6 的槽，调度域遍历正常行为）
  (4) x23 = 0x400 未见使用异常（致命装载目标寄存器，值未落地）
  (5) x20 = 0：canonical 标签 + 非零性双不变式破坏【实锤】
  (6) FSC = L2（pmd=0）：零偏移使 FAR 落入未映射空洞——
      canonical-but-unmapped 几何，与 L0 案的 noncanonical 几何互为镜像

  推理链：x20 装载返回 0（零塌缩）→ add 恒等传递 → ldr 以 x1+0x120
          寻址 → FAR canonical 但 L2 断 → translation fault → Oops。
          除 x20 装载本身外，每一步均被代数闭合验证为正确执行。
