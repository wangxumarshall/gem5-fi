## 3. 指令级解剖(同族链条 + x25=179 自指)

Code 流反汇编(手工解码,已用 Python 逐位验证编码):

```
+0x128  f9400782  ldr  x2,  [x28]           (无关前置)
+0x12c  f879d814  ldr  x20, [x0, w25, sxtw #3]   <<< 谱系同族装载指令
+0x130  2a1903e0  orr  w0, wzr, w25         (w0 = cpu 编号)
+0x134  8b14003b  add  x27, x1, x20         (x27 = rq 基址 + percpu 偏移)
+0x138→+0x140  (f9409377)  ldr x23, [x27, #288]  <<< 崩溃点: 读 rq->cfs.avg (0x120=288)
```

注:pc 指向 +0x140 即 faulting load 本身;装载 x20 的指令在 +0x12c(谱系 12 案综合报告记为 +0x134,系各内核 build 布局微差,同一函数同一模式)。

**逐步链条**:
1. `x0 = 0xb3 = 179`、`w25 = 0xb3 = 179`:x0 是 `__per_cpu_offset[]` 数组基址(经 `adrp+add` 或 PC 相对寻址装入,现场 x0=179 显然不是裸指针——它是 THIS_CPU 参数化后的数组基*入口约定,详见下),w25 是被考察的目标 CPU 编号。**x25=179=CPU179 自身:本核正在装载自己的 percpu 偏移槽 `__per_cpu_offset[179]`** —— 自指装载。这是谱系中首次观测到严格自指实例(此前各案 w25 为被均衡考察的对端核编号)。
2. `ldr x20, [x0, w25, sxtw #3]`:有效地址 = x0 + 符号扩展(w25)×8 = __per_cpu_offset 数组首 + 179×8,即槽位 [179]。**返回坏值 9226e000ffffa4bd**。
3. `add x27, x1, x20`:x1=ffffdb42eeea96c0(规范内核指针,`this_rq` 类基址),x27 = x1+x20 = 9226bb43eeea3b7d,**代数逐位闭合(algebra_out.txt 闭合 1,汉明距离 0)** —— 加法器无错。
4. `ldr x23, [x27, #288]`:有效地址 = x27+0x120 = 9226bb43eeea3c9d,**但 FAR=0026bb43eeea3c9d,高 16 位 9226→0026,差 3 位(bit 55/58/61 附近,实测 XOR=0x9200)** —— 见第 4 节,这不是错,而是 PA/VA 翻译路径上的规范截断痕迹。

**关于闭合 2 的"不闭合"假象**:x27+0x120=9226bb43eeea3c9d 而 FAR=0026bb43eeea3c9d,汉明距离 3,差异位 = bit63/60/57(XOR=0x9200000000000000),全部落在 [63:48] 段(9226 vs 0026,共享低字节 0x26)。经逐段进位解剖(algebra_out.txt 形态 C),x27=x1+x20 的 64 位加法 100% 闭合,x27[63:48] 实测就是 9226;即 AGU 交给 MMU 的 VA 高 16 位应为 9226,而 FAR 记录为 0026——这是非规范 VA 进入翻译路径时高位段被截断/替换的痕迹。关键事实是:**FAR 的低 48 位 bb43eeea3c9d 与 x27+0x120 的低 48 位逐位一致**,装载定序(基址+偏移)本身无错。dmesg-only 无法进一步解析这 3 位的硬件级成因,标注为【假设:高位段在地址通路被截断/重映射】;不影响"x20 坏值是唯一注入源"的定罪,因为即使以 FAR 为准反推,x20 的低 48 位 e000ffffa4bd 仍非任何合法 percpu 偏移形态。

**与谱系 12 案链条对照**(SYNTHESIS-12case-cross-analysis.md §2.2):同一受害指令族 `__per_cpu_offset[]` 装载、同一传播路径 add→ldr #288(rq.cfs.avg.load_avg 读)、同一崩溃函数 find_busiest_group+0x140。本案完全落入该不变式,并新增"自指槽位"实例。

## 4. 坏值形态位级解剖:9226e000ffffa4bd 混合形态

(全部计算真实输出见 `algebra_out.txt`;本节数字均已复核)

**16 位段视图(高→低):`9226 | e000 | ffff | a4bd`**

| 段 | 值 | 判读 |
|---|---|---|
| [63:48] | 9226 | **注入异常段**。真值形态必须 ffff 开头(内核规范指针,同现场 x1/x21/x24 均 ffff 开头)。9226 与最终 FAR 的 0026 段差 3 位(XOR=0x9200,差异位 = bit63/60/57,两段共享低字节 0x26)——坏值高段与传播终态高段同源:经加法回绕 x27[63:48] 仍为 9226(形态 C:ffff+9226+进位=19226,落段 9226,溢出丢弃),FAR 记录时高位段被地址通路截断为 0026 |
| [47:32] | e000 | **中段半字节标签**。与谱系 #7 案(08-31)的 0xa000 顶标签同构——16 位段内高 3 位为 1、低 13 位为 0 的"半字节标签"形态,是选通/移位网络的指纹,不是数据 |
| [31:16] | ffff | **低 16 位 0xffff 标签再现**。谱系反复出现的 ffff 标签段(案 #19 x20=ffdc206dfa4000ff 的 00ff 尾、案 #23 x20=ffa9342267e000ff 的 00ff 尾、本案 ffff 整段)——同一标签发生源 |
| [15:0] | a4bd | 形似数据残段(与 x1 低段 96c0 无 lane 对应) |

**eeea 段保留的代数成因(重要澄清)**:x27 与 FAR 的 [31:16] 段均为 eeea,与 x1 的 eeea 段完全一致,看似"真值残段保留";但逐段进位链证明这是**代数必然而非独立现象**:x1[31:16](eeea) + x20[31:16](ffff) + 进位1 = 0x1eeea,落段恰回 eeea——x20 的 ffff 段加上低位进位恰好凑满 0x10000 回绕,把 x1 的 eeea 段原样透传。**坏值中段 ffff 与真值残段的叠加,正是"混合形态"的几何本质:标签段注入 + 真值段经加法结构透传,两者交织。**

**错位窗口几何**:
- x20 与 x1 汉明距离 31 位;x20 与 FAR 距离 20 位;x27 与 x1 距离 24 位(形态/汉明表)。
- x20 的 4 个 16 位 lane 与 x1 的 4 个 lane 交集仅 {ffff}(假设检验节)——**x20 不是 x1 的纯 lane 重排**,高段 9226/e000 为注入段,非真值移位所得。这区别于谱系 #1 案(16bit lane 循环错位重组,真值 lane 全保留)。
- 低 16 位 a4bd:与 x1 低段 96c0 无明显算术关系;若假设真值 offset 低 16 位与 a4bd 的关系,无 vmcore 真值不可判(降级声明)。

**形态族归属**:混合形态 = 高段位翻转(9226 注入,部分保留/部分翻转族特征)+ 中段 e000 半字节标签(lane 错位族 #7 案同构指纹)+ 低 16 位 ffff 标签(lane 错位族标签再现)。**本案是"部分位保留族"与"lane 错位族"的混合实例**,支持谱系结论:四族同核出现,非存储单元固定坏,而是通路瞬时/间歇定序与选通错误(§2.3)。

**四连崩形态对照**(原始 dmesg,非报告):
- 案 #22 x20=9226e000ffffa4bd(混合形态)
- 案 #23 x20=ffa9342267e000ff(ff 开头但仍非规范+00ff 尾标签,与案 #19 ffdc206dfa4000ff 高度同构)

## 6. 反事实与软件排除

**反事实推理**(dmesg-only 降级版):
- 若 x20 装载返回真值(ffff 开头 percpu 偏移),则 x27=x1+true_offset 必为规范内核指针(与现场 x21/x24 同前缀形态),`ldr x23,[x27,#288]` 正常读回 load_avg,无缺页。链条中**唯一**能产生非规范地址的环节就是 x20 的装载返回值。

- 无 vmcore,无法实测 `__per_cpu_offset[179]` 内存真值与目标 PTE——真值级反事实(谱系 §2.5 的 vtop 全 VALID 证明)本案不可达,此为降级点。但谱系 10 个可对照案的真值全部完好、本案四连崩姊妹案 #25 的 x20=0 形态与 #10/#11/#12 零塌缩先例一致,内存阵列坏值的先验概率极低。

**软件排除**:
1. **非调度器 bug**:同一二进制(6.6.0-145.3.23.154,行 2)在同批次机器亿万次执行该路径,唯此机此核崩溃;find_busiest_group 的 `__per_cpu_offset` 装载是教科书式 percpu 访问,代码正确性无争议。
2. **非 KASAN/KFENCE 等检测框架**:Not tainted、无相关日志。
3. **非竞态/并发误用**:寄存器现场代数自洽(闭合 1 零误差),若是竞态踩内存,x27 与 x1+x20 无法逐位吻合。
4. **非内存条物理坏(直读)**:RAS/EDAC 零 CE/UE 上报;且四连崩跨冷启动、形态各异(固定坏位应驻留复现同值);x20 高段 9226/e000 标签形态与"选通错误"而非"存储坏位"指纹一致。

**软件成因可排除性置信**:【强推】(dmesg-only 无法做二进制 diff 级绝对排除,但六路证据全部指向排除)。

- 反事实(§2.5):本案降级为代数闭合 + 形态学(无 vmcore),结论方向与谱系一致
