四、x20 = ffa9342267e000ff 位级 16 位段分析（双端 ff 沾染形态）
------------------------------------------------------------------------------
  x20 = 0xffa9342267e000ff
    [63:48] = 0xffa9   ← 非 canonical 内核标签（真值此段应 0xffff）
    [47:32] = 0x3422   ← 0x3422：随机数据段
    [31:16] = 0x67e0   ← 0x67e0：随机数据段

  -- 对照：x1 = ffffd6cc5ea996c0（rq 指针，canonical 真值）--
  x1 = 0xffffd6cc5ea996c0

  -- x27 = x1 + x20 的逐段进位传播 --
  x27 = 0xffa90aeec68997bf
    [63:48]=0xffa9 [47:32]=0x0aee [31:16]=0xc689 [15:0]=0x97bf
  重算 x27 段值 = ['0xffa9', '0x0aee', '0xc689', '0x97bf']  vs dump x27 段值 = ['0xffa9', '0x0aee', '0xc689', '0x97bf']

  关键观察：
  1. x20[63:48]=0xffa9 —— canonical 内核指针此段必为 0xffff；
     ff 仅存于顶字节 [63:56]（bit63..56），次字节为 a9——半标签钉顶。
  2. x20[15:0]=0x00ff —— ff 又出现在底字节 [7:0]：同一 0xffff 标签的
     另一 ff 字节被搬运到寄存器最低字节——『双端 ff 沾染』。
  3. x20[11:0]=0x0ff ≠ 0 —— percpu 偏移真值低 12 位恒为 0（4K 页对齐；
     谱系实测真值低 16 位有 e000/4000/8000 等，故不变式取低 12 位），
     该 0x0ff 是注入位，经加法污染 x27[15:0]。
  4. 中段 6 字节 a9 34 22 67 e0 00 与现场所有寄存器值（x1/x21/x22/x24/
     x26/x9/x15）的全部 8 字节窗口及移位重排逐一比对均不匹配——
     判定为高熵随机注入，非任何可见数据的搬运。

  - 案23 (ffa9..e000ff)：0xff 前缀钉在 [63:56]，0xff 尾缀落在 [15:8]；

六、最终闭合判定汇总
==============================================================================
  (1) x27 = x1 + x20            : 闭合
  (2) FAR = x27 + 0x120         : 闭合
  (3) x25 = 164 → __per_cpu_offset[164]（跨槽：CPU179 读 CPU164 的槽，调度域遍历正常行为）
  (4) x23 = 0x400 未见使用异常（致命装载目标寄存器，值未落地）
  (5) x20 低 12 位 = 0x0ff ≠ 0：percpu 偏移 4K 页对齐不变式被破坏【实锤】
  (6) x20[63:48] = 0xffa9 ≠ 0xffff：canonical 标签错位【实锤】

  推理链：x20 装载返回坏值 → add（纯正确指令）传播 → ldr 以坏 x27 寻址 →
          FAR 非法 → L0 translation fault → Oops。除 x20 装载本身外，
          每一步均被代数闭合验证为正确执行。
