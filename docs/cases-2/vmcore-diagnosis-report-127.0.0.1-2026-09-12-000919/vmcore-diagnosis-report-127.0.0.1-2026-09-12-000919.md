## 1. 摘要与置信度

开机 **21773 秒（6.05 小时）**内，CPU179 上累计爆发 **63 次 spurious kernel translation fault 前兆**（全部 CPU179，受害者以 pmdalinux 为主，路径为 `/proc/interrupts` 读取的 `show_interrupts → seq_printf → __memcpy` 与 rcu_sched 路径），前兆呈现**『发作期（2141-3711s，57 次）- 静默期（3711-7811s，4100s 零前兆）- 零星（7811-9181s，5 次）- 尾段再起（20991-21771s，6 次）』三段式节奏**。最终（21773.0s，uptime 6.05h）CPU179 上的用户进程 mi-scavenger（PID 1004936）在 futex 睡眠路径（`futex_wait → schedule → newidle_balance → load_balance → find_busiest_group`）中，执行 `__per_cpu_offset[]` 装载指令 `ldr x20, [x0, x25, sxtw #3]`（x25=0xac=172，跨槽），**装载返回值 x20 = ffdfb79a8ee000ff 被结构性腐化**——其结构签名（顶字节 ff 存活 + 尾段 00ff）与前一 boot 的案 #23（ffa9342267e000ff）**跨 boot 同构复现**。该坏值经两条纯正确指令传播为非法地址 ffdf57e3756298df，触发 L0 translation fault 致命 Oops。末次前兆距致命仅 **1.752 秒**。RAS/EDAC/GHES 全程零上报；taint `G W` 与 63 次 WARNING 自洽。

**三级置信度**：
- 现象层（63 次前兆 + x20 装载返回结构化坏值 → 经闭合加法传播 → 致命缺页）：**【实锤】**——dmesg 前兆全谱 + 寄存器 dump + mod 2^64 逐位代数闭合（algebra_out.txt 第一~三节）。
- 通路归属（CPU179 核内装载返回通路 + PTW 读出通路的 lane/选通错位，非内存/软件/一致性）：**【强推】**——形态结构化 + 跨 boot 签名复现 + 63 次前兆同核 + RAS 零上报；但因本案无 vmcore，无法实测真值，故降一级。
- 物理位点：**【假设】**——软件不可分辨。

## 3. 指令级解剖

### 3.1 Code dump 五指令窗口反汇编（dmesg L5480）

```
f9400782   ldr  x2, [x28]                  // +0x128（上文，未参与致命链）
f879d814   ldr  x20, [x0, x25, sxtw #3]    // +0x130 ← __per_cpu_offset[x25] 装载（腐化点）
2a1903e0   orr  x0, wzr, w25               // +0x134（dump 时 x0=0xac）
8b14003b   add  x27, x1, x20               // +0x13c ← x27 = rq 基址 + percpu 偏移
(f9409377) ldr  x23, [x27, #0x120]         // +0x140 ← 致命装载（offset 288）
```

x0 dump 值 0xac 与 x25=0xac 逐字吻合——寄存器快照内部自洽。

### 3.2 x25=172 跨槽——正常行为

CPU172 与 CPU179 同属 Node 7（172 属 164-191 簇），负载均衡遍历 MC/NUMA 域时读邻近 CPU 槽是标准动作。跨槽无异常，异常仅在装载返回值。

### 3.3 代数闭合（algebra_out.txt，mod 2^64，全部 True）

1. **x27 = x1 + x20**：`ffffa048e68296c0 + ffdfb79a8ee000ff = ffdf57e3756297bf` ——逐位闭合。
2. **FAR = x27 + 0x120**：`ffdf57e3756297bf + 0x120 = ffdf57e3756298df` ——逐位闭合。
3. **反证非移位偏移**：x27+0x48=...9807 ≠ FAR，排除解码错误。

**结论**：腐化点唯一且收口于 `ldr x20` 装载返回通路，其余每一步代数闭合证明正确。

## 4. 形态分析：双端 ff 沾染——跨 boot 签名复现

### 4.1 x20 = ffdfb79a8ee000ff 逐 16 位段解剖

### 4.2 与案 #23 的跨 boot 同构对照（algebra_out.txt 第四节）

两次独立开机、不同槽位（164 vs 172）、不同 x1 基址（ffffd6cc vs ffffa048），产生**结构骨架相同**的坏值：`ff?? ?????? ??00ff`。这一跨 boot 复现有力排除"单次宇宙线/单次噪声"解释——**同一形态签名在不同时间、不同数据背景下重现，是通路级结构性缺陷的指纹**。同时中段完全不同又排除"固定坏位"（坏位会产生位置与值均固定的错误）。

## 5. 前兆谱：63 次三段式节奏（本案核心增量）

### 5.1 全谱统计（dmesg_forensics.txt C 节，63 行全录）

- **总数 63 次**，全部 `WARNING: CPU: 179`（63/63 同核）；
- 首次 2141.32s，末次 21771.26s，末次距致命 **1.752s**（谱系第 3 短，仅次于案 #20 的 0.72s 与谱系 #8 案的 21.17s 之后的量级）；
- 受害进程：pmdalinux×60（读 `/proc/interrupts` 的 `show_interrupts → seq_printf → __memcpy` 路径，与谱系 #7 案同路径）、rcu_sched×2、mi-scavenger×1、irqbalance×1；
- 前兆地址：ffff6040 前缀×54（percpu/vmalloc 区）+ ffff0040 前缀×9（含一次非对齐 3491s 栈中 x24/x21 显示 ffff004009f2b446/450 memcpy 目的地址族）——全部 canonical。

### 5.2 三段式节奏（algebra_out.txt 第五节，16 簇聚类）

| 阶段 | 时间窗 | 簇 | 次数 | 特征 |
|---|---|---|---|---|
| 发作期 | 2141-3711s（开机 0.6~1.0h） | 簇 1-9 | 57 | 密集爆发，单簇最密 12 次/60s（簇 7），簇间间隔 ~150-300s |
| 静默期 | 3711-7811s | — | 0 | **4100 秒完全静默** |
| 零星期 | 7811-9181s | 簇 10-13 | 5 | 孤立单发 |
| 尾段再起 | 20991-21771s（致命前 782s 起） | 簇 14-16 | 6 | 再度成簇，末次距致命 1.752s |

**解读**：前兆不是均匀泊松，也不是单调加剧，而是**阵发性簇 + 长静默 + 临终再起**。这与"通路级间歇缺陷"模型一致：缺陷受某种慢变量（温度/电压/频率边界、后台负载引起的微架构状态）调制进入发作窗；尾段再起且紧邻致命（1.75s），说明致命崩溃与前兆同源同通路——**PTW 页表读出段（前兆）与数据返回段（致命）在同一发作窗内先后被击中**。

### 5.3 uptime=21773s：谱系中位附近

谱系 uptime 谱（418s~6.21d）中 6.05h 居中。本案的时间结构信息量全部在前兆谱里，uptime 本身无特殊性。

## 6. 反事实与软件排除

### 6.1 反事实推演（无 vmcore，不变式替代实测——降级声明重申）

- **若 x20 装载返回真值**（形如 `ffff_a0xx_xxxx_x000`）：x27 = x1 + 真值为 canonical 已映射地址，无 fault。正确执行永不崩溃。
- **真值侧补偿**：canonical 顶段 + 4K 页对齐双不变式同时破坏（4.1 节），`__per_cpu_offset[172]` 真值必然同时满足两条（dmesg L321-322 percpu 4K 页 fallback 直接证据）。"x20 ≠ 内存真值"仍为【实锤】。

### 6.2 软件成因排除

| 软件假设 | 排除证据 |
|---|---|
| 内核 bug | ① 官方 build #1（L5446），W taint 仅由 63 次 spurious WARNING 累积（自洽，无第三方模块）；② 191 颗其他核同路径零异常，仅 CPU179 崩（谱系含本案 18/18 案同核）；③ 软件 bug 不挑核 |
| 坏页/页表被改 | ESR=0x96000004、S1PTW=0（L5436）——fault 为地址 noncanonical（between，L5442），页表完好由 fault 类型反证；且 63 次前兆均为"重走成功"的 spurious（PTW 读出瞬时错、页表本身有效） |
| 竞态/内存序 | 前兆与致命均为读侧；坏值为结构化标签错排而非过期值 |
| 编译器/解码错 | Code 五指令窗口与符号偏移逐条吻合；x0=0xac 与 w25 自洽；imm 反证闭合 |
| 用户态肇因 | 前兆受害者横跨 pmdalinux/rcu_sched/mi-scavenger/irqbalance 四种进程，致命为 mi-scavenger futex 路径——共同点只有 CPU179，不是任何特定进程 |

### 6.3 硬件侧非核内通路排除

- **DIMM/内存控制器**：RAS 全程零上报（5483 行全文 hardware error 匹配 0）；18 案锁定 CPU179 与 DIMM 坏的对称受害预期矛盾。
- **缓存一致性**：受害数据为内核全局数组元素读出，191 核对称受害预期与观测矛盾。
- **L1D 阵列驻留损伤**：谱系 #7 案 L1D 禁用实验期间仍复发；本案跨 boot 签名复现（4.2 节）进一步排除"单次阵列损伤"。

## 7. 根因三级置信判定与跨案对照

### 7.1 判定

1. **现象层【实锤】**：CPU179 上 63 次 spurious 前兆（2141-21771s，三段式节奏）后，`__per_cpu_offset[172]` 装载返回结构化坏值 x20=ffdfb79a8ee000ff（双不变式破坏 + 双端 ff 沾染），经代数闭合传播为 L0 fault，开机 21773s 致命，末次前兆距致命 1.752s。
2. **通路归属【强推】**：CPU179 核内装载返回通路 + PTW 读出通路的 lane 选通/定序间歇错位（SDC，无检错覆盖）。
   - 证据：跨 boot 形态签名复现（4.2 节）；63 次前兆同核同通路三段式（5.2 节）；RAS 零上报 + 软件排除（6.2/6.3 节）；谱系同构。
   - **降级说明**：无 vmcore，真值对照不可执行。
3. **物理位点【假设】**：lane 选通/定序逻辑。验证：offline CPU179；裸机 load-verify；厂商 shmoo/MBIST。

### 7.3 对谱系总图的增量

- **双端 ff 沾染子形态跨 boot 复现**——形态复现粒度从"族"细化到"签名"，排除单次噪声、锁定结构性缺陷指纹；
