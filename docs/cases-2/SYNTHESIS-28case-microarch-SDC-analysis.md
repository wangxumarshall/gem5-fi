## 1. 推理基础:代数闭合与实测对流水线的逐段有罪/无罪判定

每案的 mod 2⁶⁴ 闭合(`x27 = x1 + x20`、`FAR = x27 + 0x120` 全案 True)+ 案 28 crash 实测,把微架构流水线逐段做了判定:

| 流水段 | 判定 | 证据 |
|---|---|---|
| 取指/解码 | **无罪** | Code 五指令窗口与 crash `sym` 实测逐条吻合(案 28:`find_busiest_group = ffffcad7040cad08`);imm=0x48 反证全案闭合 |
| RF **读**口 | **无罪** | x0/x25 dump 值逐字自洽(案 28:x0=0x7=x25;案 23/24/26/27 同型) |
| AGU 地址生成 | **无罪** | FAR = x27+0x120 全案闭合;案 28 vtop 实测页表 walk 与 ESR 互证;案 22/27 FAR 顶字节截断为系统性痕迹而非 AGU 错 |
| ALU | **无罪** | x27 = x1+x20 全案闭合(零塌缩案为恒等仍闭合) |
| 内存/缓存**阵列内容** | **无罪** | 11 案 crash 实测 `__per_cpu_offset[]` 真值完好;spurious fault AT 指令重走即成功;案 28 **x17 化石** = 同核此前正确装载的槽 179 真值(`0xffffb5297bce4000` 与 crash 实测逐位一致) |
| **装载返回数据通路** | **有罪(唯一)** | x20 是唯一注入点;28 案形态各异但全部破坏 percpu 偏移不变式(canonical 顶段 / 4K 对齐 / 非零) |

由此故障窗口被压缩到:

```
L1D way-mux → 输出对齐移位器(非对齐装载支持) → 装载/fill buffer(字节合并逻辑)
→ 旁路网络(store-to-load 转发 mux) → 结果总线 → RF 写口(byte enable)
```

**这一段正是 ECC/奇偶保护覆盖不到的"运输段"**——直接解释 RAS/EDAC/GHES 全程零上报:不是没有监测,是这类故障在保护范围之外,**SDC(静默数据腐化)是其定义属性**。

## 2. 形态族 → 微架构机制映射

28 案的形态族(12 案 census 四族 + 案 20~28 增量)不是四个病灶,而是**同一病灶被不同控制信号受扰后的表现**:

| 形态族 | 案例 | 观测特征 | 指向的微结构 |
|---|---|---|---|
| **零塌缩** | 9 案(4/6/10/11/12/20/25/28 + 2 部分) | x20 = 0,整 64 位全零;FAR canonical 但落入页表空洞(L2/L3 由空洞深度决定,案 25 pmd=0/案 28 pte=0 实测) | **数据通路整字未驱动/选通到零源**:way-mux 输出使能失配、fill buffer 数据锁存未打开(时钟门控边际)、旁路 mux 误选空 STQ 项。预充电总线无人驱动 → 读 0 |
| **lane 错位·纯移位** | 3 案(1/5/7) | ror16(真值)+0xa000 标签、+1 字节窗口、16bit 循环移位 | **输出对齐移位器(barrel shifter)的移位量控制错**:非对齐装载要求按地址低位旋转数据,移位量控制单次受扰 → 整字 rol/ror 8/16/32 位 |
| **lane 错位·混合** | 6 案(21/22/23/24/26/27) | ff 标签部分存活于**任意 16 位边界**(完整 ffff 落 [31:16]@22、双端抛掷 56 位@23、相邻字节撕裂 00ff\|ffb8@24、撕裂下移 16 位 00ff\|ffab@27、双端签名跨 boot 复现@26)+ 随机中段 + 随机顶段 | **字节 lane 选通/合并逻辑按 lane 独立选错源**:部分 lane 取真值、部分取他源、部分取零。案 23 的中段来源排除(无任何现场寄存器可作母本)说明"他源"不是可见寄存器,而是通路上的并发返回项 |
| **部分位保留** | 2 案(8/9) | 26/35 位约半数翻转、低段形态保留 | **总线双驱动竞争**:两个源使能重叠(使能时序边际),逐位随机分胜负——"半数翻转"是竞争的指纹 |
| **读写双向** | 2/3/6 前兆 | 前兆含写方向假 fault(坏 dst 指针来自装载) | 仍收口于装载返回通路(装载来的指针坏 → 传给 store),不需额外假设 store 数据通路坏 |

**关键统一性**:数据 lane 本身坏(位翻转在原位)**从未出现**——所有形态都是"字节/段去了不该去的位置"或"整字归零"。这把嫌疑从数据线转移到**控制线**(mux select、byte enable、clock gate、shift amount):控制字一次受扰,取值不同 → 形态族不同。与跨案观察严格一致:同一核每次发作错排量随机、形态族同日交替(案 22~25 四连崩 3.45h 内 lane 错位×3 + 零塌缩×1)。

## 3. 前兆(PTW)与病灶域的横向边界

- **spurious fault 前兆**(谱系 19 个 dump 累计 473 次,2026-09-15 全量 grep 实测;案 28 单案 184 次新纪录):页表行走读出一次受扰、AT 指令重走即成功。PTE 是普通可缓存内存,若驻留 L1D/L2,则 PTW 读出与装载返回**共享同一私有读出/搬运段**——前兆与致命是同通路两类表现,只是被击中的消费者不同(TLB vs 通用寄存器)。
- **案 7 的 17 轮 L1D 禁用实验期间仍复发**:病灶在 L1D 阵列**之后**的搬运段(装载缓冲字节合并/旁路选通/RF 写口)或私有 L2 读出段,而非 L1D 阵列读出本身。
- **核私有性**:28/28 案锁定 CPU179,排除一切共享结构(L3、内存控制器、DIMM、一致性互连、固件)。剩余候选全部位于 CPU179 私有域内——这也是硅片级个体偏差(某条控制路径 setup/hold 余量天生不足)的自然解释。
- **案 21 反证**:CPU179 曾于 1308.5s 被 offline、61118.98s re-online,**全部 3 次前兆与致命都发生在 re-online 之后**(61118 → 74323 → 76274)——核在线即累积风险,offline 期间零事件,处置上唯一根治手段是永久下线。

## 4. 间歇性画像指向"时序边际"而非"固定损伤"

| 观察 | 数据 | 推论 |
|---|---|---|
| 形态逐次随机 | 同核同指令同数组,形态族/错排量每次不同(四连崩四形态) | 排除 stuck-at(位置与值固定) |
| 同址复读正常 | spurious fault 重走即成功;案 28 x17 化石 | 排除阵列驻留损伤 |
| uptime 全谱覆盖 | 418s(案 5)~ 6.21d(案 3),案 24 开机 1592s 冷机即崩 | 排除老化/应力累积(温升/疲劳)模型 |
| 跨冷启动复现 | 09-11 四连崩 = 4 次独立 boot;连续 6 个 boot 复发(至案 27) | 排除易失性状态(缓存残留/TLB/软件状态) |
| 发作窗结构 | 案 28:43 簇多发作窗(首窗 7.15h→**25.02h 大静默**→再发作→临终加密,末簇 35 次/250s);案 26 三段式;案 27 临终双簇 | 受慢变量调制。高负载(案 28 load 174/192)时 di/dt 电压跌落是触发 setup violation 的经典机制 |
| 前兆-致命间隔 | 0.72s(案 20,新纪录)/1.75s(26)/15.9s(27)/21.2s(8)/102.5s(28) | 前兆与致命同发作窗内先后被击中;前兆是可观测预警 |

综合:**正常工作点附近的时序边际,偶发失配**——而非老化/热致退化或固定制造缺陷。(诚实注记:前兆簇的节拍部分反映 pmdalinux 轮询/调度到 CPU179 的采样节律,去卷积后才能断言底层故障率的真实簇结构。)

## 5. SDC 分类学定位与判别实验

对照大规模集群 SDC 文献的分类(ALU 类 / RF 类 / cache 阵列类 / 搬运-控制类),本案属**最难抓的最后一类:数据搬运段控制信号边际(wrong mux select / missed enable / wrong shift)**——它绕过所有阵列 ECC,只有功能级测试能暴露。

剩余候选(软件上不可分辨,按可能性排列):
1. **旁路网络 lane 选通**(store-to-load 转发 mux)——解释混合形态的"他源 lane";
2. **装载/fill buffer 字节合并逻辑**——解释字节粒度撕裂/错排;
3. **RF 写口 byte-enable**——解释按 lane 独立选错;
4. **L1D 输出对齐移位器**——解释纯移位形态。

### 判别实验(按判别力排序)

| # | 实验 | 预期结果 | 判别力 |
|---|---|---|---|
| 1 | **offline CPU179** 后长时观察 | 前兆/崩溃归零(案 21 已有 offline 期间零事件的天然实验) | 定核;唯一止血手段 |
| 2 | **每核 load-verify 已知答案循环**,刻意覆盖非对齐/字节/半字装载(激活 lane 合并逻辑全分支),双核冗余比对 | 仅 CPU179 出错;错误形态与 vmcore 谱系对应 | 直接复现 + 形态对照 |
| 3 | **V/F margin shmoo**(降压/降频扫描) | 时序边际对电压敏感,固定缺陷不敏感 | **区分"边际"与"损伤"的决定性实验** |
| 4 | **厂商 at-speed path-delay 测试** | 搬运段控制路径 fail | 注意:MBIST 只测阵列,**测不到搬运段**——必须指明测旁路/装载缓冲控制路径 |

## 6. 置信度边界(三级)

- **【实锤】**:故障位于装载返回通路内(11 案真值实测 + 案 28 三重实测);单次间歇;无检错覆盖;核私有(28/28);控制类而非数据位翻转类(0 案原位翻转)。
- **【强推】**:受扰对象是字节 lane 选通/使能/移位量等**控制信号**;机制为时序边际类(发作窗/负载调制/V-F 敏感间接支持)。
- **【假设】**:具体物理位点(旁路 vs 装载缓冲 vs RF 写口 vs L1D 输出移位器,上述四候选);物理触发(电压跌落 setup violation vs 控制锁存器个体缺陷);以及 FAR 顶字节截断(案 22/27 同模式 XOR=0x9200…/0xd700…,仅顶字节清零、低 48 位一致)暗示的地址通路顶字节过滤行为——均为 dmesg/软件侧不可再分,须上表判别实验。

## 7. 对 12 案 census(SYNTHESIS §4/§5)启示的增量确认

1. **load 返回通路检错盲区**(SYNTHESIS §4.1)获 28 案更广样本支持——形态谱(第 2 节)进一步把建议聚焦到**控制信号通路的 parity**(mux select/byte enable/shift amount 加锁存校验),而非数据线 ECC;
2. **spurious fault 遥测**(§5.1)的量化基础扩大:前兆-致命间隔下探至 0.72s(案 20)、单案前兆上探至 184 次(案 28)——per-CPU 计数 + 阈值自动 isolate 的响应窗口与触发阈值可据此标定;
3. **案 21 的 offline→re-online 复发**把"单核隔离"从建议升级为硬结论:核在线即风险,**必须永久下线 + RMA**,微架构级 workaround(l1d_disable 类)已被案 7 的 17 轮实验证伪;
4. **结构化形态指纹库**(§4.4)新增 5 个签名:双端 ff 抛掷(23)、相邻字节撕裂(24)、撕裂漂移(27)、高段注入(21/22/27)、跨 boot 签名复现(23↔26)——全部指向 mux/bypass 错位,可直接指导厂商失效分析(FA)的电路定位。
