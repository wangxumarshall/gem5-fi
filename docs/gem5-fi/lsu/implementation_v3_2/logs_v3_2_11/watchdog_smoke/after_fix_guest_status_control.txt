(unchanged from the Task-5 build; only configs/se/lsu_proxy.py changed, no rebuild).

Reviewed finding under test: the pre-fix lsu_proxy.py propagated ANY non-zero
exit-event code via sys.exit. But the SE guest exit syscall carries the guest's
own status through exitSimLoop("exiting with last active thread context",
status & 0xff) (CHAOS/gem5/src/sim/syscall_emul.cc:250, mapped to
ExitEvent.EXIT at gem5/src/python/gem5/simulate/exit_event.py:83). A workload
whose main() returns non-zero would therefore have exited gem5 non-zero, and
run_pilot.py's generic non-zero-returncode branch would misclassify a normal
completion as SIMULATOR_ERROR/CRASH/INCOMPLETE.

Scratch guest workload (built in /tmp, host gcc -O2 -static per repo recipe;
NOT added to the repo, no historical pilot touched):

  $ printf 'int main(void) { return 3; }\n' > /tmp/guest_exit3.c
  $ gcc -O2 -static -o /tmp/guest_exit3 /tmp/guest_exit3.c
  $ /tmp/guest_exit3; echo "native_exit=$?"
  native_exit=3
