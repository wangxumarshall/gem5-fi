# R6 逐实验观测链准入规范（用户 2026-10-23 指令，**权威**）

> 目标：**实验矩阵中每一个可执行实验都通过观测链准入（PILOT_READY）后，才允许启动正式实验。**
> 12 个 TLB 锚点（T01–T10 × W4 等）**只是首轮回归集，不是完成条件**。
> 执行时优先保证证据真实性与因果链完整性，**不以扩大运行数量代替修复**。

## 一、总体执行原则
1. 暂停正式实验，不得直接启动 325 项 formal campaign。
2. 先完成统一代码集成、测试修复和**唯一** `gem5.opt` 构建。
3. 冻结 `gem5.opt`，并记录**完整 SHA-256**。
4. 此后**逐个实验**进行小规模 pilot。
5. pilot 发现观测链/运行/分类/基础设施问题时，**立即停止该实验的扩大运行**，先定位并修复。
6. **所有**实验均通过 pilot 准入后，才允许启动正式实验。
7. **不得**将"未运行""未激活""事件流缺失"解释成 Masked、Contained 或没有传播。

## 二、完整观测链定义
对发生有效故障注入的样本，必须得到一条**连续、可验证、属于同一次故障和同一次请求**的因果链：

`L0 故障注入 → L1 单元内部首次受影响状态 → L2 单元输出或传播状态 → L3 跨单元请求/响应传播 → L4 架构状态/消费者/提交前状态 → L5 最终可观察结果`

每条链必须满足：
1. L0 注入事件含真实 `before/after`、`fault_id`、RunID、`sample_run_id`。
2. 每条传播边通过 `parent_event_id` 形成**连续 DAG**。
3. 不允许从多个无关请求、多个 fault 或多个样本拼接证据。
4. `request_id`、`fault_id`、`commit_seq` 等关联字段在适用位置必须一致。
5. L5 必须是**真实检测或真实结果事件**；不允许用 `chain_end` 等生命周期事件代替。
6. 事件流必须**完整、可读取、未截断**，且有正常收尾标记。
7. 不允许 `Unknown`、字段缺失、含义不明确，或仅靠推断补链。
8. 中间层被可靠阻断时可用**显式 containment** 作为完整终点，但必须记录：
   containment 发生层；阻断原因与直接证据；后续层为何是 `N/A(contained)`；不存在更深层传播事件。
9. `Masked` 不能仅由 RC=0 或输出碰巧一致推断；必须有完整 oracle 与 containment/无影响证据。
10. 无故障阴性对照不要求 L0–L5 故障链，但必须证明：注入数=0；事件流完整可读；workload 正常完成；oracle 通过；无任何故障事件或伪造 `chain_end`。

## 三、逐实验 pilot 流程
对矩阵中每个 RunID 依次：
1. 检查配置、路由、checkpoint、workload、oracle、事件钩子是否齐全。
2. 默认先跑 **3 个不同 seed** 的小规模 pilot。
3. 三个 pilot 必须正常结束，且**至少一个样本真实激活故障并形成完整观测链**。
4. **所有已激活样本**都必须通过严格链检查；任一出现以下情况即**不得准入**：
   无注入 / 无事件流 / 事件流截断 / L0–L5 缺层 / `parent_event_id` 断裂 / 跨 request 或跨 fault 拼接 /
   oracle 缺失 / `Unknown` / 错误分类 / 超时·崩溃·进程泄漏但未被正确记录。
5. 若 3 个 seed 均未激活：调整触发条件、warmup、span、概率或工作负载后重跑；**不得直接标记通过**。
6. 若存在偶发性或种子相关差异：扩大到 **5 个 seed**，直到问题可稳定复现和解释。
7. pilot 失败时：定位缺失的具体层或字段 → 修复对应 C++ 事件钩子 / Python 路由 / oracle / 检查器 / campaign →
   运行针对性测试 → **重新构建并记录新的 `gem5.opt` SHA-256** → 重跑受影响 RunID →
   对可能受全局修改影响的已通过 RunID 执行**回归**。
8. 只有满足全部准入条件的 RunID 才可标记 **PILOT_READY**。

## 四、状态管理（权威状态表，每行至少）
RunID · 实验族与故障模型 · 是否可执行 · pilot seed 数 · 激活样本数 · 完整事件流数 · L0–L5 覆盖 ·
containment 层与证据 · oracle 结果 · 运行结果 · 严格链检查结论 · 当前状态 · 失败原因 · 修复提交 ·
`gem5.opt` SHA-256 · checkpoint 身份 · 结果目录。

状态集合（**只能用这些**）：
`NOT_RUN` · `RUNNING` · `NO_ACTIVATION` · `INFRA_FAILED` · `CHAIN_INCOMPLETE` · `ORACLE_INCOMPLETE` ·
`BLOCKED` · `PILOT_READY` · `FORMAL_RUNNING` · `FORMAL_COMPLETE`

**不得**将 BLOCKED / NO_ACTIVATION / CHAIN_INCOMPLETE 或缺失证据的实验计入 PILOT_READY。

## 五、全局准入门禁（全部满足才可启动正式实验）
1. 所有可执行 RunID 均为 `PILOT_READY`。
2. `evidence_missing = 0`。
3. `truncated = 0`。
4. `Unknown = 0`。
5. 所有激活样本均存在完整 L0–L5 链，或严格证明的显式 containment。
6. 完整测试套件**无新增失败**。
7. 所有 pilot 使用**同一个冻结的 `gem5.opt` SHA-256**；中途修改二进制则完成必要的受影响回归。
8. 不存在孤儿进程、未回收的超时进程或长期卡住的后处理任务。
9. `write_chain_report` 能在大事件流上稳定完成并生成 `cell_results.json`。
10. 磁盘、内存、swap、checkpoint 均通过运行门禁。
11. 生成并保存**全局准入报告**，逐行证明每个 RunID 为何可以进入正式实验。

> 只要仍有一个可执行 RunID 未达 PILOT_READY，**不得**启动正式实验。

## 六、正式实验（仅在门禁全过后）
1. 冻结代码提交、`gem5.opt` SHA-256、checkpoint、矩阵与配置。
2. 生成正式实验清单与资源预算。
3. 资源纪律：**FS gem5 并发 ≤6**（按可用内存动态降到 4）；**SE gem5 并发 ≤20**；
   禁止按固定时间间隔不断启动任务；使用**有槽位限制的调度器**；每任务独立输出；
   超时后 **kill 并 reap 整个进程组**；定期检查内存、swap、磁盘与孤儿进程。
4. 正式实验中**每个样本**仍必须执行事件流完整性与观测链检查。
5. 若正式实验暴露新的链路或运行问题，**立即暂停受影响实验**，修复后重做必要的 pilot 准入与正式样本。

## 七、阶段汇报（持续更新并最终汇报）
1. 总 RunID 数量；2. PILOT_READY 数量；3. NOT_RUN / NO_ACTIVATION / INFRA_FAILED / CHAIN_INCOMPLETE /
ORACLE_INCOMPLETE / BLOCKED 数量；4. 每个失败 RunID 的具体缺口与修复状态；5. 当前唯一 `gem5.opt` SHA-256；
6. 全部 RunID 的权威准入表；7. 是否满足正式实验启动条件；8. 正式实验启动后的任务数、并发、资源占用与完成情况。

## 禁止事项（红线）
不得通过**放宽检查器**、**拼接无关事件**、**用 `chain_end` 冒充 L5**、**忽略截断流**、
或**把未激活样本计为成功**来满足门禁。
