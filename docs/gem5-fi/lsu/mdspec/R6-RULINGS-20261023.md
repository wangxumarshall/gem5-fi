## 裁决 A — 跨 request 语义：「全局传播链身份 + 局部请求身份」

**不得**简单放宽或删除 `cross_request_edge` 检查；**不得**为通过而把本属不同局部请求的 `request_id` 强行伪装成相同值。

1. `corr`/chain identity 表示**同一条端到端故障传播链**，跨 cache/LSQ/MSHR 层必须稳定。
2. `request_id` 保留其在组件/阶段内的**真实局部语义**。
3. 若硬件流程确实在层间产生新的 `request_id`，必须发出**明确、可审计的 request-handoff / bridge 事件**，记录：
   `old_request_id` · `new_request_id` · 稳定的 `corr`/chain identity · `parent`/`child` · 发生层级与原因。
4. checker **只允许两类边**：
   - `request_id` 一致的普通父子边；
   - 有**合法显式 handoff/bridge 证据**支持的跨 request 边。
5. **没有 bridge 证据**的原始跨 request 父边，**继续判定为 `cross_request_edge`**。
6. Lane A 必须说明实际采用哪种实现、为何符合真实微架构语义，并以测试证明：
   ① 合法同请求边**通过**；② 合法显式 handoff **通过**；③ 无 handoff 的跨请求边**仍被拒绝**。
7. **若当前事件模型无法可靠表达 handoff，本轮先采用严格的 request-scoped 父边，不得自行弱化门禁。**

## 裁决 B — 状态表改为「两轴表达」

不得用一个 `BLOCKED` 覆盖证据事实。

**A. `evidence_state`（磁盘实际观测进度，仅取五值）**：`NOT_RUN` · `EVIDENCE_MISSING` · `TRUNCATED` · `UNPROVEN` · `PILOT_READY`

**B. `eligibility`/`blocker_state`（是否被规格/基础设施/模式能力阻塞）**：`RUNNABLE` · `BLOCKED`，并列出 `blocker_code` 与 `blocker_detail`。

要求：
1. 有规格或基础设施 blocker 的 RunID，仍须在 `evidence_state` 中**如实显示** `NOT_RUN`/`TRUNCATED`/`UNPROVEN`，同时 `eligibility=BLOCKED`。
2. **不得**因 contract 中有 blocker 就把所有磁盘事实短路成 `BLOCKED`。
3. **`BLOCKED=0` 只能表示该统计维度中没有 blocker**，不得被解释为"全部实验已可运行或已通过"。
4. 权威汇总必须**同时**报告：各 `evidence_state` 数量 · `RUNNABLE`/`BLOCKED` 数量 · `PILOT_READY` 数量 · `blocker_code` 分类数量。
5. 正式实验准入依据**仍是 `PILOT_READY`**，不以 `BLOCKED=0` 代替。
