# 03 · 负载清单

> 来源：工作表「4.负载清单」R1–R12，内容忠实提取。
> 设计矩阵（`04-design-matrix.md`）的「适用负载」列只从本清单取值；
> 三个自设探针负载是事件触发行（事件覆盖计数）达成 2000 次事件覆盖的关键手段（见 `02-frequency-and-sampling.md`）。

## 负载表（原文）

| 负载 | 类型 | 简介 | 校验方式 | 主要覆盖单元 |
|---|---|---|---|---|
| CoreMark | 通用 | EEMBC 官方整数基准：链表、矩阵、状态机、CRC。 | 自带结果校验 | Int Decode / Int Rename / Int Dispatch-ROB |
| Embench | 通用 | 公开的 22 个小程序，整数、浮点、乘除、哈希都有。 | 每个自带结果校验 | 全部六个单元（整数/浮点子集分别用） |
| GAP | 通用 | 图计算基准（bfs、pr），邻接表下标取数，控制流不规则，边界/异常路径多。 | 有 OpenMP 多线程版可自行加校验 | Int Dispatch-ROB（配合 old-phys 字段的异常/中断触发场景） |
| PolyBench | 通用 | 稠密线性代数与网格计算（gemm、lu、cholesky、jacobi-2d）。 | 可输出整个结果数组逐个比对 | FP/SIMD Decode / FP/SIMD Rename / FP/SIMD Dispatch-ROB |
| libjpeg-turbo | 通用 | JPEG 压缩/解压，核心是手写 NEON 向量指令。 | 输出逐像素比对 | FP/SIMD Rename（向量寄存器堆压力） |
| 分支误预测密集核 | 自设 | 构造大量数据相关、不可预测的条件跳转（如对随机排列数组做条件分支遍历），刻意压高分支误预测率，制造 RAT/Rename 检查点被频繁触发恢复的场景。 | 结果数组自校验（排列的统计量） | Int Rename（配合 F4 事件触发：误预测恢复瞬间） |
| 长依赖链压力核 | 自设 | 构造大量真依赖链（每条指令都依赖前一条的结果，如链式累乘/累加），让编译器/硬件长期占用同一小撮物理寄存器，逼迫 Free List 长期处于低水位。 | 累计结果自校验 | Int Rename（配合 F4 事件触发：空闲表低水位）；FP/SIMD Rename（向量版本，用向量累加链） |
| ROB 填满核 | 自设 | 构造长延迟操作（连续除法/大跨度内存访问）与大量后续独立短指令交织，把 ROB 撑到接近满（指针追逐、长期高占用）。 | 结果自校验 | Int Dispatch-ROB / FP-SIMD Dispatch-ROB（配合 F4 事件触发：ROB 占用超过 80%） |

## 分配原则（原文）

每个「位置x模型」格配 2~3 个负载，不做负载x位置的全交叉；通用负载优先复用同一单元类别下已经在用的（整数三单元共用 CoreMark+Embench+GAP 里选 2 个，浮点/向量三单元共用 PolyBench+Embench(+libjpeg-turbo) 里选 2 个）；自设负载只配给设计初衷对应的位置，不用于其余位置（例如「ROB 填满核」不用来测 Decode）。负载不够用时再加，不预先铺开。

## 〔提取注〕负载在展开矩阵中的实际用量

由 `05-expanded-matrix.md` 的分布汇总给出（生成时统计）：CoreMark / Embench / PolyBench 占大头，
三个自设探针负载只出现在其设计初衷对应的事件触发行与资源压力行上，与上述分配原则一致。
