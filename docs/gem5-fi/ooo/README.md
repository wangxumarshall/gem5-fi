## 1. 北极星目标

在 gem5 ARMv8 O3CPU 上，对 **Int Decode / Int Rename / Int Dispatch-ROB / FP-SIMD Decode / FP-SIMD Rename / FP-SIMD Dispatch-ROB** 六个单元，
按「位置 × 频率 × 负载 × 故障模型」的完整网格（**91 个设计单元 → 226 个实验格 → 约 45.2 万次注入/运行**），
测出每个注入位置在 **L0~L4 五层观测**下的故障传播画像，
回答：**哪些位置有真实 SDC 潜力（而不是被 gem5 依赖检查拦成 Crash）、SDC 发生前微架构层有什么可观测前兆、结构化故障模型相对随机翻转的增量到底有多大。**

方案自认的空白填补价值（边界条件③）：Int Rename、Int Dispatch 的分发/发射逻辑本身、FP/SIMD Rename、FP/SIMD Dispatch 在已发表文献中**零覆盖**；本方案是目前已知第一份系统覆盖这六个单元的注入设计。

## 4. 五条设计边界（贯穿全篇，全文见 `00-overview.md`）

1. **依赖检查拦截**：gem5 O3 对 ROB/RAT 字段有依赖图检查，随机翻转几乎全变 Crash（TC'23：SDC=0%）→ 必须设计「换值」类结构化模型让翻转后的值仍合法。
2. **Veritas 论断待检验**：控制逻辑持久故障「非常不可能」SDC——无实验佐证，本方案译码/发射行就是检验。
3. **文献空白**：六单元中除 ROB 字段（TC'23）与 Int Decode 时延（DelayAVF，异核异模型）外全部无直接对照数据。
4. **频率-结局规律**（CHAOS）：注入概率越高越集中 Crash → 先试跑挑「非 Crash 占比」最高的频率区间再跑正式统计。
5. **参数非 920 真值**：ROB=128、IQ=64、PRF=128/192/48 等均为 A72 公开资料+gem5 示例估计值，论文必须注明来源。

## 5. 方法的核心主张（综合自源表设计理由，出处已注明）

1. **结构化模型是测出真实 SDC 的必要手段**——随机翻转被合法性检查拦截（边界①），「换值到另一个活跃物理寄存器」（D13/D31/D39）、「读到旧数据」（D16/D41/D55…）、「状态位撒谎」（D32/D48）都在刻意构造「合法但错误」的状态。其中「读到旧数据」是唯一**不需要专门构造目标值**就能绕过依赖检查的机制（旧值本来就合法，D41）。
2. **故障三根源体系**：值错误（翻转/换值）、存储位缺陷（卡死 F5）、写入时序（读到旧数据/丢失释放）——外加控制状态类（置位/重复分配/路由）。同一字段上翻转 vs 换值 vs 卡死 vs 旧数据的四联对照（如 RAT 映射字段 D11–D16）是方案的骨架。
3. **事件触发 vs 固定间隔是待验证的方法论主张本身**：D14/D18/D33/D36/D50 与各自固定间隔版严格配对，检验「精确瞄准窗口是否真的更高效」。
4. **L1 微架构层观测是区别于现有文献的重点**：多数论文只看 L2/L4；本方案要求影子 RAT/影子 Free List 分歧、停顿周期、IPC 偏差等 commit 前信号（`01-observation-points.md`）。
5. **Crash 必须双拆分**：仿真器断言崩溃（依赖检查触发）≠ 架构崩溃——这是判断「真实 SDC 潜力」的关键口径（L4 定义）。
6. **资源耗尽型故障的产出是前兆曲线**：丢失释放（D20）、done 位延迟置位（D35/D36）、ready 位永不置位（D49/D50）预期 Timeout 主导，价值在停顿/占用率趋势能否提前预警。

## 6. 实施顺序

**方案自带的验证锚点（做任何统计前先过这三关）：**

1. **注入器正确性自检**：D25/D28（ROB PC/寄存器标识符单比特）应复现 TC'23 的 SDC≈0%——不过关说明注入器实现有错。
2. **统一结构自检**：D83/D84/D85 用 FP 负载重跑 ROB 基线格与高 SDC 格，与整数负载结果高度一致才算「ROB 整数/FP 共用」假设成立。
3. **机制核实前置项**（源表明确标注「实验前必须先核实」）：
   - D23/D24 重命名检查点：先读 gem5 `src/cpu/o3/rename.cc` 确认是否用 checkpoint 机制，否则该两行位置定义要调整；
   - D62 系 标量 FP 与向量 NEON 是否两套独立寄存器类——若同套，标量/向量 RAT 行应合并不重复跑；
   - 事件覆盖计分行：先在无故障基线测事件密度（次/运行），倒推运行数（`02-frequency-and-sampling.md`）。

**提取者建议的推进序（非源表内容，供排期参考）**：自检三关 → Int Rename（RAT 换值 D13 是总表「标红但无实验数据」的直接回应）→ Int Dispatch/ROB（D32 done 位是预期最高 SDC 格）→ Int Decode → FP/SIMD 三单元（依赖标量/向量机制核实结论）。
