**范围：** DA04 实现 + FW02/SQ01 Trace 修复；不重新设计 LSU 整体实验方案，不改变 12 模型/60 样本/RunID/SubTaskID/SampleRunID/Seed。

## 1. DA04 唯一故障定义

4-bit Byte-enable Mask 的 **bit0 清零**：

```text
故障前 Byte-enable = 1111 = 0xF
故障后 Byte-enable = 1110 = 0xE
```

约束：

1. 只修改 4-bit mask 的 bit0；
2. 保持原始访存地址不变；
3. 保持原始访问 size 不变；
4. 不修改 Store 数据；
5. 不修改其他 Byte-enable 位；
6. 故障只作用于目标 Store 路径；
7. **Load 路径不得作为 DA04 的有效故障注入位置**。

## 2. 与 Excel v3.1 的显式偏离

Excel 第 5 sheet 中 DA04 的 `TargetInstruction` 为 `4B Load/Store`，`EligibleEventCondition` 为 `目标访存size=4且mask全1`。本轮任务书（研究者 2026-11-07 指令）将有效注入点收紧为 **Store-only**。本规格以任务书为准；Excel 的 RunID/SubTaskID/SampleRunID/Seed/EventOrdinal 不变。

## 5. PROPAGATION_VERIFIED 判定门槛

一个故障模型只有在**同一条链**（同一 ptag）同时具备下列真实事件时，才允许标记 `PROPAGATION_VERIFIED`：

1. `injection`：真实运行状态记录的 original/injected mask；
2. `store_writeback`：SQ Drain 时同一动态 Store 的写回（be_mask、data hash）；
3. `store_mem_write`：cache block 的实际字节更新（before/after；DA04 必须有 `disabled_unchanged=1`，且 `lane0_before==lane0_after`）；
4. `memory_response`：后续 Load 命中受影响字节；
5. `register_writeback`：Load 响应写入目的寄存器，且 `source_value_hash` 与 response 的 `data_fnv` 连续；
6. `consumer_commit`：通过 propagation edge 关联到该 taint 寄存器的消费者提交。

任一缺失 → 只能标记 `PILOT_RUN`，并记录链在哪一步停止。禁止用不同动态指令的节点拼接出 COMPLETE 链。
