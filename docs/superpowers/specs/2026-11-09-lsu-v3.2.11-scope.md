## 3. Task B — 11-model propagation audit (B1–B9)

**B1 — Audit all 11 implemented models from raw traces.** Independently
re-derive each model's chain from `trace_v31.jsonl` plus `pilot_meta.json` for
A01, A03, FW02, SQ01, DA04, LP01, MD04, FW05, SQ03, SP05, LQ04. Historical
verdicts are inputs to re-derive, never values to copy. (Plan Tasks 8–22, 28.)

**B2 — Streaming audit tool + archived-trace extraction.** `tools/lsu_propagation_audit.py`
reads `trace_v31.jsonl` line by line (never loading whole 196 MB SQ03 traces),
exposes `audit_pilot(pilot_dir, model, binary_sha=None)`, `audit_model(model,
pilot_dirs)`, `write_matrix(rows, out)`. Archived raw traces (SQ01 from the
v3.2.3 zip, FW05 from the v3.2.7 zip, SQ03 from the v3.2.8 zip, SP05 from the
v3.2.9 zip) are extracted only into `audit_v3_2_11/extracted_evidence/`, never
over `pilots_v3_2_*`, and every extracted trace is hash-verified against the
recorded checksums (mismatch ⇒ `missing=HASH_MISMATCH`). (Plan Tasks 8–9.)

**B3 — Time adjacency is not causality.** A chain edge exists only from an
explicit `ptag`, `dyn_inst_seq`, or data-hash link. Injection plus an unrelated
adjacent event with no link must grade `PARTIAL`/`UNRESOLVED`, never
`COMPLETE_CAUSAL_CHAIN`. (Plan Tasks 2, 8; Review Focus 2.)

**B4 — Historical artifacts untouched.** A report or matrix step that writes
into `pilots_v3_2_*` invalidates the evidence chain. Extraction steps verify
`sha256sum` before/after and the final check asserts `git status --short` has
no `pilots_v3_2_*` entry. (Plan Tasks 9, 21; Review Focus 1.)

**B5 — One audit report per model.** Eleven reports under
`audit_v3_2_11/<MODEL>_Propagation_Audit_v3.2.11.md`, one commit each, in the
order A01, A03, FW02, SQ01, DA04, LP01, MD04, FW05, SQ03, SP05, LQ04. Every
report uses the same template: identity/provenance table (per pilot:
SampleRunID, seed, ordinal, binary SHA, workload SHA, oracle); seven-stage
table (one row per pilot); quoted primary evidence (`file:line`, event id,
hashes); terminal causality (observed terminal vs fault causality, stated
separately); oracle comparison; missing-evidence list; `FinalClassification`;
supplementary-pilot recommendation with B8 justification fields (or `none`).
(Plan Tasks 10–20.)

**B6 — Seven-stage audit contract with explicit missing codes.** The seven
chain stages — `injection`, `activation`, `early anomaly`, `intermediate
propagation`, `register writeback`, `consumer`, `commit` — plus the two
adjudication fields `terminal` and `oracle`, each recorded as
`injection_verified`, `activation_verified`, `early_anomaly_verified`,
`intermediate_propagation_verified`, `register_writeback_verified`,
`consumer_verified`, `commit_verified`, `terminal_verified`, `oracle_verified`
with values `yes|no|n/a|missing`. `missing` is a list of explicit reason codes
(`NO_INJECTION_EVENT`, `NO_CONSUMER_EDGE`, `HASH_MISMATCH`, `TRACE_INCOMPLETE`,
`BINARY_SHA_MISMATCH`, `PILOT_DIR_ABSENT`, …). Never emit a blank or a bare
`PASS`; no `PASS`/`COMPLETE` without evidence. Expected paths are derived from
each model's frozen Excel sheet-4 definition, not copied from a list.
(Plan Task 8 + Tasks 10–20.)

**B7 — Unified audit matrix.** `audit_v3_2_11/LSU_11Model_Propagation_Audit_Matrix.csv`
with exactly the 20 enumerated columns: `ModelID, SubUnit, FaultDefinition,
PilotCount, InjectionVerified, ActivationVerified, EarlyAnomalyVerified,
IntermediatePropagationVerified, RegisterWritebackVerified, ConsumerVerified,
CommitVerified, TerminalVerified, OracleVerified, StructuralChainCompleteness,
FaultEffectPropagationCoverage, FaultCausality, FinalClassification,
MissingEvidence, SupplementaryPilotRequired, EvidencePaths`; 11 data rows; no
cell empty or a bare `PASS`; the LQ04 row is `LIFECYCLE_ONLY`/`0`; the
`PROPAGATION_VERIFIED` count is derived from verdicts, never copied. (SDD
ruling: the plan text's "19-column" is a typo; the enumerated 20 columns are
binding.) (Plan Task 21.)

**B8 — Supplementary-pilot plan, approval-gated.** For each model needing
supplementary evidence: the missing event/evidence, why the current trace
cannot supply it, the hook/workload change required, the minimal run count, the
preserved SampleRunID/Seed, and the non-overwrite rule. Every item is marked
`AWAITING_RESEARCHER_APPROVAL`; **nothing is executed**. If no gap needs a run,
state `none`. (Plan Task 22.)

**B9 — Binary purity.** The audit refuses to compare a pilot's recorded binary
SHA with a different audit binary (`BINARY_SHA_MISMATCH`). Models whose pilots
span several binaries get one row per binary split labelled `<MODEL>@<sha8>`
plus a model-level row stating `MIXED_BINARY_SPLIT` — never a merged verdict.
(Plan Tasks 8, 21; Review Focus 5.)

### 3.1 The four coverage classes (frozen definitions)

| Class | Definition |
|---|---|
| `COMPLETE_CAUSAL_CHAIN` | A value divergence (`data_corruption=1`, `consumer_input_matches_source=0`, or `consumer_input_fnv != source_value_hash`, or a model effect marker with a downstream linked event) **plus** a downstream commit/terminal explanation exists |
| `PARTIAL` | A divergence or effect marker exists but without the downstream link |
| `LIFECYCLE_ONLY` | The injection changed state but nothing diverged (LQ04's target class) |
| `UNRESOLVED` | No injection event, or the trace is incomplete |

## 6. Git discipline

1. One patch per unit: one commit per plan task; solve tasks sequentially, never
   batched.
2. Stage explicit paths only. **Never** `git add -A`, `git reset --hard`, or
   `git clean -fd`.
3. Push every verified commit; first push is `git push -u origin
   lsu-platform-v3.2.11`; never force-push; never push to `main`.
4. Self-verification before commit is mandatory and real: build clean (for the
   one C++ change), run the affected behavior with real commands, quote real
   output, run at least one unaffected regression test.
5. The main `fi-ding` worktree's pre-existing deletions/untracked files and the
   v3.2.10 worktree's `.tmp_lsu_conc/` are not this round's business and must
   not be touched.
