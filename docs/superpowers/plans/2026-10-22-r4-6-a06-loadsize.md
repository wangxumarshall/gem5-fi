## 目标

## 硬约束（源码实证，决定设计）

C1 `LSQ::pushRequest(size)` 的 size 同时决定：`LSQRequest::_size` → `Request::_size` →
`Packet::createRead(req())` 的 packet size（`lsq.cc:1362-1369`）与 `inst->memData`
的分配长度（`lsq_unit.cc:1915-1917`：`new uint8_t[request->mainReq()->getSize()]`）。
C2 ARM `LoadCompleteAcc`（`arch/arm/isa/templates/mem.isa:487-512`）无条件
`getMemLE(pkt, Mem, traceData)` —— 从 packet 拷 `sizeof(Mem)` 字节，宽度由**静态指令**固定，
与 request size 无关。
⇒ **C1∧C2：load 的 request size < 静态宽度 = 堆越界读**（`s11` 式 0 长度除外，
`lsq_unit.cc:1630` 的 MaxDataBytes 分支）。这就是 "load-side fixed-width completion contract"。
⇒ load 侧合法替换集合 = `{new_size > old_size} ∩ {1,2,4,8,16} ∩ {几何: (addr&63)+new_size <= 64}`。
C3 byte-enable：AArch64 全部访存路径传 `std::vector<bool>(size, true)`
（`mem.isa:424,477`、`neon64.isa:328,355,411,443`、`sve_mem.isa`、`sme.isa`，
`dyn_inst.cc:426/448 assert(byte_enable.size()==size)`）⇒ ISA 侧掩码域 = 单元素 {全 1}。
`LSQRequest::addReq`（`lsq.cc:1182-1217`）只把**尾部连续 0** 折算成 size 缩短
（`inactiveTailSize`）⇒ 尾部 0 掩码 ≡ size 收缩 ≡ C1/C2 禁区；
非尾部 0 掩码保留 size，且 `Request::isMasked()` → `Packet::isMaskedWrite()`
被 `mshr.cc:139`/`base.cc:1090`/`cache.cc:405` 真实消费（部分写）。

## 落地设计（A06-a）

`pre_mode = a06_size`（规格名，保持）扩为**按 op-class 的合法包络**：

- store：合法目标 `{1,2,4,8,16}` 全量替换（**行为不变**）。
- load：仅 **widen**（`--agu_size_to_load`，默认 0 = 无法注入，计数拒斥）；
  拒绝 shrink/相等/非法/跨 64B 线 —— 每类独立计数 + 独立 REJECT 理由（F6 armed 时刷日志）。
- 合格性判定放在 **trigger 决策之前**（F-049 纪律：模式写不进去的 op 不属于 eligible 流），
  保证 `f6_pending` 不被"注定拒斥"的 load 消费。

放大器路径（可观测、可追踪）：load 加宽 ⇒ `req_e = req_s + getSize()` 变大 ⇒
`LSQUnit::tryToForward`（`lsq_unit.cc:1657-1720`）的 `store_has_upper_limit` 不再成立
⇒ 全量转发分支不可达 ⇒ 部分覆盖进入 "Load-store forwarding mis-match" 分支
（`rescheduleMemInst` + `discard` + `return NoFault`，`lsq_unit.cc:1880-1905`）
⇒ 该 load 被 **replay**。规格 A06 的 W5 负载原文即点名 "转发探针 … replay"。

**诚实分级**：widen 的架构后果是 (1) 转发降级/replay、(2) 访存几何改变
（single↔split、MSHR/需求行集合），**不是** value-level SDC —— 完成宽度只取
`sizeof(Mem)` 低字节，且 gem5 对部分覆盖走 replay 而非陈旧合并，最终寄存器值通常
仍等于内存正确值。是否被 L5 记 SDC 由 pilot 实测决定（报告 §4 判据 5 要求如实标注
每次 run 的激活形态）。

## 落地设计（A06-b）

`--agu_be_mode {off|observe|shift_mid}`：

- `observe`（默认）：对**被注入的**请求记录掩码普查（`be_len/be_ones/be_all_true`），
  写注入日志 + 新增 stdout 汇总行 —— 这是"A06-b 载体可达性"的经验证据面。
- `shift_mid`：把掩码替换为"另一合法掩码" = 全 1 且**中间位置清 0**
  （index = size/2，要求 size>=2 且 index<size-1 ⇒ `inactiveTailSize==0` ⇒ size 不变 ⇒
  不触 C2）。仅对 **store** 注入（`isMaskedWrite()` 有真实架构效果）；
  load 侧拒斥（load 的掩码在本路径无架构消费者，只喂 `addReq` 的尾部裁剪）。
