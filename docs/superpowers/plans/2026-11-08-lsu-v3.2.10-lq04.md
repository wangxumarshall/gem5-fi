# LSU v3.2.10 — LQ04 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the literal LQ04 `_valid`/`_request` lifetime corruption in the vendored gem5 LSQ, run the five frozen LQ04 pilots plus five no-fault controls on a new explicit-anchor workload, and publish the v3.2.5 Excel, model matrix and evidence package.

**Architecture:** A new `CHAOSLQ04` SimObject counts eligible Loads at the end of `LSQUnit::executeLoad`, fires once on the configured ordinal, and asks the owning `LQEntry` to move its request into an opaque side channel while setting `_valid=false` and `_request=nullptr`. The request is restored and freed at the entry's real commit/squash boundary, so the core queue invariants and request ownership remain intact. The response still binds through `pkt->senderState`; the trace records that binding and the invalid-entry interval instead of fabricating response loss.

**Tech Stack:** C++17 (gem5 v25.1.0.1 vendored tree, SCons), Python 3 (gem5 stdlib config, pilot platform), pytest, openpyxl, AArch64 host `gcc -O2 -static`.

**Spec:** `docs/superpowers/specs/2026-11-08-lsu-v3.2.10-lq04-design.md`

## Review Focus

1. **Repeated `executeLoad` for one dynamic Load (replay/fault retry).** A second call must never count as a new target or fire twice; identity is `(seqNum, lqIdx, lqEntryGeneration)`.
2. **Split/atomic/store-conditional accesses reaching the hook.** `mainReq()` asserts when `_reqs.size()!=1`; use `req(0)` for the request identity and skip non-Loads.
3. **Entry reuse before commit/squash.** The restore must apply only to the stored `(idx, generation)`; a different generation may not inherit the side channel.
4. **Simulation ending before commit/squash (watchdog/timeout/abort).** The side channel must free its request in the `LQEntry` destructor; no leak and no double free.
5. **Squash while the response is still in flight.** `clear()` calls `freeLSQEntry()`; the later response must be ignored through `isReleased()` and the request must self-delete without touching a freed entry.

- [x] **Step 1: Write the assembly entry**

```asm
// _start: no data load may precede the five anchors.
    .section .text
    .global _start
_start:
    adrp x1, anchor_tbl
    add  x1, x1, :lo12:anchor_tbl
    ldr  x2, [x1, #0]
    ldr  x3, [x1, #8]
    ldr  x4, [x1, #16]
    ldr  x5, [x1, #24]
    ldr  x6, [x1, #32]
    mov  x0, x2           // a -> x0
    mov  x1, x3           // b -> x1
    mov  x2, x4           // c -> x2 (x2 already consumed)
    mov  x3, x5           // d -> x3 (x3 already consumed)
    mov  x4, x6           // e -> x4
    bl   main
    mov  x0, #0           // exit status 0
    mov  x8, #93          // exit
    svc  #0
    .section .data
    .align 3
    .global anchor_tbl
anchor_tbl:
    .quad 0x0102030405060708
    .quad 0x1112131415161718
    .quad 0x2122232425262728
    .quad 0x3132333435363738
    .quad 0x4142434445464748
    .quad 0x5152535455565758
```

- [x] **Step 2: Write `main`**

Signature `uint64_t main(uint64_t a, uint64_t b, uint64_t c, uint64_t d, uint64_t e)`.
Five distinct consumers: `s = a*3 + (b^0x9e37) + (c<<7) + (d>>5) + (e & 0xffff)`;
then the original 64-iteration loop over a 4096-byte `static uint8_t a[4096]`
(`a[i]=i*7+3`, `idx=(r*97+13)&4095`, `s += a[idx]*3 + a[(idx+64)&4095]`,
`if((r&7)==0) s^=0x9e3779b97f4a7c15`), a 64-byte `0xA5` guard check, and a raw
`write(1, buf, len)` of `checksum=0x%016llx\n` followed by `return s ^ fnv1a(a,4096)`.
No libc calls.
