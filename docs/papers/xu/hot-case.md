# 一个"浮点 SDC"的真面目：CPU179 案例的完整取证与根因重定位

> 案例平台：Yangtze Computing R240K V2 / Kunpeng-920（TaiShan-v110，192 核，8 NUMA 节点）/ openEuler 24.03，内核 6.6.0-145.3.23.154
> 观测窗口：2026-08-13 至 2026-09-04，22 天，12+5 次开机崩溃（后扩展至 17 案口径）
> 证据基础：17 份 vmcore 取证报告、两次独立重研究的交叉综合（12 案 subagent 独立取证 + 十二开机全谱普查）、三份硬件复现方法文档、以及 gem5-fi 平台 19 注入器的 formal 实验数据
> 用途：学术论文案例素材。全部数字可溯源至仓库内报告原文；引用路径逐条标注。

## 1. 案例概述

一台生产环境 192 核 ARM64 服务器在 22 天内反复崩溃。取证经历了三个阶段，每一阶段都修正了前一阶段的归因：

1. **崩溃普查**：12+5 次开机全部以致命 panic 收场，崩溃执行核 16 次为 CPU179（1 次相邻核级联），累计 160 余次内核异常事件 100% 归属同一颗 CPU179，其余 191 核零事件。RAS 体系（GHES/ghes_edac/BERT/SEL）全程静默。
2. **主动复现**：三种独立方法在同一硬件上复现 SDC：OpenDCDiag 负载循环下的 Eigen 稀疏 Cholesky 失败（看似浮点问题）、欠压加 STL 压测的调度器崩溃、六类负载的跨通路触发实验。
3. **根因综合**：三种复现形态与 17 次崩溃的坏值形态学收敛到同一结论：故障不在任何功能单元内部，而在所有功能单元共用的数据搬运与选路基础设施上。

本案例的学术价值在于一个完整的归因纠偏过程：**"浮点运算单元 SDC"这个初始标签如何被证据链逐步证伪，根因如何被重新定位到处理器微架构的数据通路层**。这个过程对现有 SDC 文献的方法论（指令级功能测试偏向算术单元归因）构成直接的反例与补充。

## 2. 时间线与原始现象

### 2.1 自然崩溃史（17 案口径）

按十二开机普查（后扩展）与 paper2026_zh 综合报告：

- 12 次开机存活时长全谱（小时）：149.30 / 110.03 / 89.51 / 66.54 / 31.67 / 21.34 / 18.52 / 14.52 / 1.41 / 1.10 / 0.404 / 0.116。最长最短相差 1285 倍，无单调恶化趋势（早期"渐进恶化"的判断在扩样后如实修正为"间歇性"）。
- 致命点 11/12 案为同一条指令 `find_busiest_group+0x140`（CFS 调度器负载均衡的 per-CPU 遍历体，`ldr x23,[x27,#0x120]` 读 `rq->cfs.load_avg`）。唯一异例（08-24）崩在 `bio_add_page+0xf0`，但坏值同样来自一条索引型装载指令的返回值，同病不同路径。
- 前兆信号：约 135 次 `Ignoring spurious kernel translation fault` WARNING，全部 CPU179。内核对页表完全有效的地址（AT S1E1R 重放即成功）报了假翻译故障。末次前兆距致命崩溃的间隔谱从 3.1 秒到 10.67 小时，跨四个数量级；唯一可靠的预测量是"是否出现过任意一次该核 spurious fault"这个二值事件（11/12 开机有前兆）。
- 受害进程横跨六种身份（kworker/swapper/rcu_sched/mi-scavenger/sftp-server/systemd-coredump），排除软件路径特异性。

### 2.2 三种硬件复现方法

**方法一（OpenDCDiag 负载循环，"浮点 SDC"表象的来源）**。无限循环全量测试约 17 分钟后出现 2/2178 次失败，集中在 eigen_sparse（double 精度稀疏 Cholesky）与 eigen_gemm_float，全部来自 CPU 179。六层分层假设排除法完成定位：

- 固定失败 seed 在核 179 上 9000+ 次单跑全过（B1 实验 91/0），排除 Eigen 5.0 确定性软件 bug；
- 全核相同输入相同数据，仅核 179 失败（G5：285/285 失败全 179；G6 换 seed：140/140），彻底排除 seed/数据/数值边界；
- 测试类型矩阵：密集 GEMM float/double、SVD、纯 FMA、整数/CRC 全部 0 失败，唯一触发的是稀疏 Cholesky 的 numeric factorize 阶段；
- 字节级定位：损坏固定在求解结果向量 x[0]（固定栈地址），多位 21-32 bit 数据混叠，非单 bit；
- MRU 削减：dense/SpMV/gather/纯 FMA 单一操作全 0 失败；最小复现用例锁定为 factorize 列更新循环的特定指令交错（cdiv 条件分支 + rank-1 update 标量 FMA + 间接地址生成 + 长存活 d4 累加器）；
- 状态泄漏签名：numeric-only 失败率约 4 倍于 compute-both（15/1500 vs 4/1500）。symbolic 阶段重做会刷新某个持续占用的微架构状态，指向乱序引擎的跨迭代状态泄漏。

**方法二（欠压 + STL 压测）**。通过 BMC 对四路 CPU 的 VDDAVS 拉偏 30mV（0.88V→0.85V），CPU2 VDDAVS 实测下探 0.810V 触及欠压阈值，运行 `kunpeng-stl-kp920 -L 9999 -r all` 压测：三次崩溃同调用栈（`find_busiest_group+0x1b8`），故障寄存器 x10 每次为不同的非法地址（`0x0ffe809021e0b2ae`、`0xa23fa5817371856b`…），ESR 恒为 0x96000004（DABT L0 翻译故障）。同一指令不同坏值是硬件 SDC 的典型特征；软件 bug 在固定输入下产生固定错误。

**方法三（跨通路触发实验，v3 报告）**。8×15 分钟受控 campaign 加历史日志：六类互不相关的工作负载（movbe 字节交换、mrn_rmw 整数读改写、eigen GEMM float/double、SVD）全部在 CPU179 触发同一缺陷（6/8 触发，全部同核）。触发条件被探针锁定为四个必要条件：store 必须存在（probe A）、store 地址必须推进（D）、必须同 LLC 域（E）、必须跨 cache line 推进（F）。对照实验里最有判别力的一条：在热路径插入一条语义 no-op 的 ALU 指令（probe H），触发率从近 100% 塌缩到约 10%；而 store↔reload 的背靠背相邻性被打破（probe X）却不消除触发。判别变量是指令调度的时序相位，与任何指令的语义无关。

## 3. 坏值形态学：四族形态的解剖结构

17 次崩溃中可对照的坏值（x20 实收 vs `__per_cpu_offset[]` 内存真值，crash 直读）分为四族：

| 族 | 案数 | 形态 | 判定 |
|---|---|---|---|
| 零塌缩 | 6（5 实锤+1 强推） | 非零内核指针装载为全零（真值如 `0xffffa89017090000`，实收 `0x0`） | 数据拍未送达：返回总线该拍未驱动（浮空读零）或填充缓冲以零值顶替 |
| 撕裂移位 | 7（6 实锤+1 强推） | 实收值 = 被读数组错相位 N 字节处的**真实字节流**（+1/+2/+5 字节相位均被 crash 直读唯一命中验证） | 字节选路网络（对齐 mux/字节使能/合并缓冲指针）错拍；SRAM 阵列失效给不出"别处的正确内容" |
| 宽带位翻转 | 2 | 汉明距离 31-35，均匀散布 64 位，无字节/列结构 | 读出模拟前端（sense-amp/位线）边际压差窗口内多位同时误读 |
| 同类指针替换 | 1（多核级联） | 链表头被写成合法 vmemmap 指针（XOR 27 位整字替换）+ 写路径持久化 + 相邻双 load 同址不同值 | store 数据选择误路由（写侧交付错误且持久化） |

方法三的位谱统计（36 样本/562 翻转位）补充了浮点载体的形态学：符号位 562 位中仅 0-1 次翻转（近乎免疫），尾数集中（float 85%、double 93%），翻转位数路径相依（SVD 中位 3、GEMM double 中位 28）。

四族共享五条不变量：内存真值完好 / 地址计算正确 / 算术自洽 / 唯搬运交付出错 / 归属 CPU179。这个解剖结构把故障从"随机位翻转"重新定义为"数据搬运通路的结构化选路错误"。

## 4. 推理链：为什么"浮点单元"被证伪

### 4.1 单根因统计论证强制三种 SDC 同源

三种复现方法全部锁定同一物理核（方法一 G5/G6 全核同输入仅 179 失败；方法二三崩同核；方法三六负载 6/8 同核）。k 个独立根因全部落在 192 分之一单一核上的先验代价是 (1/192)^(k-1)；样本是数百次事件无一例外（普查口径 147 起可归因事件 100% 单核，均匀随机假设下概率约 192^-147）。

由此得出不可回避的推论：方法一的"浮点 SDC"与两个 load-store SDC 必然共享同一物理缺陷。既然方法二/三的形态明确位于数据搬运通路，"浮点 SDC"这个标签就只能是观测载体的伪标签。

### 4.2 浮点单元无辜的直接证据

方法一自己的探针矩阵就排除了浮点 pipe：密集 GEMM float/double 0 失败、SVD 0 失败、纯 FMA 探针 0 失败。若是浮点运算部件损坏，所有浮点测试都该失败，而实际唯一触发的是 Cholesky numeric factorize 的特定指令交错。"浮点 SDC"的表象来自 Eigen 测试是当时唯一在跑的浮点密集负载，故障位置与浮点部件无关。

方法三的位谱进一步排除算术语义错误：符号位免疫 + 尾数集中 + 位数路径相依，ALU 语义错误给不出这个分布。跨通路确证补上最后一环：整数 movbe、整数 mrn_rmw 与 float/double GEMM 同核同条件触发，且 GEMM 的翻转位点在结果写回/复制的 store→reload 往返，不在 FMA 本身。v3 报告的原话：指令是激励载体，不是原因。

### 4.3 候选逻辑单元的逐一鉴别

单根因确定后，候选单元收敛到所有功能单元共用的数据搬运与选路基础设施。逐个评估：

STLF（存储转发数据通路），首要嫌疑，置信度最高。方法三的四个必要条件全是 store→load 性质（store 存在、地址推进、跨行、同 LLC 域），翻转位点全部是 reload 指令；GEMM 触发率低于 movbe 恰因其 store→load 往返只在写回/复制段出现；一条 no-op ALU 指令使触发率从 100% 塌到 10% 证明是时序相位竞争。gem5 formal 侧证：LSQ 转发的 bitflip/撕裂/相位三种模式 SDC 全部 100%（n=64/cell），相位偏移 offset∈{1,2,4,8} × n=384 全部 384/384 SDC。相位错开一步即必错，与现场"一条 no-op 塌方"的敏感性定量同构。

旁路交叉矩阵/写端口，方法一混叠形态的机理载体。gem5 侧的关键技术发现：背靠背 FMA 依赖链（fmadd d0 → fmadd d0）的中间值在旁路网络中流动、从不回读物理寄存器堆。对 PRF 单元的注入被操作数转发完全击败（15 个种子全部掩蔽），唯一有效的注入点是源操作数读取路径。这证明 FMA 链的暴露点恰在转发网络，而方法一的"其他计算数据混叠写入 x[0]"与旁路/写端口误路由的净效果完全一致。

寄存器重命名表（合法域替换），对方法一的混叠成立，与撕裂形态可区分。支持证据：方法一的状态泄漏签名（numeric-only 失败率 ≈4× compute-both）指向跨迭代微架构状态泄漏；长存活 d4 累加器正是 F5 偷映射的目标类。gem5 侧证：m1-formal 用 CHAOSRenameMap f5_substitute 打在汇编固定的长存活累加器 x9 上，精确复现了这个压制签名（numeric 臂 77% vs compute-both 臂 0%，Fisher 精确检验 p=1.19e-71）。限定：现场撕裂移位的形态（实收值 = 别处真实内存字节流）是装载通路签名；重命名替换应交付另一个活寄存器的值而非内存字节。所以此候选解释方法一，不解释方法二/三。

PRF 单元（cell 级），不太可能。现场 XOR 每次不同（无驻留位）、无重复值模式；撕裂移位需要"别的地址的真实字节流"，寄存器堆 cell 给不出这个。写端口 mux 的可能性并入旁路矩阵候选。反向证据：17 轮 L1D 整体禁用实验期间故障仍复发（08-31 案），排除阵列级驻留损伤，支持通路级（时序/选通）缺陷。

乱序控制/指针管理，驻留损坏 unlikely，瞬态误相位成立。现场案 14（合法 vmemmap 指针整字替换 + 相邻双 load 同址不同值）证明选择逻辑的瞬态误选可以交付"合法但错误"的值。但 gem5 formal 显示控制状态的驻留性损坏倾向响亮崩溃：IQ 75.3% DUE/0% SDC、freelist 72-77% DUE/0% SDC、RAT F5 59.7% DUE/0% SDC。控制结构免疫 SDC（提交前依赖检查必崩），与 TC'23 文献结论一致。

已被 17 案排除矩阵明确排除的：内核软件 bug（代数闭合+反事实+11 案同指令软件自洽）、DIMM/DDR（EDAC 零记录+数组恒完好+损坏随核不随地址）、L3/互连（同节点 23 个同胞核零事件）、页表硬件（spurious 重走成功）、KASLR/地址错位（多路符号咬合×7 案）、槽位特异性（10/11 案迭代号 i≠179，腐化绑定执行核而非被读槽位）、l1d_disable 缓解（三试验后 55h 复发实证无效）。

### 4.4 统一图景

同一边际时序毛刺落在数据交付段的不同逻辑上，形态就不同：字节选路 mux 错拍给撕裂移位；数据使能/总线未驱动给零塌缩；sense-amp 采样窗给宽带翻转；store 数据选择给同类指针替换；旁路/写端口误路由给寄存器混叠（方法一）；PTW 读出受扰给假翻译故障（前兆）。术语上需要一次精确化：这些单元不是流水线意义上的"前置"，而是所有功能单元结果必经的公共数据搬运与选路段。故障不在功能单元内部，而在功能单元之间的基础设施上。

物理机理层的诚实边界：单点缺陷（某通孔退化，后果扇出）与单一边际区域（局部电源域老化，多条临界路径间歇违例）在软件侧不可区分，倾向后者（与间歇无趋势、簇发节律吻合更好），但这是倾向不是证明。裁决需要供应商 ATE/shmoo。

## 5. 待验证的鉴别实验

假说内部剩余的可判别分支：方法一的混叠具体是重命名替换（交付另一个活寄存器的值）还是旁路/写端口误路由（交付另一条在途结果）。

实验一：坏值溯源（现场数据即可做）。dump 被污染的 x[0] 值，在程序全部活变量当前值中搜索精确匹配。命中某个活变量的当前值是重命名/转发混叠签名；在被读内存字节流中错相位命中是装载通路签名（撕裂移位变体）。方法一的 dump 探针框架（movbe_dump 模式：热循环字节不动、诊断进冷分支）已验证不扰动触发，可直接扩展。

实验二：注入器签名匹配 campaign（gem5 平台已就绪）。把 Cholesky MRU（mru_eigenmc，libc-only）作为 workload 分别置于各候选注入器下（CHAOSLSQFwd 的 byte_lane_skew/phase_offset、CHAOSRenameMap 的 f5_substitute、CHAOSFPU 的源读 hook），按三个签名维度打分：损坏落点（固定 elem[0] 与否）、混叠 vs 位翻转、numeric/both 失败率比。锚点全部就位：rol1 复现撕裂签名 93% 检出（30 注入 28 检出）、相位敏感性 100% vs 10-20%、m1 的 4× Fisher 复现。

实验三：物理裁决（超出软件可见范围）。厂商对 MPIDR 0x7a03xx 物理核执行 MBIST/LBIST 与电压-频率 shmoo（-30mV 起点），重点复测 RF 端口、bypass 网络、L1D 输出锁存，针对 fill-buffer 合并窗口的 1-7 字节全相位错配设计定向向量。这是 vmcore 方法论与功能仿真都到不了的层面，全部 17 份报告对此表述一致。

系统侧验证（低成本高价值）：offline CPU179 后前兆 spurious fault 应归零（预期归零即坐实核级归属）；裸机 load-verify 双核校验；per-CPU spurious fault 计数器纳入标准遥测并在超阈值时自动隔离。

## 6. 设计与检测启示

检测方面，`Ignoring spurious kernel translation fault` 按核统计是本谱系唯一免费的前兆遥测，当前被 WARN_RATELIMIT 静默吞掉。本案例等效于手工执行了 Hardware Sentinel 的启发式（单核异常集中+内核异常+SEL 静默）且判别力更强。调度器热路径的指针装载可加低成本不变量校验（高位 16 位必须全 1、对齐检查），把 SDC 从静默错误决策变成可定位的 panic。

微架构方面，L1D ECC 拦驻留翻转，拦不住"行内容正确但回读错"。load 返回总线（fill-buffer→寄存器堆写端口）加端到端奇偶，错则重放，面积小，正中盲区。store 通路对称处理（案 14 证明写侧同样交付错误且持久化）。PTW 读出 PTE 加奇偶：最坏情形（PTE 读错且值合法，导致静默错误映射）是 SDC 完全体。

制造测试方面，撕裂移位在传统 March 算法下不可见（阵列没坏，选路错拍）。需要已知模式填充连续行+非对齐装载序列回读比对的定向向量，覆盖全部字节相位组合。结构化腐化形态（ror16+标签、+N 字节窗口）应纳入 DFT 图谱，它们指向 mux/bypass 错位而非 SRAM 坏位，直接指导失效分析方向。

方法论对文献的修正：现有 SDC 归因建立在指令级功能测试上，这个范式天然偏向"输出即结果"的算术单元。本案例中"浮点 SDC"的初始标签正是这个偏差的产物：Eigen 测试是当时唯一在跑的浮点负载，故障却全然不在浮点部件。Harpocrates 实测现有工具对 LSQ 的 SDC 检测率仅 0-20%，是所有结构中最低的；本案例以三级代数闭合+真值对照证明了这块盲区可观测，所需的全部工具是 kdump 与 crash。

## 7. 结论

一台生产 ARM64 服务器，22 天，17 次崩溃，一颗核。三种独立复现方法中标签为"浮点 SDC"的那一种，其浮点归因被三层证据链证伪：单根因统计论证强制三种 SDC 同源；方法一自身的探针矩阵排除浮点 pipe（密集 GEMM/SVD/纯 FMA 全 0 失败）；方法三的位谱与跨通路确证把翻转位点钉在装载/写回往返。

根因重定位到所有功能单元共用的数据搬运与选路基础设施。候选单元按证据强度排序：STLF（首要，四必要条件+相位敏感+gem5 三模式 100%）、旁路交叉矩阵/写端口（方法一混叠的机理载体，gem5 旁路击败 PRF 注入的发现）、寄存器重命名表合法域替换（解释方法一的 4× 状态泄漏签名，与撕裂形态可区分）；PRF cell 级与控制结构驻留损坏被形态学与 formal 数据双重排除。四族坏值形态是同一边际时序条件在不同逻辑落点上的失败模式谱，共享"内存正确、地址正确、运算正确、搬运出错"的解剖结构。

对研究的普适意义：SDC 的微架构分布归因必须穿过观测载体的表象。浮点负载上的 SDC 不等于浮点单元的 SDC。当故障在公共数据通路上时，任何功能单元都会成为它的放大器与替罪羊。指令级功能测试需要一个"真值 vs 实收"的对照面才能看见数据搬运通路，这是本案例给 SDC 观测方法论的最直接补丁。
