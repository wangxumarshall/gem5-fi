# 一个"浮点 SDC"的真面目：CPU179 案例的完整取证与根因重定位


一台生产环境 192 核 ARM64 服务器在 22 天内持续崩溃。四种独立方法在同一硬件上复现了 SDC：OpenDCDiag 负载循环下的 Eigen 稀疏 Cholesky 失败（表象看似浮点问题）、欠压加 simd memcpy 压测触发 OS panic、高并发 memcpy 检测用例的黄金值比对、stress-ng cpu 压测加 opendcdiag 触发 OS panic。四种方法均可稳定复现 CORE179 的 SDC 故障，其余核零故障，RAS 体系（GHES/ghes_edac/BERT/SEL）全程静默。调查共收集 12 次 panic 的 vmcore 数据。
- 12 次开机存活时长全谱（小时）：149.30 / 110.03 / 89.51 / 66.54 / 31.67 / 21.34 / 18.52 / 14.52 / 1.41 / 1.10 / 0.404 / 0.116。最长最短相差 1285 倍，无单调恶化趋势。早期"渐进恶化"的判断在扩样后如实修正为"间歇性"。
- 致命点 11/12 案为同一条指令 `find_busiest_group+0x140`（CFS 调度器负载均衡的 per-CPU 遍历体，`ldr x23,[x27,#0x120]` 读 `rq->cfs.load_avg`）。唯一异例（08-24）崩在 `bio_add_page+0xf0`，但坏值同样来自一条索引型装载指令的返回值，同病不同路径。
- 受害进程横跨六种身份（kworker/swapper/rcu_sched/mi-scavenger/sftp-server/systemd-coredump），排除软件路径特异性。

对这批数据的深入研究表明，最初"浮点运算单元 SDC"的猜测被证据链逐步证伪，根因应重新定位到处理器微架构的数据通路层。现有 SDC 文献的归因方法（指令级功能测试，偏向后端运算单元）在这个案例上给出了错误答案，本案因此既是反例也是补充。



**方法一（OpenDCDiag 负载循环，"浮点 SDC"表象的来源）**。无限循环全量测试约 17 分钟后出现 2/2178 次失败，集中在 eigen_sparse（double 精度稀疏 Cholesky）与 eigen_gemm_float，全部来自 CPU 179。六层分层假设排除法完成定位：

- 固定失败 seed 在核 179 上 9000+ 次单跑全过（B1 实验 91/0），排除 Eigen 5.0 确定性软件 bug；
- 全核相同输入相同数据，仅核 179 失败（G5：285/285 失败全 179；G6 换 seed：140/140），彻底排除 seed/数据/数值边界；
- 测试类型矩阵：密集 GEMM float/double、SVD、纯 FMA、整数/CRC 全部 0 失败，唯一触发的是稀疏 Cholesky 的 numeric factorize 阶段；
- 字节级定位：损坏固定在求解结果向量 x[0]（固定栈地址），多位 21-32 bit 数据混叠，非单 bit；
- MRU 削减：dense/SpMV/gather/纯 FMA 单一操作全 0 失败；最小复现用例锁定为 factorize 列更新循环的特定指令交错（cdiv 条件分支 + rank-1 update 标量 FMA + 间接地址生成 + 长存活 d4 累加器）；
- 状态泄漏签名：numeric-only 失败率约 4 倍于 compute-both（15/1500 vs 4/1500）。symbolic 阶段重做会刷新某个持续占用的微架构状态，指向乱序引擎的跨迭代状态泄漏。

**方法二（欠压 + simd memcpy 压测）**。通过 BMC 对四路 CPU 的 VDDAVS 拉偏 30mV（0.88V→0.85V），CPU2 VDDAVS 实测下探 0.810V 触及欠压阈值，运行 `memcpy` 压测：三次崩溃同调用栈（`find_busiest_group+0x1b8`），故障寄存器 x10 每次为不同的非法地址（`0x0ffe809021e0b2ae`、`0xa23fa5817371856b`…），ESR 恒为 0x96000004（DABT L0 翻译故障）。同一指令不同坏值是硬件 SDC 的典型特征；软件 bug 在固定输入下产生固定错误。


17 次崩溃中可对照的坏值（x20 实收 vs `__per_cpu_offset[]` 内存真值，crash 直读）分为四族。本节列出与本案归因直接相关的两族：

- 零塌缩（6 案，5 实锤+1 强推）：非零内核指针装载为全零（真值如 `0xffffa89017090000`，实收 `0x0`）。数据拍未送达：返回总线该拍未驱动（浮空读零），或填充缓冲以零值顶替。
- 撕裂移位（7 案，6 实锤+1 强推）：实收值 = 被读数组错相位 N 字节处的真实字节流，+1/+2/+5 字节相位均被 crash 直读唯一命中验证。字节选路网络（对齐 mux/字节使能/合并缓冲指针）错拍；SRAM 阵列失效给不出"别处的正确内容"。




各复现方法全部锁定同一物理核（方法一 G5/G6 全核同输入仅 179 失败；方法二三崩同核；方法三六负载 6/8 同核）。k 个独立根因全部落在 192 分之一单一核上的先验代价是 (1/192)^(k-1)；样本是数百次事件无一例外（普查口径 147 起可归因事件 100% 单核，均匀随机假设下概率约 192^-147）。

由此得出不可回避的推论：方法一的"浮点 SDC"与其余 load-store 类 SDC 必然共享同一物理缺陷。既然方法二/三的形态明确位于数据搬运通路，"浮点 SDC"这个标签就只能是观测载体的伪标签。

方法一自己的探针矩阵就排除了浮点 pipe：密集 GEMM float/double 0 失败、SVD 0 失败、纯 FMA 探针 0 失败。若是浮点运算部件损坏，所有浮点测试都该失败，而实际唯一触发的是 Cholesky numeric factorize 的特定指令交错。"浮点 SDC"的表象来自 Eigen 测试是当时唯一在跑的浮点密集负载，故障位置与浮点部件无关。

方法三的位谱进一步排除算术语义错误：符号位免疫 + 尾数集中 + 位数路径相依，ALU 语义错误给不出这个分布。跨通路确证再加一条：memcpy 与 float/double GEMM 同核同条件触发，且 GEMM 的翻转位点在结果写回/复制的 store→reload 往返，不在 FMA 本身。v3 报告的结论在此适用：指令是激励载体，不是原因。


单根因确定后，候选单元收敛到所有功能单元共用的数据搬运与选路基础设施。逐个评估：

STLF（存储转发数据通路），首要嫌疑。方法三的四个必要条件全是 store→load 性质（store 存在、地址推进、跨行、同 LLC 域），翻转位点全部是 reload 指令；GEMM 触发率低于 movbe 恰因其 store→load 往返只在写回/复制段出现；一条 no-op ALU 指令使触发率从 100% 塌到 10% 证明是时序相位竞争。gem5 formal 侧证：LSQ 转发的 bitflip/撕裂/相位三种模式 SDC 全部 100%（n=64/cell），相位偏移 offset∈{1,2,4,8} × n=384 全部 384/384 SDC。相位错开一步即必错，与现场"一条 no-op 塌方"的敏感性定量同构。

旁路交叉矩阵/写端口，方法一混叠形态的机理载体。gem5 侧的关键技术发现：背靠背 FMA 依赖链（fmadd d0 → fmadd d0）的中间值在旁路网络中流动、从不回读物理寄存器堆。对 PRF 单元的注入被操作数转发完全击败（15 个种子全部掩蔽），唯一有效的注入点是源操作数读取路径。这证明 FMA 链的暴露点恰在转发网络，而方法一的"其他计算数据混叠写入 x[0]"与旁路/写端口误路由的净效果完全一致。

寄存器重命名表（合法域替换），对方法一的混叠成立，与撕裂形态可区分。支持证据：方法一的状态泄漏签名（numeric-only 失败率 ≈4× compute-both）指向跨迭代微架构状态泄漏；长存活 d4 累加器正是 F5 偷映射的目标类。gem5 侧证：m1-formal 用 CHAOSRenameMap f5_substitute 打在汇编固定的长存活累加器 x9 上，精确复现了这个压制签名（numeric 臂 77% vs compute-both 臂 0%，Fisher 精确检验 p=1.19e-71）。限定：现场撕裂移位的形态（实收值 = 别处真实内存字节流）是装载通路签名；重命名替换应交付另一个活寄存器的值而非内存字节。所以此候选解释方法一，不解释方法二/三。

PRF 单元（cell 级），不太可能。现场 XOR 每次不同（无驻留位）、无重复值模式；撕裂移位需要"别的地址的真实字节流"，寄存器堆 cell 给不出这个。写端口 mux 的可能性并入旁路矩阵候选。反向证据：17 轮 L1D 整体禁用实验期间故障仍复发（08-31 案），排除阵列级驻留损伤，支持通路级（时序/选通）缺陷。

乱序控制/指针管理，驻留损坏 unlikely，瞬态误相位成立。现场案 14（合法 vmemmap 指针整字替换 + 相邻双 load 同址不同值）证明选择逻辑的瞬态误选可以交付"合法但错误"的值。但 gem5 formal 显示控制状态的驻留性损坏倾向响亮崩溃：IQ 75.3% DUE/0% SDC、freelist 72-77% DUE/0% SDC、RAT F5 59.7% DUE/0% SDC。控制结构免疫 SDC（提交前依赖检查必崩），与 TC'23 文献结论一致。


同一边际时序毛刺落在数据交付段的不同逻辑上，形态就不同：字节选路 mux 错拍给撕裂移位；数据使能/总线未驱动给零塌缩；sense-amp 采样窗给宽带翻转；store 数据选择给同类指针替换；旁路/写端口误路由给寄存器混叠（方法一）；PTW 读出受扰给假翻译故障（前兆）。这些单元不是流水线意义上的"前置"，而是所有功能单元结果必经的公共数据搬运与选路段。故障不在功能单元内部，而在功能单元之间的基础设施上。

物理机理层的诚实边界：单点缺陷（某通孔退化，后果扇出）与单一边际区域（局部电源域老化，多条临界路径间歇违例）在软件侧不可区分，倾向后者（与间歇无趋势、簇发节律吻合更好），但这是倾向不是证明。裁决需要供应商 ATE/shmoo。

至于根因在于重命名替换（交付另一个活寄存器的值）还是旁路/写端口误路由（交付另一条在途结果），超出软件可判定范围。


根因重定位到所有功能单元共用的数据搬运与选路基础设施。候选单元按证据强度排序：STLF（首要，四必要条件+相位敏感+gem5 三模式 100%）、旁路交叉矩阵/写端口（方法一混叠的机理载体，gem5 旁路击败 PRF 注入的发现）、寄存器重命名表合法域替换（解释方法一的 4× 状态泄漏签名，与撕裂形态可区分）；PRF cell 级与控制结构驻留损坏被形态学与 formal 数据双重排除。四族坏值形态是同一边际时序条件在不同逻辑落点上的失败模式谱，共享"内存正确、地址正确、运算正确、搬运出错"的解剖结构。

SDC的微架构分布归因必须穿过观测载体的表象：浮点负载上的 SDC 不等于浮点单元的 SDC，当故障在公共数据通路上时，任何功能单元都可能替它背锅。指令级功能测试需要一个"真值 vs 实收"的对照面才能看见数据搬运通路。
