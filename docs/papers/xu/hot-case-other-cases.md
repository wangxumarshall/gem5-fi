
17 次崩溃中可对照的坏值（x20 实收 vs `__per_cpu_offset[]` 内存真值，crash 直读）分为四族：

| 族 | 案数 | 形态 | 判定 |
|---|---|---|---|
| 零塌缩 | 6（5 实锤+1 强推） | 非零内核指针装载为全零（真值如 `0xffffa89017090000`，实收 `0x0`） | 数据拍未送达：返回总线该拍未驱动（浮空读零）或填充缓冲以零值顶替 |
| 撕裂移位 | 7（6 实锤+1 强推） | 实收值 = 被读数组错相位 N 字节处的**真实字节流**（+1/+2/+5 字节相位均被 crash 直读唯一命中验证） | 字节选路网络（对齐 mux/字节使能/合并缓冲指针）错拍；SRAM 阵列失效给不出"别处的正确内容" |
| 宽带位翻转 | 2 | 汉明距离 31-35，均匀散布 64 位，无字节/列结构 | 读出模拟前端（sense-amp/位线）边际压差窗口内多位同时误读 |
| 同类指针替换 | 1（多核级联） | 链表头被写成合法 vmemmap 指针（XOR 27 位整字替换）+ 写路径持久化 + 相邻双 load 同址不同值 | store 数据选择误路由（写侧交付错误且持久化） |


四族共享五条不变量：内存真值完好 / 地址计算正确 / 算术自洽 / 唯搬运交付出错 / 归属 CPU179。这个解剖结构把故障从"随机位翻转"重新定义为"数据搬运通路的结构化选路错误"。

## 6. 设计与检测启示

检测方面，`Ignoring spurious kernel translation fault` 按核统计是本谱系唯一免费的前兆遥测，当前被 WARN_RATELIMIT 静默吞掉。本案例等效于手工执行了 Hardware Sentinel 的启发式（单核异常集中+内核异常+SEL 静默）且判别力更强。调度器热路径的指针装载可加低成本不变量校验（高位 16 位必须全 1、对齐检查），把 SDC 从静默错误决策变成可定位的 panic。

微架构方面，L1D ECC 拦驻留翻转，拦不住"行内容正确但回读错"。load 返回总线（fill-buffer→寄存器堆写端口）加端到端奇偶，错则重放，面积小，正中盲区。store 通路对称处理（案 14 证明写侧同样交付错误且持久化）。PTW 读出 PTE 加奇偶：最坏情形（PTE 读错且值合法，导致静默错误映射）是 SDC 完全体。

制造测试方面，撕裂移位在传统 March 算法下不可见（阵列没坏，选路错拍）。需要已知模式填充连续行+非对齐装载序列回读比对的定向向量，覆盖全部字节相位组合。结构化腐化形态（ror16+标签、+N 字节窗口）应纳入 DFT 图谱，它们指向 mux/bypass 错位而非 SRAM 坏位，直接指导失效分析方向。

方法论对文献的修正：现有 SDC 归因建立在指令级功能测试上，这个范式天然偏向"输出即结果"的算术单元。本案例中"浮点 SDC"的初始标签正是这个偏差的产物：Eigen 测试是当时唯一在跑的浮点负载，故障却全然不在浮点部件。Harpocrates 实测现有工具对 LSQ 的 SDC 检测率仅 0-20%，是所有结构中最低的；本案例以三级代数闭合+真值对照证明了这块盲区可观测，所需的全部工具是 kdump 与 crash。
