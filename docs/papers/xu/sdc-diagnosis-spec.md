# CausalSDC：基于故障传播链和证据图溯因推理的微架构级 SDC 诊断

通过建立从物理微架构到 Fleet 服务层的多层级故障传播链模型（L0–L5），结合正向证据（P1–P6）、间接证据（G1–G29）、负向证据（N1–N11）、证据组合协同判定规则（SYN-1–SYN-6）以及处置动作（ACT-1–ACT-7），构建基于故障传播链路的结构化决策图谱，实现SDC根因概率溯缘推理、自适应测试选择及自适应隔离处置。

> **编号约定**：**P\*/G\*/N\*** 为三级证据编号，**SYN-\*** 为证据组合协同判定规则，**ACT-\*** 为处置动作，**CP-\*** 为核心解耦原则。

---

## 一、 SDC 定义与故障传播链层级模型

### 1.1 SDC 严谨定义
静默数据损坏（Silent Data Corruption, SDC）定义为：**CPU 硬件计算逻辑产出错误架构结果，但未触发任何硬件告警（RAS 链路全程静默，如零 MCE/SError/GHES/BERT/SEL 记录），错误数据穿透保护路径，最终导致业务数据损坏或系统崩溃。**

> **注**：SDC 并非完全不引发显性故障。若上一条指令计算的地址受损，后续指令访问该非法地址引发进程崩溃（SIGSEGV）或内核 Panic，仍属 SDC 范畴。因为在触发非法地址访问前，硬件已静默加载/计算了错误数据。

### 1.2 六层故障传播链模型与诊断策略
SDC 故障从微观物理缺陷演变为宏观业务故障，需穿透以下 6 层传播链条：

```
[在线/运行态软件诊断层]
L5 Fleet/服务层   ──► 跨机复发模式、单核失败分布、业务可见故障
L4 应用/业务层   ──► 输出 Diff、CRC 失配、重执行不一致、PMC 签名偏移
L3 OS/系统层      ──► 内核 Panic/Oops、SEL/BMC 遥测、EDAC 记录、Syscall 行为
L2 ISA/指令层     ──► 架构状态污染 (WD/WI/WOI)、双执行分歧、ESC 旁路
──────────────────────────────────────────────────────────────────────
[后测/微架构级深入定位层 (深入定位步骤)]
L1 微架构层      ──► 结构承载 (L1D/FPU/STLF/PRF)、un-ACE 掩蔽、Commit Trace
L0 电路/物理层   ──► 缺陷本体 (Stuck-at/Aging/Marginal/Delay)、时序 Slack、变温特征
```

**诊断策略**：
1. **第一阶段（运行态诊断）**：依赖 L2–L5 的日志、探针、软件重执行与遥测，完成 SDC 的定性判定、软件 Bug 排除与物理核初步锁定。
2. **第二阶段（微架构定位）**：针对已确诊/高度可疑的 SDC 硬件，下发至离线/离线沙盒（SBST/gem5-fi/变温测试），调用 L0–L1 规则（第七章）将故障精准归因至特定微架构执行单元（如 Vector FPU、STLF CAM 比对器、L1D 数据阵列）。

## 二、 核心理念与判定原则

传统诊断依赖专家经验的静态"布尔规则匹配"，容易因规则冲突产生诊断盲区，或"误把相关性当因果性"。CausalSDC 范式将 SDC 诊断重新定义为基于全栈证据图谱的概率溯因推理、成本感知的自适应测试选择过程。

### 2.1 解耦错误源头与架构表象（核心原则 CP-1）
* **原理**：\\[\text{SDC Source} \neq \text{SDC Outcome}\\]
* **微架构源头与架构表象解耦**：同一种底层微架构缺陷（如 LSU 存取数据通路 MUX 翻转），在架构层既可能表现为 **SDC**（计算结果偏离），也可能表现为 **DUE/Crash**（非法指针引发 Kernel Panic）或 **Hang**（状态机卡死）。诊断系统绝不能被最终的表象绑定。

### 2.2 解耦软件并发与硬件 SDC（核心原则 CP-2）
* **软硬件行为解耦**：在弱内存序（如 ARM64）架构下，多线程竞争/数据竞争的表现与硬件 SDC 极其相似。
* **确定性排空规程**：在确认硬件 SDC 前，必须通过绑核、缓存状态对齐、相同输入控制及禁用中断完成确定性沙盒排空。唯有出现 **跨核不一致（Cross-core Inconsistency，P4）** 或 **单核重执行分歧（Same-core Divergence，P4）** 时，才能确立硬件 SDC 嫌疑。

### 2.3 二维故障定位坐标系（核心原则 CP-3）
任何异常事件均须置于**"故障表现"**与**"故障源头"**构成的二维坐标系中进行精确定位：
| 故障源头 \ 架构表现 | Masked（被掩蔽） | SDC（静默数据损坏） | DUE / Crash（显性崩溃） | Hang（系统挂死） |
| :--- | :--- | :--- | :--- | :--- |
| **软件 Bug / 竞争** | 动态死代码 / 无用路径 | 弱内存序竞争（N11） | 软件空指针 / 越界 | 软件死锁 |
| **硬件固定/边缘缺陷**| un-ACE 掩蔽（Rule1-2）| 逻辑门/数据通路翻转（P1–P6）| Tag 错引发 Page Fault | 状态机未复位/Bus 挂起 |
| **环境/瞬态粒子** | 乱序推测 Flush | 瞬态 Vdroop 翻转 | 临界 Single Event Upset | 锁存器锁死 |
| **未知 / 外部 IO** | 被上层应用容忍 | 存储/网络 DMA 污染 | 磁盘/PCIe 硬件 DUE（N1–N10）| PCIe 链路超时 |

### 2.4 证据优先级与冲突仲裁原则
三级证据（P/G/N，定义见第三章）在冲突时的仲裁规则，是整个判定体系的元规则：

1. **证据优先级与冲突仲裁**：
   * 当排除证据与间接证据或直接证据同时存在时，**直接证据优先级最高、排除证据优先级第二、间接证据优先级最低**；但去重后的间接证据似然权重联合压倒排除证据时，间接证据占主导地位（判据见下方似然比解释）。
   * 排除证据用于说明异常是否可由非 CPU-SDC 根因（如内存 DIMM、磁盘、存储 IO、PCIe 链路、已知软件 Bug 或显性硬件 DUE）解释。

   **似然比（LR）解释**（本仲裁规则的概率论依据）：
   * 直接证据（P2–P6）：\\[\text{LR}^+ \ge 100\\]（已知答案/物理隔离构造，假阳性率结构性趋零，可独立翻越任意先验）；
   * 排除证据（N）：\\[\text{LR}^- \le 0.01\\]（对非 CPU-SDC 假设的强支持）；
   * 单条间接证据（G）：\\[1 < \text{LR}^+ < 10\\]（不可独立定性，须联合）。
   * "间接证据压倒排除证据"的判据是**去重后的似然权重**而非证据条数：多条**近独立**的 G 证据联合 LR 超过对应 N 证据的 LR⁻ 倒数时，间接证据群占主导。
   * **相关性去重原则**：同一底层事实的多种投影不得重复计票——G17/G18/G19（单核集中/同核多模块/NUMA 集中）属同一**空间信号族**，G20/G21/G22（频繁重启/间隔递减/静默窗口）属同一**时域信号族**；同族证据合并计一次似然权重。

   **fallback 层声明**：本节序数仲裁规则是第四章似然引擎的**降级 fallback**——当涉及证据的似然表未校准（证据卡"校准状态"为 uncalibrated，见 3.0 节）时适用；证据已校准时，以第四章后验 \\(P(H \mid E)\\) 计算结果为准，本节规则不得覆盖。
2. **直接证据独立定性原则**：
   * 命中任一直接证据（P1–P6），由于其拥有最高优先级，即可无视排除证据，独立定性为 **确定性 SDC**。
   * **P1 例外**：P1（软硬 DIF 校验失配）的假阳性来源恰是排除证据 N6 所述的校验硬件自身故障（HBA/RAID 卡故障同样表现为软硬校验失配）。因此 P1 参与本仲裁须先满足其前置条件（见 3.1 节 P1 定义）：排除校验硬件故障或确认校验路径物理隔离。
3. **单条间接证据不能独立定性，必须多层协同形成证据链**：
   * **RAS 静默（G1）** 与 **RAS 信息不完整（G2）** 仅说明"观测能力不足"或"未通过受保护路径"，不能单独作为 SDC 的定性依据，必须配合 CPU 核级别异常信号方有诊断价值。
4. **二元解耦原则（Source ≠ Outcome 与软硬件解耦）**：
   * **源头与表象解耦**：同一种微架构 SDC 根因，在架构层既可表现为 SDC（错计算输出），也可表现为 DUE（错误指针引发 Kernel Panic）。
   * **软硬件解耦**：在确定硬件 SDC 前，必须通过绑核、缓存状态对齐、确定性重放（SYN-2）排除软件并发/弱内存序导致的非确定性。

## 三、 分层判定证据清单（P / G / N）

> **定位**：本章是四步闭环诊断体系（第四章）的数据基础，给出三级证据的完整定义、诊断签名与采集方法。

### 3.1 直接证据清单（Positive Evidence，P1–P6）：命中任一即可独立定性 SDC（证据优先级仲裁见 2.4 节；P1 须先满足其前置条件）。

| 编号 | 直接证据名称 | 详细描述与诊断签名 | 典型日志/数据来源 |
| :--- | :--- | :--- | :--- |
| **P1** | **软硬DIF校验码不一致** | 软件计算的 DIF/Checksum 与硬件（RAID/HBA 卡）计算结果发生失配。**前置条件**：须先排除校验硬件自身故障（对应排除证据 N6：RAID 控制器/HBA 卡故障本身即可造成软硬校验失配的假阳性），或确认校验路径与被检数据路径物理隔离；未满足前置条件时 P1 不参与"直接证据压倒排除证据"仲裁。 | 存储层校验日志 |
| **P2** | **CPU 指令级计算错误** | 汇编级分析确认特定 CPU 算术/校验指令（如 ARM `CRC32CX`）算错输出结果。 | 汇编指令插桩/SDC检测用例复现 |
| **P3** | **同节点/Core上不同业务/进程的错误指纹模式相同** | 同一节点或cpu核上多个独立进程崩溃的 vmcore 文件或dmesg中提取出完全一致的比特错误（翻转或跳变或循环移位或清零等）模式，且异常集中在某个核/某些核。 | 多 vmCore 或dmesg文件对比 |
| **P4** | **双执行/重执行跨核不一致** | 同一指令/程序在相同架构输入下，原始核与验证核（物理隔离）输出不一致（Inconsistent Error），直接证明硬件非确定性错误。验证核必须与执行核物理隔离，防止同一坏单元产生相同错误而漏检。 | L2 双执行插桩 / L4 跨核确定性重放 |
| **P5** | **跨天复现且 SMT Sibling 同败** | 同一物理核跨多天复现同一测试失败，且该核的两个 SMT 兄弟逻辑核同败同一测试、跨物理核不扩散，判定为单物理核单一失效单元缺陷（占 Fleet 62%–89% 案例）。 | Fleet 测试平台持续测试记录 |
| **P6** | **向量 vs 标量差分不一致** | 同一计算，向量指令输出与标量参考指令输出不一致，判定为向量单元缺陷；>80% SDC 案例在 <10K 轮内首次失败。 | 向量/标量差分测试框架 |

### 3.2 间接证据清单（Gray Evidence，G1–G29）：须多条组合形成证据链，或结合核级信号判定。

#### 【第 1 层：硬件 RAS 信号层】
* **G1（RAS 信息静默）**：RAS 采集链完整，但系统无任何硬件告警。
* **G2（RAS 信息不完整）**：RAS 采集链断裂（如 APEI 固件缺陷、PECI 通信超时、I2C 挂死）。*必须配合核级信号方有效；若有排除证据则直接排除。*
* **G3（MultiEcc）**：启动期出现多次 ECC 错误，指示 CPU Cache 存在硬件异常。
* **G4（Core Isolated）**：BIOS/硬件日志报告故障 CPU 核心已被隔离。
* **G5（无 ECC 保护配置）**：命中 `DCU Without ECC` 或 `ddr_ecc:0x0` 等无 ECC 保护拓扑。
* **G6（ARER 指向核内 Cache）**：ARER 记录明确指向 CPU 核内 L1/L2/L3 Cache。*注：若指向 DIMM 则归入排除证据 N4。*

#### 【第 2 层：内核异常信号层】
* **G7（SError 核心集中）**：ARM64 SError 异常高度集中于特定 CPU 物理核。
* **G8（特定CPU核挂死）**：Softlockup 或 Hung Task 在不同代码路径下均固定挂死于特定的CPU物理核。
* **G9（FPAC 异常）**：ARM64 浮点指针认证异常（FPAC）触发。
* **G10（单 bit 翻转）**：通过Oops 寄存器值、core 文件指针分析，寄存器、指针或锁状态位中发现明确的单 bit 翻转（如 bit0、bit5、bit6、bit31 翻转）。
* **G11（已知模式多位翻转）**：堆栈/内存 Dump 分析，内存或堆栈中提取出符合特定硬件泄露指纹的多位翻转（如 `0x800000`、`dead4ead` 泄漏）。
* **G26（罕见内核异常聚合）**：罕见内核异常类型（如 Double Fault 偏离度 59.35×、Stack Segment 20.77×、Invalid Op 17.80×）在单核聚合出现，是 CPU SDC 的强指标。

#### 【第 3 层：应用层数据校验层】
* **G12（内存数据翻转）**：应用 CRC 校验失败，但落盘原始数据完全正确。
* **G13（元数据 CRC 扩散）**：MDS 或文件系统元数据（如 Radix Tree）CRC 错误扩散。
* **G14（魔数字不匹配）**：内存结构或元数据魔数字（Magic Number）发生异常改变。
* **G15（Pool Verify 失败）**：存储池（如 ZONEIO/CKTAIL）一致性校验失败。
* **G16（EC分条校验单 bit 翻转）**：EC一致性检查日志中，存储 EC（纠删码）P/Q 分条校验中发现单 bit 数据/校验码翻转。
* **G27（PMC/HPC 签名偏差）**：输出正确但 PMC/HPC 性能计数器偏差达百倍到十万倍，指示隐蔽执行轨迹异常；但 PMC 正常不可排除主存值型 SDC。

#### 【第 4 层：空间分布特征层】
* **G17（系统软件报错信息集中在某个或某几个物理核）**：故障统计显示，单物理核异常次数占节点总异常次数 **> 60%**。
* **G18（多个进程或软件模块故障集中在某一个或某几个物理核）**：同一时间内，同一物理 CPU 核上有 **≥ 2 个不同软件模块**发生崩溃或软件报错。
* **G19（NUMA 节点集中）**：异常事件高度集中于特定 NUMA 节点。

#### 【第 5 层：时间与运维特征层】
* **G20（频繁非计划重启）**：30 天内非计划重启/Panic 次数 **≥ 3 次**。
* **G21（重启间隔加速恶化）**：连续非计划重启的时间间隔呈递减序列（如 18h → 6h → 18min）。
* **G22（静默窗口期）**：重启前后存在 > 5 分钟的日志空白窗口期。
* **G23（反复维修未解决）**：运维历史记录显示存在反复维修/更换非 CPU 部件但故障未消除记录。
* **G24（原因不明重启）**：未记录到明确软件 Panic 原因的系统复位。
* **G25（更换验证恢复）**：运维记录明确显示，在更换 CPU 或主板后，该节点故障彻底消失。
* **G28（复发常态与晚发磨损）**：>71% 失败机器在后续 ≥2 年持续稳定失败；或机器在长期无故障运行后开始失败，指示硅片退化/老化。单次窗口无失败不能排除硬件缺陷。
* **G29（温度相关性）**：失败频率与核心温度呈 Log-线性相关（Pearson >0.75）或存在最小触发温度阈值（如仅 >59°C 出错），指示 Marginal/Aging 物理缺陷。

### 3.3 排除证据清单（Negative Evidence，N1–N11）：拥有第二优先级；当无直接证据且无海量间接证据时，判定为非 CPU-SDC。

| 编号 | 排除证据名称 | 排除判定依据与排他性理由 |
| :--- | :--- | :--- |
| **N1** | **显性硬件崩溃** | 出现 CATERR/IERR 等硬件不可恢复告警，属 DUE 显性故障而非 SDC。 |
| **N2** | **多核均匀分散** | 异常事件在节点内所有 CPU 核心上均匀分布，指示软件缺陷或系统配置问题。 |
| **N3** | **单一软件栈 Bug** | 仅单一软件模块发生崩溃，且所有 Backtrace 完全一致。 |
| **N4** | **内存层故障** | 异常可由 DIMM CE/UE/PFAE/CE_STORM 解释（含 ARER 指向 DIMM）。 |
| **N5** | **存储介质故障** | 异常可由磁盘 Setro、Medium Error、SMART 报修完全解释。 |
| **N6** | **存储 IO 基础设施故障** | 异常可由 RAID 控制器、SAS Expander、HBA 卡故障完全解释。 |
| **N7** | **PCIe IO 链路层故障** | 异常可由 PCIe AER IO 超时、Completion Timeout、Bad TLP 解释。 |
| **N8** | **已知软件 Bug/CVE** | 匹配已知软件漏洞、CVE 或升级 BIOS 引入的软件缺陷。 |
| **N9** | **大规模同步异常** | 集群内大量节点在极短时间内同步发生异常（属软件发布/运维变更诱发）。 |
| **N10** | **更换硬件未恢复** | 运维记录显示在更换 CPU 及主板后，同一异常依然发生。 |
| **N11** | **软件确定性复现** | 在相同输入与软件栈下错误确定性复现，且更换核心执行症状不变，判定为软件 Bug 或数据源损坏。 |

### 3.4 证据采集方法

> **定位**：针对每类证据，给出运行态（L2–L5）的具体检测手段和采集要点。

#### 3.4.1 直接证据的检测方法

**→ P1（软硬 DIF 校验比对）**
比对软件路径计算的 DIF/Checksum 与硬件路径（RAID/HBA 卡）校验结果，两者失配即命中 P1。

**→ P2（指令级已知答案测试）**
对特定 CPU 算术/校验指令（如 ARM `CRC32CX`）执行已知输入→已知输出验证。输出不符即命中 P2。

**→ P3（多 vmcore/dmesg 比特模式对比）**
从同一节点/核上多个独立进程的 vmcore 或 dmesg 中提取比特错误模式（翻转/跳变/循环移位/清零），模式一致且核集中即命中 P3。

**→ P4（双执行 / 跨核重执行）**
两种互补检测路径：
* **L2 双执行**：同一线程内同指令、相同架构输入、不同执行上下文（前导指令序列）下比对输出，不一致即命中 P4。
* **L4 确定性重放**：相同输入 + 初始内存状态 + Syscall 重放，在物理隔离的验证核上重执行，结果不一致即命中 P4。
* **验证核必须与执行核物理隔离**（核私有 ALU/FPU），防止同一坏单元计算两遍产生相同错误而漏检。

**→ P5（Fleet 持续测试 + SMT Sibling 分析）**
* 获取每次测试的 Core ID、时间戳、失败指纹。
* 判定需同时满足三个条件：① 同一物理核**跨多天**复现同一测试失败；② 两个 SMT 兄弟逻辑核同败同一测试且频率几乎一致；③ 跨物理核不扩散。三者齐备方命中 P5。
* 单次失败仅入观察池，不构成 P5。

**→ P6（向量 vs 标量差分测试）**
* 同一计算同时用向量指令和标量指令执行，比对输出，不一致即命中 P6。
* FMA 占向量 SDC 案例 >75%、事件 >92%，检测探针应**优先覆盖 FMA 与向量浮点单元**。

#### 3.4.2 间接证据的采集要点

| 证据 | 采集方法 | 关键阈值/判定条件 |
| :--- | :--- | :--- |
| **G1** | 确认 RAS 采集链完整后检查 SEL/BMC/EDAC 记录 | CPU 相关硬件遥测条目数 = 0 |
| **G2** | 检查 APEI/PECI/I2C 通信状态 | 采集链断裂（固件缺陷/通信超时/挂死） |
| **G3** | 检查启动期 ECC 错误日志 | 多次 ECC 错误 |
| **G4** | 检查 BIOS/硬件日志 | Core Isolated 标记 |
| **G5** | 检查 DCU ECC 配置、DDR ECC 状态 | `DCU Without ECC` 或 `ddr_ecc:0x0` |
| **G6** | 解析 ARER 记录指向 | 指向核内 L1/L2/L3（非 DIMM） |
| **G7–G9** | 收集 SError / Softlockup / FPAC 的物理核分布统计 | 高度集中于特定核 |
| **G10–G11** | 从 Oops 寄存器值、core 文件、堆栈 Dump 提取比特模式 | 单 bit 或已知模式翻转 |
| **G26** | 统计罕见异常类型（Double Fault / Stack Segment / Invalid Op）的单核聚合度 | 偏离度 >10× |
| **G12–G16** | 汇总 CRC / 元数据 / 魔数字 / EC 校验异常 | 校验失败且落盘原始数据正确 |
| **G27** | 收集 PMC/HPC 性能计数器偏差（开销 <2%，适合作初筛触发器） | 偏差 10³%～10⁵% |
| **G17** | 统计单物理核异常占节点总异常比例 | >60% |
| **G18** | 统计同一物理核上不同模块崩溃数 | ≥2 个不同模块 |
| **G19** | 统计 NUMA 节点异常分布 | 集中于特定 NUMA 节点 |
| **G20** | 30 天窗口内非计划重启计数 | ≥3 次 |
| **G21** | 分析连续重启时间间隔 | 递减序列（如 18h→6h→18min） |
| **G22** | 检查重启前后日志连续性 | >5 分钟空白窗口 |
| **G23–G25** | 查阅运维历史（维修 / 更换 / 恢复记录） | 事实匹配即命中 |
| **G28** | 长期失败趋势跟踪 | 持续失败 ≥2 年；或晚发恶化 |
| **G29** | 失败频率与温度的相关性分析 | Pearson >0.75 / 存在最小触发温度 |

#### 3.4.3 排除证据的验证流程

对 **N1–N10** 逐项排查对应非 CPU 故障源（显性硬件告警 → DIMM → 磁盘 → 存储 IO → PCIe → 已知 CVE → 集群同步 → 更换后状态）。每项验证须确认异常**完全**可由该故障源解释方可命中排除。

**N11（软件确定性复现）验证**：
1. 保持相同输入与软件栈。
2. 将负载迁移至不同物理核执行。
3. 若症状**跟随软件栈**而非物理核 → 命中 N11，排除硬件 SDC。
4. 若症状**跟随物理核**而非软件栈 → 不命中 N11，保留硬件嫌疑。

### Step 1：结构化证据图谱

将全量探针与观测证据融合成四维图谱节点。其中 P/G/N 编号的完整定义、诊断签名与采集方法见第三章（3.4 节），证据冲突时的优先级仲裁遵循 2.4 节。

#### 1. 正向归因证据（\\[E^+\\]：支持硬件 SDC 假设）
* **\\[E^+_{\text{Strong}}\\]（P4 跨核重放不一致）**：相同架构输入与初始内存状态下，验证核（物理隔离）与原始核输出不一致。
* **\\[E^+_{\text{Strong}}\\]（P5 跨天复现 + SMT Sibling 同败）**：同一物理核跨多天复现同一测试失败，且该核的 2 个 SMT 兄弟逻辑核同败同一测试、跨物理核不扩散（锁定单物理核缺陷，占 Fleet 62%–89% 案例）。
* **\\[E^+_{\text{Strong}}\\]（P1 软硬 DIF 失配）**：软件计算 Checksum 与硬件（RAID/HBA）DIF 校验结果失配。
* **\\[E^+_{\text{Medium}}\\]（P2 指令级算错 / P6 向量 vs 标量不一致）**：特定 CPU 指令（如 `CRC32CX`）算错，或同一计算向量指令与标量指令输出失配。
* **\\[E^+_{\text{Medium}}\\]（P3 跨进程同模式翻转）**：同节点多个独立进程崩溃，提取出完全一致的比特翻转指纹（G10/G11）。

#### 2. 反向约束证据（\\[E^-\\]：排除特定假设）
* **\\[E^-_{\text{Strong}}\\]（N11 软件确定性复现，SYN-2）**：相同输入与软件栈下，错误随软件栈迁移至不同核心均确定性复现 \\[\rightarrow\\] **排除硬件 SDC，定性为软件 Bug/数据源已坏**。*注：若同时存在直接证据（如 P4），按 2.4 节仲裁，直接证据优先级更高，仍定性为硬件故障。*
* **\\[E^-_{\text{Strong}}\\]（N1–N10 硬件非 CPU 故障排除）**：可完全由显性硬件告警（N1）、DIMM CE/UE（N4）、磁盘（N5）、存储 IO（N6）、PCIe 链路超时（N7）或已知 CVE（N8）解释者，一票否定（仅在无直接证据且间接证据未形成压倒性证据链时生效）。
* **\\[E^-_{\text{Strong}}\\]（SYN-3 EDAC 零告警负证据定罪）**：应用层出现 SDC 症状且全程零 EDAC/CE 记录 \\[\rightarrow\\] **绝对排除受 ECC/SECDED 保护的阵列（L2/L3、ECC 内存），嫌疑锁定至无 Protection 的单元：功能单元（ALU/FPU）、无 ECC 的 L1D、流水线 Mux**。
* **\\[E^-_{\text{Weak}}\\]（G1/G2 RAS 静默与可观测性黑洞）**：明确指出 **"无 RAS 报警 \\[\neq\\] 不是硬件 SDC"**，仅代表错误未通过受保护路径或遥测链断裂，不可独立作为否定硬件 SDC 的依据。

#### 3. 空间定位证据（\\[E_{\text{LOC}}\\]）
* **G17/G18（单物理核故障集中）**：单物理核异常占节点总异常比例 **> 60%**，或同一物理核上 **≥ 2 个不同软件模块** 发生崩溃。
* **G19（NUMA / Mesh 节点集中）**：异常集中于特定 NUMA 节点，或展现出 CMN Mesh 互连网络跨节点扩散特征。

#### 4. 时域与环境证据（\\[E_{\text{TEMP}}\\]）
* **G29 / SYN-5（热敏/压敏 log-线性特征）**：失败频率与核心温度呈 **Log-线性相关（Pearson > 0.75）** 或存在最小触发温度（如仅 \\(>59^\circ\text{C}\\) 出错）\\[\rightarrow\\] **判定为 Marginal/Aging 物理延时缺陷**。
* **G28（晚发磨损与复发常态）**：机器长期正常后爆发失败（硅片退化），且 \\(>71\%\\) 失败机器在后续 \\(\ge 2\\) 年持续稳定失败。
* **G20–G22（频繁重启与恶化间隔）**：30 天内非计划重启 \\(\ge 3\\) 次，且间隔呈递减序列（如 18h \\(\rightarrow\\) 6h \\(\rightarrow\\) 18min）。

### Step 2：微架构似然引擎（Likelihood Engine）

弃用纯经验判断，基于 `gem5-fi` 故障注入与 Fleet 统计建立定量概率计算网络：

\\[P(H_j \mid E) = \frac{P(H_j) \cdot P_{\text{microarch}}(E \mid H_j) \cdot P_{\text{fleet}}(E \mid H_j) \cdot W_{\text{ISA}}(H_j)}{\sum_k P(H_k) \cdot P_{\text{microarch}}(E \mid H_k) \cdot P_{\text{fleet}}(E \mid H_k) \cdot W_{\text{ISA}}(H_k)}\\]

#### 微架构结构先验矩阵（结构 → 症状先验对照与受害单元反查表，由仿真与 Fleet 数据注入）：

| 微架构部件 / 结构 | SDC 敏感度 / 倾向 | 核心症状签名与表现 | 归因定位结论 |
| :--- | :--- | :--- | :--- |
| **L1D Data Array（无 ECC）** | **最高**（53.4%；永久缺陷达 5–71%） | 单 Bit 翻转（对应 G10），强地址相关性；SDC 为其余类别之和的 3–5 倍。 | 锁定 L1D 数据 SRAM 阵列。 |
| **向量 FP 加/乘单元（FMA）** | **最高**（GEMM 下 98.7%，Sparse 97.4%） | 数值/矩阵运算下尾数/指数漂移，极少触发 DUE/Crash。差分测试命中 P6。 | 锁定 17-Port 等执行端口中的 FMA/Wallace Tree 乘法树。 |
| **存储转发通路（STLF）** | 高风险 | 字节旋转（Byte Rotation）、零折叠；CAM 地址比对失灵。 | 锁定 LSU 的 STLF CAM 比较器与 Merge Mask 逻辑。 |
| **物理寄存器堆（PRF）/ Bypass** | 中高风险（真实注入 0–9.9%） | 指针破坏偏多；线间串扰电容（Cross-coupling）引发过期值采样。 | 锁定 Bypass Crossbar 交叉多路复用网表。 |
| **标量整数 ALU** | 极低（SDC 仅 0–18%，Crash >80%） | 长进位链违例；SDC 必然伴随极低 BER（高烈度错误自我暴露为 Crash）。 | 锁定标量加法器 Carry-Lookahead 网络。 |
| **ROB / Issue Queue / TLB** | SDC <1%，DUE/Crash 主导（≈50%） | 虚实地址错乱映射，伴随 Kernel Panic 或 Load Queue 挂起。 | 锁定控制流水线 Flop 或 TLB/MMU 页表 Walk 逻辑。 |
| **主存数据（DRAM）** | SDC/Masked 主导 | 随机命中，HPC/PMC 几乎无痕迹（<0.3%，G27 盲区），极难靠崩溃察觉。 | 锁定主存/数据总线（必须依赖重执行/校验）。 |

### Step 3：假设驱动的自适应测试选择（Active Experiment Selection）

根据当前证据后验概率 \\(P(H \mid E)\\)，利用目标函数动态选择**信息增益最大且成本最优**的下一个测试：

\\[\text{Next Test}^* = \arg\max_{T_i} \frac{\text{EIG}(T_i \mid E) \cdot \left[1 - P_{\text{FP}}(T_i)\right]}{\text{Cost}_{\text{time}}(T_i) + \lambda_1 \text{Cost}_{\text{impact}}(T_i) + \lambda_2 \Delta \text{Env}(T_i)}\\]

#### 三阶自适应测试阶梯：
* **Step 1（低成本 / 在线遥测）**：收集 G1–G9 RAS/SEL 日志、G27 PMC 性能计数器轨迹签名（开销 \\(<2\%\\)，作初筛触发器）。
* **Step 2（中成本 / 毫秒级微基准 SBST）**：在空闲窗口下发特定微架构指令序列（纯 FMA 翻转、memcpy、STLF CAM 匹配、x87 超越函数）。
  * **红线要求**：测试必须遵循**"执行上下文主导复现"**（红线约束 1，第十章），包含能够塑造局部 Vdroop 的前导指令 Context，严禁使用单指令轰炸。
* **Step 3（高成本 / 物理复现）**：执行 P4 跨核确定性重放、P5 跨天复现追踪、以及 G29 / SYN-5 变温压阶跃 Shmoo 扫频。

各证据的具体检测手段与采集要点见 3.4 节；测试族覆盖必须满足 ACT-3 全谱覆盖要求与红线约束 5（多指令族交叉验证）。

### Step 4：成本感知的自适应隔离与处置（Action Framework）

根据推导出的**诊断信心指数（Confidence Index）** 结合成本函数进行闭环处置（ACT-1–ACT-7 完整定义见第八章）：

```

                                    │
       ┌────────────────────────────┼────────────────────────────┐
       ▼                            ▼                            ▼
置信度 < 50% (观察池)        置信度 50%~90% (候选池)       置信度 > 90% (确诊)
       │                            │                            │
       ▼                            ▼                            ▼
• 维持遥测观察                • 部署自适应变温/变压深度测试    • 评估故障域大小 (ACT-1)
• 提升采样频次 (ACT-2/4)     • 加跑 Active/Suspected 测试    ├── ≤2 坏核 ──► 核级 Masking 隔离
                                                               └── >2 坏核 ──► 整机退役 (RMA)
```

## 五、 证据组合与协同判定规则（SYN-1 ~ SYN-6）

> **定位**：本章定义**多条证据如何组合形成判定结论**。每条规则的输入为 P/G/N 证据编号，输出为确定/可疑/排除等判定结论。

* **SYN-1（硬件归因成立的最小证据组合）**：
  IF (命中 P4「跨核重执行不一致」 ∨ 命中 P5「跨天复现 + SMT 同败」)
  ∧ (命中 G1「RAS 静默」)
  ∧ (跨应用复现 / 绑定特定指令族)
  → **判定：硬件 SDC（高置信度）**

* **SYN-2（软件原因排除）**：
  在无直接证据（P1-P6）的情况下，命中 N11（软件确定性复现） → **判定为软件 Bug 或数据源损坏，排除本机硬件 SDC**。
  *注：若同时存在直接证据（如 P4）和 N11，直接证据优先级更高，无视 N11 定性为硬件故障（参见 2.4 节仲裁原则）。*

* **SYN-3（RAS负证据定罪：嫌疑收窄）**：
  应用层出现 SDC 症状 ∧ 全程零 RAS（EDAC/CE） 记录（结合 G5）
  → **排除 ECC 保护阵列（L2/L3、ECC 内存），嫌疑收窄至无 ECC 保护单元（FU > 无 ECC 的 L1D > 流水线逻辑）**。

* **SYN-4（定位到物理核 → 隔离）**：
  命中 P5 → **判定为单物理核缺陷，执行核级 Masking 隔离（ACT-1）**。

* **SYN-5（温度/环境触发归因）**：
  命中 G29（温度相关性） → **判定为 Marginal/Aging 物理缺陷；复现采用加温/压制交替测试**。

* **SYN-6（PMC 轨迹偏移规则）**：
  命中 G27（PMC/HPC 签名偏差） → **判定为隐蔽执行轨迹异常，列入观察池**。但 PMC 正常不可排除主存值型 SDC（参见第十章盲区 3）。

## 六、 运行态协同判定流程与决策树

### 6.1 结论分级标准

| 结论等级 | 判定条件组合 | 运维处置动作 |
| :--- | :--- | :--- |
| **SDC（确定 / Confirmed）** | 命中 P1–P6 直接证据之一（无视排除证据，2.4 节仲裁）；或 SYN-1 成立 \\(\land\\) 跨天复现 \\(\land\\) 定位至 Core/单元；或更换 CPU/主板后故障消失（G25）且伴有核级异常信号。 | 执行 ACT-1 细粒度隔离/退役。 |
| **SDC 高度可疑（Highly Suspect）** | 命中 1 条直接证据但环境扰动大；或**去重后间接证据似然权重压倒排除证据（2.4 节似然比判据）**；或多模块共现（G18）+ 核心集中（G17）+ RAS 静默/黑洞（G1/G2）；或 SYN-1 成立但复现轮次不足。 | 部署自适应变温/变压深度测试，隔离观察。 |
| **SDC 可疑（Candidate）** | 存在 \\(\ge 3\\) 条间接证据（无直接证据）；或仅有单层证据（如仅 L4 输出异常，或仅 PMC 偏差 G27）。 | 列入观察池，提升测试频次（Cadence，ACT-2）。 |
| **观察（Observe）** | 存在 1–2 条间接证据（含 CPU 核级信号 G7/G8/G9/G17），或仅有 RAS 静默/黑洞（G1/G2）且无排除/压倒性证据。 | 维持遥测观察（ACT-4）。 |
| **排除（Excluded）** | **命中 N1–N11 且无直接证据，去重后间接证据似然权重亦未压倒排除证据（2.4 节判据）**；或 SYN-2 成立（N11）。 | 转入非 SDC 故障处理流程（软件/内存/存储/DUE 流程）。 |

### 6.2 综合判定决策树
> 证据优先级遵循 2.4 节仲裁原则：直接证据（P）最高 → 排除证据（N）第二（可被去重后似然权重压倒性间接证据群否决）→ 间接证据（G）最低。

       │
       ├─► 2. 是否命中 N1-N11 排除证据？（第二优先级，含 SYN-2 软件确定性复现）

## 七、 SDC 定位（微架构级深入定位与物理归因）

> **定位阶段说明**：因 L0 电路信号与 L1 微架构 Commit Trace 在软件生产运行态极难实时获取，本步骤作为确诊或高度可疑 SDC 硬件后的**深入定位阶段**，下沉至离线沙盒（SBST/gem5-fi/变温压机台）执行。

### 7.1 L1 微架构结构归因探针与规则
* **Probe1-1（Commit-stage Trace Diff）**：逐条比对 Commit Cycle/PC/Opcode/Operands/物理寄存器内容，锁定首次架构可见故障点。
* **Probe1-2（PMC 性能计数器偏差）**：收集 20 个关键 HPC 指标的绝对百分比偏差。
* **Rule1-1（传播前提与掩蔽）**：若故障位落在 Invalid Entry、被覆写先于读取、位于 Wrong-path（Mis-speculation 被 Flush）、或命中后从未被 Committed 读 \\[\rightarrow\\] **掩蔽，不判为 SDC**。
* **Rule1-2（un-ACE 九类掩蔽库）**：命中以下任一即掩蔽：Idle/Invalid 状态位；Wrong-path 指令；预测器结构（BTB/分支预测器 AVF=0）；Ex-ACE；NOP 非 Opcode 位；非绑定 Prefetch；Predicated-false 指令；动态死代码（FDD/TDD）；逻辑掩蔽位（OR 常数高位 Unused）。
* **Rule1-3 / Rule1-4（Cache & Tag 生命周期）**：写穿透 Cache 数据位仅在 Fill/Read 时为 ACE；写回 Cache 一旦被写，同行未写字节全程保持 ACE 直至 Evict。Tag 单 bit 错仅 False Positive（错误命中）可能致 SDC，False Negative 仅触发 Miss；写回 Cache 的 Tag 从数据首次修改到 Evict 全程为 ACE。
* **Rule1-5（HPC 偏差探针与盲区）**：输出正确但 PMC 偏差巨大（10³%～10⁵%）指示隐蔽轨迹异常（命中间接证据 G27）；**但主存数据值型 SDC 在 HPC 上几乎零痕迹（<0.3%），纯计数器检测对此类 SDC 失效**（参见第十章盲区 3）。
* **Rule1-6（驻留时长与永久缺陷）**：永久缺陷在 L1D 的 SDC 率（最高 70.8%）远高于瞬态缺陷（最高 43%），同一位置反复出错指示永久物理缺陷。

### 7.2 L0 电路/物理层根因定位探针与规则
* **Probe0-1（时序 Slack 前兆）**：Aging-aware STA 的 Slack/WNS 及 Cell 延迟退化百分比。
* **Probe0-2（环境遥测）**：核心温度、电压、频率阶跃特征（BMC/SEL）。
* **Rule0-1（前兆预警）**：若时序违例路径 Slack 持续下降且 BTI 退化模型预测违例 \\[\rightarrow\\] 列入高危先验预警。
* **Rule0-2（触发条件归因）**：命中间接证据 G29（SDC 失败频率与核心温度呈 **Log-线性相关 Pearson > 0.75** 或存在最小触发温度，如仅 \\(>59^\circ\text{C}\\) 出错）\\[\rightarrow\\] **判定为 Marginal/Aging 类物理延时缺陷，排除高能粒子软错误**。
* **Rule0-3（规格内出错）**：若出错均发生在正常规范内（95% 事件发生在 \\(<80\%\\) 最大频率下）\\[\rightarrow\\] **不可用"降频避险"处置，属设计/制造缺陷**。
* **Rule0-4（输入位敏感指纹）**：若特定输入位（如特定 bit 清零时必错、置位时正常）表现出极高敏感性 \\[\rightarrow\\] 输入依赖型硬件缺陷，可作为微架构指纹。
* **Rule0-5（延迟故障判据）**：Wire 延迟故障导致 SDC 必须同时满足静态超时钟周期、信号实际 Toggle、错误值被锁存、锁存集合 GroupACE 四条件；**注意 ECC 对字线延迟故障不等价防护（延迟可致 Sense Amp 锁错行且 ECC 校验仍能通过）**（参见第十章盲区 6）。

## 八、 处置与运维规则（Action: ACT-1 ~ ACT-7）

* **ACT-1（细粒度自适应退役）**：若缺陷物理核数量 **≤ 2 个**，且无 Mesh/L3 扩散特征，仅对故障物理核及其 SMT 兄弟核实施 **OS 级 Masking 软隔离（Core Offlining）**，复用其余算力；若缺陷核 **> 2 个** 或扩散至 Mesh 网格，退役整机（RMA）。
* **ACT-2（测试优先级动态划分）**：测试集划分为 Basic（日常必跑）、Active（候选机加跑）、Suspected（本机曾检出用例最高优先级）三级。
* **ACT-3（测试族覆盖多样性）**：测试族必须完整覆盖算术、向量、浮点、Cache 一致性、事务内存、加密、并发锁全谱，严禁仅覆盖算术指令（参见红线约束 5）。
* **ACT-4（双轨持续测试模式）**：必须同时部署 Out-of-production（分钟级、全负载、高覆盖）与 In-production（毫秒级、Co-located、快速收敛）双轨测试机制（参见红线约束 7）。
* **ACT-5（Corpus 语料库反哺）**：坏机快照、失败 Seed、前导 Context 自动回填 Fleet 诊断语料库，后续测试使用伪随机指令/数据序列扩大输入空间。
* **ACT-6（误报治理与假阳性剔除）**：持续识别并剔除高误报率测试（指示全核失败的测试为首要嫌疑，对应排除证据 N2 的多核均匀分散特征），排除故意崩溃的 Fuzzer 负载。
* **ACT-7（复现报告必备 6 大字段）**：定案复现报告必须包含：**失败 Seed、Core ID、温/频/压快照、前导指令序列（Execution Context）、负载指纹、复现频率（次/分钟）**。

## 九、 典型诊断推演案例（CPU179 假设消除法）

以下展示 CausalSDC 框架如何通过假设消除与自适应测试选择完成闭环推理：

1. **初始现象**：Core179 运行复杂 GEMM 浮点业务时突发输出偏离（应用层 ABFT Canary 捕获）。
2. **初始假设（\\[H_0\\]）**：Vector FPU 算术单元硬件损坏。
3. **主动测试 Step 1（遥测与零告警，SYN-3）**：收集发现近旁 SEL/EDAC 零告警。似然引擎通过负证据定罪 **排除受 ECC 保护的 L2/L3/DRAM**，嫌疑锁定至无 ECC 保护逻辑。
4. **主动测试 Step 2（轻量微基准，红线约束 1）**：派发高浓度纯 FPU 算术微基准，结果 **全部 Pass**。
5. **假设更新**：\\[H_0\\] 后验概率暴跌，提出新假设 \\[H_1\\]（LSU 数据搬运通路 / STLF 损坏）。
6. **主动测试 Step 2 续（定向 SBST）**：派发纯 memcpy 与整数 Load 测试，在 Core179 上 **稳定复现失败**（产生 \\(E^+\\) 证据）。
7. **签名分析**：错误数据呈现"字节旋转（Byte Rotation）"特征。
8. **根因收敛与隔离（ACT-1）**：精准锁定故障位于 LSU 的 Load/Store 跨排线/多路选择器（MUX）微架构结构。诊断置信度 \\(>95\%\\)，触发 ACT-1 执行 OS 级 Core179 物理核软隔离（Masking）。

## 十、 诊断方法论红线约束与结构性盲区

### 10.1 不可违反的方法论红线约束
1. **执行上下文主导复现**：SDC 错误显现取决于前导指令序列塑造的微架构/电气 Context（如局部 Vdroop），而非指令使用频率。单指令轰炸脚本几乎全部复现失败，**必须构造包含前导 Context 的测试序列**（x87 legacy 指令除外）。
2. **"校验通过"不可作为排除证据**：若 EC/CRC 校验由向量/FMA 指令加速计算，校验逻辑与数据可能同时被同一硬件缺陷污染（同源污染），**必须引入物理隔离的校验路径**。
3. **OS/内核路径盲区**：OS 参与使 SDC 率相对裸机最高放大 6.7×。Syscall/库路径内的 SDC 无软件防护层，**不能因"应用自身校验通过"而排除**，必须由 L2 指令级插桩补位。
4. **应用语义容差**：若输出偏差在应用语义容差内（如 PSNR、小数位舍入、AI 迭代收敛性），**不判为 SDC**。
5. **负载变更不排除故障**：负载变更后症状消失**不可据此排除硬件故障**（存在软件掩蔽或 Context 未触发），必须用原始 Seed 回放复现。
6. **多指令族交叉验证**：同一缺陷可以跨指令类型以相差 6 个数量级的速率致错，**禁止仅凭单一指令族测试锁定故障单元**（参见 ACT-3）。
7. **持续测试必要性**：一次性快照测试必漏间歇/晚发/磨损类缺陷（参见 G28），诊断体系必须内建双轨持续重测机制（ACT-4）。
8. **CRC 边界判据**：CRC 失配仅指示数据搬运途中被改（"数据变了"），无法发现计算过程算错（如哈希表映射计算算错）。**Checksum 类检测对计算型 SDC 存在原理性盲区。**
9. **ABFT 在线检测**：对于矩阵乘法等数值负载可部署 Checksum 类 ABFT（Algorithm-Based Fault Tolerance），使生产负载直接转化为在线检测器，作为上述 CRC 盲区的补充。

### 10.2 判定能力边界与结构性盲区
1. **一致性错误（Consistent Errors）**：若电路缺陷在相同输入与 Context 下导致两份副本**错得完全一致**，双执行差分比对（P4）原理性失效。
2. **ESC（输出驻留缓存）旁路**：坏数据直接击中 Modified L1D 中即将输出的数据，经 DMA 直接写回内存/网络，**不经后续程序流**，导致基于程序流的一切软件层检测彻底失效。
3. **主存数据值型 SDC**：PMC/HPC 偏差对主存数据值型 SDC 几乎无痕迹（\\(<0.3\%\\)），间接证据 G27 对此类 SDC 存在盲区。此为 SYN-6 的局限性声明。
4. **校验器自身同源污染**：向量/FMA 加速校验时，校验逻辑与数据同源受害导致校验和与坏数据自洽。
5. **PVF/SVF 与全栈 AVF 的失配**：纯软件/架构级评估模型（PVF/SVF）与全栈真实 AVF 结论相反率达 **27–50%**，依赖纯仿真注入矩阵会产生先验偏置。
6. **延迟故障导致 ECC 假性防护**：字线延迟故障可导致 Sense Amp 锁错行且 **ECC 校验仍能通过**（参见 Rule0-5），打破"有 ECC 即无 SDC"的假设，间接证据 G5（无 ECC 保护配置）的排查范围需相应扩展。
7. **"自愈"异例与晚发变数**：硬件存在"119 次失败后 59k+ 测试零失败"的自愈现象或首测 4 年后才爆发的晚发磨损（参见 G28），单次静态测试无法排除缺陷。
