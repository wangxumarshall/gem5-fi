# CausalSDC：基于故障传播链和证据图溯因推理的微架构级 SDC 诊断

SDC 诊断的难点从来不在发现数据错了，而在把账算到哪一层头上：是 CPU、是内存、是存储链路，还是软件自己的 Bug。本规范把从物理微架构到 Fleet 服务层的故障传播路径显式拆成 L0–L5 六层，证据按证明力分三级登记——直接证据 P1–P6、间接证据 G1–G29、排除证据 N1–N11——再配上证据组合规则（SYN-1–SYN-6）与处置动作（ACT-1–ACT-7）。诊断过程就是在这张图谱上做三件事：根因概率溯因、自适应选择下一个测试、自适应隔离处置。

> **编号约定**：**P\*/G\*/N\*** 为三级证据编号，**SYN-\*** 为证据组合协同判定规则，**ACT-\*** 为处置动作，**CP-\*** 为核心解耦原则。

## 一、 SDC 定义与故障传播链层级模型

### 1.1 SDC 严谨定义
静默数据损坏（Silent Data Corruption, SDC）定义为：**CPU 硬件计算逻辑产出错误架构结果，但未触发任何硬件告警（RAS 链路全程静默，如零 MCE/SError/GHES/BERT/SEL 记录），错误数据穿透保护路径，最终导致业务数据损坏或系统崩溃。**

> **注**：SDC 并非完全不引发显性故障。若上一条指令计算的地址受损，后续指令访问该非法地址引发进程崩溃（SIGSEGV）或内核 Panic，仍属 SDC 范畴。因为在触发非法地址访问前，硬件已静默加载/计算了错误数据。

### 1.2 六层故障传播链模型与诊断策略
一个微观物理缺陷要变成业务可见的故障，得依次走完以下 6 层传播链：

```
[在线/运行态软件诊断层]
L5 Fleet/服务层   ──► 跨机复发模式、单核失败分布、业务可见故障
L4 应用/业务层   ──► 输出 Diff、CRC 失配、重执行不一致、PMC 签名偏移
L3 OS/系统层      ──► 内核 Panic/Oops、SEL/BMC 遥测、EDAC 记录、Syscall 行为
L2 ISA/指令层     ──► 架构状态污染 (WD/WI/WOI)、双执行分歧、ESC 旁路
──────────────────────────────────────────────────────────────────────
[后测/微架构级深入定位层 (深入定位步骤)]
L1 微架构层      ──► 结构承载 (L1D/FPU/STLF/PRF)、un-ACE 掩蔽、Commit Trace
L0 电路/物理层   ──► 缺陷本体 (Stuck-at/Aging/Marginal/Delay)、时序 Slack、变温特征
```

**诊断策略**：
1. **第一阶段（运行态诊断）**：依赖 L2–L5 的日志、探针、软件重执行与遥测，完成 SDC 的定性判定、软件 Bug 排除与物理核初步锁定。
2. **第二阶段（微架构定位）**：已确诊或高度可疑的 SDC 硬件，下发至离线沙盒（SBST/gem5-fi/变温测试），调用 L0–L1 规则（第七章）把故障归因到具体微架构执行单元（如 Vector FPU、STLF CAM 比对器、L1D 数据阵列）。

## 二、 核心理念与判定原则

传统诊断靠专家经验做静态的布尔规则匹配，有两个老毛病：规则一多就开始打架，留下诊断盲区；再就是把相关当因果。CausalSDC 换一条路：把 SDC 诊断当作两个过程来做——在证据图谱上做概率溯因推理，以及在成本约束下自适应地选下一个测试。

### 2.1 二元解耦原则（Source ≠ Outcome 与软硬件解耦）（核心原则 CP-1）
* **微架构源头与架构表象解耦**：同一个底层微架构缺陷（比如 LSU 存取数据通路的 MUX 翻转），到了架构层可能表现为 **SDC**（计算结果偏离），也可能表现为 **DUE/Crash**（非法指针引发 Kernel Panic），还可能是 **Hang**（状态机卡死）。表象由软件怎么消费坏数据决定，不由缺陷本身决定。诊断系统一旦绑定最终表象，就已经输了一半。

### 2.2 解耦软件并发与硬件 SDC（核心原则 CP-2）
* **软硬件行为解耦**：ARM64 这类弱内存序架构上，多线程竞争/数据竞争的表现和硬件 SDC 几乎一个模子。
* **确定性排空规程**：定硬件 SDC 之前，必须先通过绑核、缓存状态对齐、确定性重放（SYN-2）把软件并发和弱内存序的非确定性排除掉。

### 2.3 二维故障定位坐标系（核心原则 CP-3）
任何异常事件均须置于**"故障表现"**与**"故障源头"**构成的二维坐标系中进行精确定位：
| 故障源头 \ 架构表现 | Masked（被掩蔽） | SDC（静默数据损坏） | DUE / Crash（显性崩溃） | Hang（系统挂死） |
| :--- | :--- | :--- | :--- | :--- |
| **软件 Bug / 竞争** | 动态死代码 / 无用路径 | 弱内存序竞争（N11） | 软件空指针 / 越界 | 软件死锁 |
| **硬件固定/边缘缺陷**| un-ACE 掩蔽（Rule1-2）| 逻辑门/数据通路翻转（P1–P6）| Tag 错引发 Page Fault | 状态机未复位/Bus 挂起 |
| **物理电气环境或老化的/位翻转或移位或逻辑错误等** | 乱序推测 Flush | 瞬态 Vdroop 翻转 | 临界 Single Event Upset | 锁存器锁死 |
| **未知 / 外部 IO** | 被上层应用容忍 | 存储/网络 DMA 污染 | 磁盘/PCIe 硬件 DUE（N1–N10）| PCIe 链路超时 |

### 2.4 证据优先级与冲突仲裁原则（核心原则 CP-4）
三级证据（P/G/N，定义见第三章）撞车时怎么仲裁，是整个判定体系的元规则：

1. **证据优先级与冲突仲裁**：
   * 排除证据、间接证据、直接证据同时在场时，**直接证据优先级最高，排除证据第二，间接证据最低**。有一个例外：去重后的间接证据似然权重联合起来压倒排除证据时，间接证据说了算（判据见下方似然比解释）。
   * 排除证据的职责只有一个：说明异常能否由非 CPU-SDC 根因（内存 DIMM、磁盘、存储 IO、PCIe 链路、已知软件 Bug、显性硬件 DUE）解释。

   **似然比（LR）解释**（本仲裁规则的概率论依据）：
   * 直接证据（P2–P6）：$\text{LR}^+ \ge 100$（已知答案/物理隔离构造，假阳性率结构性趋零，可独立翻越任意先验）；
   * 排除证据（N）：$\text{LR}^- \le 0.01$（对非 CPU-SDC 假设的强支持）；
   * 单条间接证据（G）：$1 < \text{LR}^+ < 10$（不可独立定性，须联合）。
   * "间接证据压倒排除证据"看的是**去重后的似然权重**，不是证据条数：多条**近独立**的 G 证据联合 LR 超过对应 N 证据 LR⁻ 的倒数，间接证据群才占主导。
   * **相关性去重原则**：同一底层事实的多种投影不许重复计票。G17/G18/G19（单核集中/同核多模块/NUMA 集中）都是空间信号，G20/G21/G22（频繁重启/间隔递减/静默窗口）都是时域信号；同族证据不管命中几条，似然权重只计一次。要是指纹堆得足够多，同族再命中十条也不增加信息量。

   **"间接证据压倒排除证据"的操作性判据（fallback 启发式）**：

   | 排除证据条数 | 间接证据需满足的最低条件 | 判定 |
   | :--- | :--- | :--- |
   | 1 条 N | ≥ 3 条**去重后近独立** G 证据，且至少包含 1 条核级信号（G7/G8/G9/G17/G26） | 间接证据主导 → 【高度可疑/可疑】 |
   | 2 条 N | ≥ 5 条去重后近独立 G 证据，跨越 ≥ 3 个层级（如 RAS 层 + 内核异常层 + 空间分布层） | 间接证据主导 |
   | ≥ 3 条 N | 间接证据几乎不可能压倒，判定为【排除】 | 排除证据主导 |

   > 此表是未校准场景的 fallback 启发式。证据已校准时，以似然比乘积的定量比较为准。

   **完整去重族对照表**：

   | 去重族名称 | 成员证据 | 共同底层信号 |
   | :--- | :--- | :--- |
   | **空间集中族** | G7, G8, G9, G17, G18, G19 | 故障集中于特定物理核/NUMA 节点 |
   | **时域恶化族** | G20, G21, G22, G24 | 频繁重启/间隔递减/静默窗口/原因不明重启 |
   | **运维验证族** | G23, G25 | 维修/更换历史 |
   | **RAS 可观测性族** | G1, G2 | RAS 链路的可观测性状态 |
   | **比特翻转指纹族** | G10, G11 | 寄存器/内存中的比特错误模式 |
   | **数据校验族** | G12, G13, G14, G15, G16 | 应用层数据完整性校验失败 |

   > **跨族独立性**：不同去重族之间的证据视为近独立——G17（空间集中族）和 G20（时域恶化族）同时命中，算 2 条独立证据。
   > **族内合并**：同族证据无论命中多少条，合并计 1 次似然权重。


   **fallback 层声明**：本节序数仲裁规则是第四章似然引擎的**降级 fallback**——涉及证据的似然表未校准时（证据卡"校准状态"为 uncalibrated，见 3.0 节）才适用。多数涉及证据已校准时，以第四章后验计算结果为主要决策依据，本节序数规则退居人工审计的交叉验证；衔接细则见第四章适用边界声明。
2. **直接证据独立定性原则**：
   * 命中任一直接证据（P1–P6）即无视排除证据，独立定性为 **确定性 SDC**——直接证据的构造本身就排除了其他解释。
   * **P1 例外**：P1（软硬 DIF 校验失配）的假阳性来源恰恰是排除证据 N6 描述的校验硬件自身故障——HBA/RAID 卡坏了，软硬校验同样失配。所以 P1 参与仲裁前必须先过前置条件（见 3.1 节 P1 定义）：要么排除校验硬件故障，要么确认校验路径与被检数据路径物理隔离。
3. **单条间接证据不能独立定性，必须多层协同形成证据链**：
   * **RAS 静默（G1）** 和 **RAS 信息不完整（G2）** 只说明"观测能力不足"或"错误没走受保护路径"，单拿出来什么都定性不了，必须配合 CPU 核级别异常信号才有诊断价值。

## 三、 分层判定证据清单（P / G / N）

> **定位**：本章是四步闭环诊断体系（第四章）的数据基础，给出三级证据的完整定义、诊断签名与采集方法。

### 3.0 证据卡字段规范（Evidence Card Schema）

每条证据（P/G/N）在定义之外，还须按以下**八字段**登记为证据卡。证据卡是第四章似然引擎的直接输入——**每条证据本质上就是一个测试**，其灵敏度/特异度直接给出似然比 $\text{LR}^+ = \text{sensitivity}/(1 - \text{specificity})$。

| 字段 | 含义 |
| :--- | :--- |
| **前置条件** | 证据命中成立所须满足的观测/构造条件（如 P1 须排除校验硬件故障） |
| **假阳性来源** | 非 CPU-SDC 根因产生同样观测的路径（对应 2.4 节 LR 判据的 1−specificity） |
| **假阴性来源** | CPU-SDC 存在但该证据不命中的路径（原理性盲区，交叉引用第十章） |
| **Likelihood Ratio** | $\text{LR}^+$（或排除证据的 $\text{LR}^-$），缺数据时给序数带（见 2.4 节） |
| **采集成本** | 时间开销、基础设施依赖（对应第四章 Step 3 的 Cost 项） |
| **侵入性** | 对生产负载的影响等级（无/低 <2% / 中 / 高需下线） |
| **适用架构** | ARM64 专属 / x86 专属 / 通用（对应第四章 $W_{\text{ISA}}$）。注：本规范核心逻辑同时适用于 ARM64 与 x86；微架构归因逻辑理论上可扩展至 RISC-V 等乱序核心，但需重新采集先验数据；不直接适用于 GPU（其超大规模 SIMT 架构的错误传播模型完全不同）。 |
| **校准状态** | **calibrated**（双盲实证）/ **fleet-estimated**（Fleet 统计）/ **expert-prior**（专家先验）/ **uncalibrated**（未校准，2.4 节 fallback 适用） |

> **诚实性红线**：校准状态字段禁止为填表而编造精度。**uncalibrated 的证据卡必须如实标注 uncalibrated**，其似然权重按 2.4 节 fallback 规则降级处理。一个假装精确的 LR 数字，比没有数字害处更大——下游会把它当真。

### 3.1 直接证据清单（Positive Evidence，P1–P6）：命中任一即可独立定性 SDC（证据优先级仲裁见 2.4 节；P1 须先过前置条件）。

| 编号 | 直接证据名称 | 详细描述与诊断签名 | 典型日志/数据来源 |
| :--- | :--- | :--- | :--- |
| **P1** | **软硬DIF校验码不一致** | 软件计算的 DIF/Checksum 与硬件（RAID/HBA 卡）计算结果发生失配。**前置条件**：须先排除校验硬件自身故障（对应排除证据 N6：RAID 控制器/HBA 卡故障本身即可造成软硬校验失配的假阳性），或确认校验路径与被检数据路径物理隔离。前置条件未满足时，P1 降级为高权重间接证据（LR⁺ 降至 ≈10），参与 2.4 节间接证据仲裁流程而非直接定性。 | 存储层校验日志 |
| **P2** | **CPU 指令级计算错误** | 汇编级分析确认特定 CPU 算术/校验指令（如 ARM `CRC32CX`）算错输出结果。 | 汇编指令插桩/SDC检测用例复现 |
| **P3** | **同节点/Core上不同业务/进程的错误指纹模式相同** | 同一节点或cpu核上多个独立进程崩溃的 vmcore 文件或dmesg中提取出完全一致的比特错误（翻转或跳变或循环移位或清零等）模式，且异常集中在某个核/某些核。 | 多 vmCore 或dmesg文件对比 |
| **P4** | **双执行/重执行跨核不一致** | 同一指令/程序在相同架构输入下，原始核与验证核（物理隔离）输出不一致（Inconsistent Error），直接证明硬件非确定性错误。验证核必须与执行核物理隔离，防止同一坏单元产生相同错误而漏检。 | L2 双执行插桩 / L4 跨核确定性重放 |
| **P5** | **跨天复现且 SMT Sibling 同败** | 同一物理核跨多天复现同一测试失败，且该核的两个 SMT 兄弟逻辑核同败同一测试、跨物理核不扩散，判定为单物理核单一失效单元缺陷（占 Fleet 62%–89% 案例，来源：SiliFuzz 论文，Google x86 Fleet 统计；换一个 Fleet，这个比例可能差得很远）。 | Fleet 测试平台持续测试记录 |
| **P6** | **向量 vs 标量差分不一致** | 同一计算，向量指令输出与标量参考指令输出不一致，判定为向量单元缺陷；>80% SDC 案例在 <10K 轮内首次失败（来源：SEVI/ASPLOS'26，向量指令专项测试统计）。 | 向量/标量差分测试框架 |

| **P5** | 三条件齐备：跨多天复现 + SMT 兄弟同败 + 跨物理核不扩散（单次失败仅入观察池） | 共享 L3/Mesh 级缺陷也可能 SMT 同败（需排除扩散特征） | 非 SMT 架构无兄弟核可比；间歇缺陷跨天不复现（G28 晚发变数）；测试环境变更导致复现链中断 | LR⁺≥100 | 高：跨天持续测试记录（依赖 ACT-4 双轨机制） | 低：持续测试本就在生产外窗口 | 通用（SMT 架构） | fleet-estimated（62%–89% 案例占比有 Fleet 统计） |
| **P6** | 向量与标量参考指令本身无缺陷（标量路径作 golden） | 标量参考单元同坏（概率极低但非零）；编译器向量化混入语义差异 | 缺陷在标量单元（此时差分方向反转，仍是证据）；缺陷在访存通路而非计算单元；负载未有效使用硬件向量单元 | LR⁺≥100 | 中：向量/标量差分 SBST（<10K 轮内首败，>80% 案例） | 低-中 | 通用（NEON/AVX 向量实现不同，测试需按 ISA 定制） | fleet-estimated |

### 3.2 间接证据清单（Gray Evidence，G1–G29）：须多条组合形成证据链，或结合核级信号判定。

#### 【第 1 层：硬件 RAS 信号层】
* **G1（RAS 信息静默）**：RAS 采集链完整，但系统无任何硬件告警。
* **G2（RAS 信息不完整）**：RAS 采集链断裂（如 APEI 固件缺陷、PECI 通信超时、I2C 挂死）。*必须配合核级信号方有效；若有排除证据则直接排除。*
* **G3（MultiEcc）**：启动期出现多次 ECC 错误，指示 CPU Cache 存在硬件异常。
* **G4（Core Isolated）**：BIOS/硬件日志报告故障 CPU 核心已被隔离。
* **G5（无 ECC 保护配置）**：命中 `DCU Without ECC` 或 `ddr_ecc:0x0` 等无 ECC 保护拓扑。
* **G6（ARER 指向核内 Cache）**：ARER 记录明确指向 CPU 核内 L1/L2/L3 Cache。*注：若指向 DIMM 则归入排除证据 N4。*

#### 【第 2 层：内核异常信号层】
* **G7（SError 核心集中）**：ARM64 SError 异常高度集中于特定 CPU 物理核。
* **G8（特定CPU核挂死）**：Softlockup 或 Hung Task 在不同代码路径下均固定挂死于特定的CPU物理核。
* **G9（FPAC 异常）**：ARM64 浮点指针认证异常（FPAC）触发。
* **G10（单 bit 翻转）**：通过Oops 寄存器值、core 文件指针分析，寄存器、指针或锁状态位中发现明确的单 bit 翻转（如 bit0、bit5、bit6、bit31 翻转）。
* **G11（已知模式多位翻转）**：堆栈/内存 Dump 分析，内存或堆栈中提取出符合特定硬件泄露指纹的多位翻转（如 `0x800000`、`dead4ead` 泄漏）。
* **G26（罕见内核异常聚合）**：罕见内核异常类型（如 Double Fault 偏离度 59.35×、Stack Segment 20.77×、Invalid Op 17.80×）在单核聚合出现，是 CPU SDC 的强指标。

> **比特翻转特征注意事项**（影响 G10/G11 的签名分析）：
> - 比特翻转**非独立同分布（IID）**：翻转呈位置偏好（如浮点小数部分/尾数位翻转概率显著高于指数位），且多比特翻转之间存在相关性（SOSP'23）。
> - 向量指令 SDC 中，98.5% 仅影响单个向量 lane（SEVI/ASPLOS'26），此空间局部性可作为向量单元缺陷的诊断指纹。
> - 向量指令中指数位和尾数位均可受影响，不可假设"SDC 仅影响低位"（SEVI/ASPLOS'26）。

#### 【第 3 层：应用层数据校验层】
* **G12（内存数据翻转）**：应用 CRC 校验失败，但落盘原始数据完全正确。
* **G13（元数据 CRC 扩散）**：MDS 或文件系统元数据（如 Radix Tree）CRC 错误扩散。
* **G14（魔数字不匹配）**：内存结构或元数据魔数字（Magic Number）发生异常改变。
* **G15（Pool Verify 失败）**：存储池（如 ZONEIO/CKTAIL）一致性校验失败。
* **G16（EC分条校验单 bit 翻转）**：EC一致性检查日志中，存储 EC（纠删码）P/Q 分条校验中发现单 bit 数据/校验码翻转。
* **G27（PMC/HPC 签名偏差）**：输出正确但 PMC/HPC 性能计数器偏差达百倍到十万倍，指示隐蔽执行轨迹异常；但 PMC 正常不可排除主存值型 SDC。

#### 【第 4 层：空间分布特征层】
* **G17（系统软件报错信息集中在某个或某几个物理核）**：故障统计显示，单物理核异常次数占节点总异常次数 **> 60%**。
* **G18（多个进程或软件模块故障集中在某一个或某几个物理核）**：同一时间内，同一物理 CPU 核上有 **≥ 2 个不同软件模块**发生崩溃或软件报错。
* **G19（NUMA 节点集中）**：异常事件高度集中于特定 NUMA 节点。

#### 【第 5 层：时间与运维特征层】
* **G20（频繁非计划重启）**：30 天内非计划重启/Panic 次数 **≥ 3 次**。
* **G21（重启间隔加速恶化）**：连续非计划重启的时间间隔呈递减序列（如 18h → 6h → 18min）。
* **G22（静默窗口期）**：重启前后存在 > 5 分钟的日志空白窗口期。
* **G23（反复维修未解决）**：运维历史记录显示存在反复维修/更换非 CPU 部件但故障未消除记录。
* **G24（原因不明重启）**：未记录到明确软件 Panic 原因的系统复位。
* **G25（更换验证恢复）**：运维记录明确显示，在更换 CPU 或主板后，该节点故障彻底消失。
* **G28（复发常态与晚发磨损）**：>71% 失败机器在后续 ≥2 年持续稳定失败；或机器在长期无故障运行后开始失败，指示硅片退化/老化。单次窗口无失败不能排除硬件缺陷。
* **G29（温度相关性）**：失败频率与核心温度呈 Log-线性相关（Pearson >0.75）或存在最小触发温度阈值（如仅 >59°C 出错），指示 Marginal/Aging 物理缺陷。

### 3.4 证据采集方法

> **定位**：针对每类证据，给出运行态（L2–L5）的具体检测手段和采集要点。

#### 3.4.1 直接证据的检测方法

**→ P1（软硬 DIF 校验比对）**
比对软件路径计算的 DIF/Checksum 与硬件路径（RAID/HBA 卡）校验结果，两者失配即命中 P1。

**→ P2（指令级已知答案测试）**
对特定 CPU 算术/校验指令（如 ARM `CRC32CX`）执行已知输入→已知输出验证。输出不符即命中 P2。

**→ P3（多 vmcore/dmesg 比特模式对比）**
从同一节点/核上多个独立进程的 vmcore 或 dmesg 中提取比特错误模式（翻转/跳变/循环移位/清零），模式一致且核集中即命中 P3。

**→ P4（双执行 / 跨核重执行）**
两种互补检测路径：
* **L2 双执行**：同一线程内同指令、相同架构输入、不同执行上下文（前导指令序列）下比对输出，不一致即命中 P4。
* **L4 确定性重放**：相同输入 + 初始内存状态 + Syscall 重放，在物理隔离的验证核上重执行，结果不一致即命中 P4。
* **验证核必须与执行核物理隔离**（核私有 ALU/FPU），防止同一坏单元计算两遍产生相同错误而漏检。

**→ P5（Fleet 持续测试 + SMT Sibling 分析）**
* 获取每次测试的 Core ID、时间戳、失败指纹。
* 判定需同时满足三个条件：① 同一物理核**跨多天**复现同一测试失败；② 两个 SMT 兄弟逻辑核同败同一测试且频率几乎一致；③ 跨物理核不扩散。三者齐备方命中 P5。
* 单次失败仅入观察池，不构成 P5。

**→ P6（向量 vs 标量差分测试）**
* 同一计算同时用向量指令和标量指令执行，比对输出，不一致即命中 P6。
* FMA 占向量 SDC 案例 >75%、事件 >92%，检测探针应**优先覆盖 FMA 与向量浮点单元**。

#### 3.4.2 间接证据的采集要点

| 证据 | 采集方法 | 关键阈值/判定条件 |
| :--- | :--- | :--- |
| **G1** | 确认 RAS 采集链完整后检查 SEL/BMC/EDAC 记录 | CPU 相关硬件遥测条目数 = 0 |
| **G2** | 检查 APEI/PECI/I2C 通信状态 | 采集链断裂（固件缺陷/通信超时/挂死） |
| **G3** | 检查启动期 ECC 错误日志 | 多次 ECC 错误 |
| **G4** | 检查 BIOS/硬件日志 | Core Isolated 标记 |
| **G5** | 检查 DCU ECC 配置、DDR ECC 状态 | `DCU Without ECC` 或 `ddr_ecc:0x0` |
| **G6** | 解析 ARER 记录指向 | 指向核内 L1/L2/L3（非 DIMM） |
| **G7–G9** | 收集 SError / Softlockup / FPAC 的物理核分布统计 | 高度集中于特定核 |
| **G10–G11** | 从 Oops 寄存器值、core 文件、堆栈 Dump 提取比特模式 | 单 bit 或已知模式翻转 |
| **G26** | 统计罕见异常类型（Double Fault / Stack Segment / Invalid Op）的单核聚合度 | 偏离度 >10× |
| **G12–G16** | 汇总 CRC / 元数据 / 魔数字 / EC 校验异常 | 校验失败且落盘原始数据正确 |
| **G27** | 收集 PMC/HPC 性能计数器偏差（开销 <2%，适合作初筛触发器） | 偏差 10³%～10⁵% |
| **G17** | 统计单物理核异常占节点总异常比例 | >60% |
| **G18** | 统计同一物理核上不同模块崩溃数 | ≥2 个不同模块 |
| **G19** | 统计 NUMA 节点异常分布 | 集中于特定 NUMA 节点 |
| **G20** | 30 天窗口内非计划重启计数 | ≥3 次 |
| **G21** | 分析连续重启时间间隔 | 递减序列（如 18h→6h→18min） |
| **G22** | 检查重启前后日志连续性 | >5 分钟空白窗口 |
| **G23–G25** | 查阅运维历史（维修 / 更换 / 恢复记录） | 事实匹配即命中 |
| **G28** | 长期失败趋势跟踪 | 持续失败 ≥2 年；或晚发恶化 |
| **G29** | 失败频率与温度的相关性分析 | Pearson >0.75 / 存在最小触发温度 |

#### 3.4.3 排除证据的验证流程

对 **N1–N10** 逐项排查对应非 CPU 故障源（显性硬件告警 → DIMM → 磁盘 → 存储 IO → PCIe → 已知 CVE → 集群同步 → 更换后状态）。每项验证须确认异常**完全**可由该故障源解释方可命中排除。

**N11（软件确定性复现）验证**：
1. 保持相同输入与软件栈。
2. 将负载迁移至不同物理核执行。
3. 若症状**跟随软件栈**而非物理核 → 命中 N11，排除硬件 SDC。
4. 若症状**跟随物理核**而非软件栈 → 不命中 N11，保留硬件嫌疑。

## 四、 诊断体系的核心方法论

> **两套体系的适用边界与衔接规则**：
> - **全校准模式**（所有涉及证据的证据卡校准状态为 calibrated 或 fleet-estimated）：使用本章（第四章）的贝叶斯似然引擎计算后验概率，以 Step 4 的 Bayes risk 阈值进行决策。
> - **部分校准模式**（部分证据已校准、部分 uncalibrated）：已校准证据通过似然引擎计算后验，uncalibrated 证据通过第六章决策树的启发式规则进行定性补充。两者结论不一致时，以已校准证据的定量结论为主、启发式结论为辅（即定量结论可升级但不可降级启发式结论）。
> - **全未校准模式**（所有证据 uncalibrated）：仅使用第六章决策树。此为部署初期的预期状态。

### Step 1：结构化证据图谱

将全量观察探针与观测证据融合成四维图谱节点。证据的完整定义见第三章，此处仅定义其在图谱中的**认识论角色分类**：

| 角色标签 | 含义 | 典型证据（完整定义见第三章） |
| :--- | :--- | :--- |
| **E⁺（正向归因）** | 支持硬件 SDC 假设 | P1–P6, SYN-1 |
| **E⁻（反向约束）** | 排除特定假设 | N1–N11, SYN-2, SYN-3 |
| **E_LOC（空间定位）** | 缩小故障物理位置范围 | G17, G18, G19, P5 |
| **E_TEMP（时域环境）** | 提供时间/环境触发条件 | G28, G29, G20-G22 |

> 同一证据可同时携带多个角色标签——例如 P5 既是 E⁺（正向归因：确认硬件缺陷）又是 E_LOC（空间定位：锁定单物理核）。

#### Step 1 补充：图谱节点与边类型定义

证据图谱的**节点类型**须与证据的认识论标签区分——$E^+$/$E^-$/$E_{\text{LOC}}$/$E_{\text{TEMP}}$ 是观测节点上的**认识论角色标签**（支持/反驳/定位/时域），不是图的拓扑结构。图谱由五类节点与两类边构成：

| 节点/边类型 | 内容 | 对应章节 |
| :--- | :--- | :--- |
| **观测节点** | P/G/N 证据的命中事实（含强度与校准状态，取自 3.x 证据卡） | 第三章 |
| **假设节点** | 微架构根因假设 $H_j$（L1D、Vector FPU、STLF、PRF、ALU、ROB/TLB 等） | 第四章先验矩阵 |
| **机制边**（假设→观测） | L0→L5 故障传播概率 $P(\text{签名} \mid H_j)$，即先验矩阵的图化表达；显式因果图的边 | 第一章 L0–L5、第四章 |
| **测试节点** | 3.4 节采集动作与 Step 3 候选测试（含成本/侵入性，取自证据卡） | 3.4 节、Step 3 |
| **动作节点** | ACT-1–ACT-7 处置动作（含 Bayes risk 阈值条件） | 第八章、Step 4 |

> **SYN 规则与因果结构的关系**：第五章的 SYN 规则是显式因果图结构蕴含结论的**规则化冗余**——例如 SYN-3（零 EDAC → 排除 ECC 保护阵列）本质是因果图上的 explaining-away 推理（观测到"零 EDAC 告警"使 ECC 保护阵列假设的后验坍缩，嫌疑质量流向无保护单元）。规则形式便于人工执行与审计，因果图形式便于机器推理与规则一致性校验；两者结论冲突时以因果图推导为准并回溯修正规则。

### Step 2：微架构似然引擎（Likelihood Engine）

这一步不再靠拍脑袋。以 `gem5-fi` 故障注入统计与 Fleet 实测数据为底，建定量概率计算网络：

$$P(H_j \mid E) = \frac{P(H_j) \cdot W_{\text{ISA}}(H_j) \cdot \tilde{P}(E \mid H_j)}{\sum_k P(H_k) \cdot W_{\text{ISA}}(H_k) \cdot \tilde{P}(E \mid H_k)}$$

> **似然融合规则（防双重计数）**：$\tilde{P}(E \mid H_j)$ 是**融合后**的似然。$P_{\text{microarch}}(E \mid H_j)$（gem5-fi 注入统计）与 $P_{\text{fleet}}(E \mid H_j)$（Fleet 实测统计）描述的是同一个 $P(E \mid H_j)$，各贡献一份信息，**不许独立连乘**——连乘等于把同一份证明力记两遍账，必然过度自信。融合按证据卡"校准状态"（3.0 节）取优先级：两者均 calibrated 时推荐 Log-linear 意见池化（或其他能防极端置信度的算法）；只有一方 calibrated 时取该方；都未校准时取几何均值，整体降级为 expert-prior。
> **$W_{\text{ISA}}$ 的定位**：它是假设先验的 ISA 条件化因子（$P(H_j \mid \text{ISA})$ 对 $P(H_j)$ 的修正），在先验侧，不是独立的证据因子——含义只是：不同 ISA（ARM64/x86）下各微架构单元的缺陷发生率基线不同。仅此而已。

#### 微架构结构先验矩阵（结构 → 症状先验对照与受害单元反查表，由仿真与 Fleet 数据注入）：

| 微架构部件 / 结构 | SDC 敏感度 / 倾向 | 核心症状签名与表现 | 归因定位结论 |
| :--- | :--- | :--- | :--- |
| **L1D Data Array（无 ECC）** | **高**（53.4%；永久缺陷达 5–71%） | 单 Bit 翻转（对应 G10），强地址相关性；SDC 为其余类别之和的 3–5 倍。 | 锁定 L1D 数据 SRAM 阵列。 |
| **向量 FP 加/乘单元（FMA）** | **最高**（GEMM 下 98.7%，Sparse 97.4%） | 数值/矩阵运算下尾数/指数漂移，极少触发 DUE/Crash。差分测试命中 P6。 | 锁定 17-Port 等执行端口中的 FMA/Wallace Tree 乘法树。 |
| **存储转发通路（STLF）** | 高风险 | 字节旋转（Byte Rotation）、零折叠；CAM 地址比对失灵。 | 锁定 LSU 的 STLF CAM 比较器与 Merge Mask 逻辑。 |
| **物理寄存器堆（PRF）/ Bypass** | 中高风险（真实注入 0–9.9%） | 指针破坏偏多；线间串扰电容（Cross-coupling）引发过期值采样。 | 锁定 Bypass Crossbar 交叉多路复用网表。 |
| **标量整数 ALU** | 极低（SDC 仅 0–18%，Crash >80%） | 长进位链违例；SDC 必然伴随极低 BER（高烈度错误自我暴露为 Crash）。 | 锁定标量加法器 Carry-Lookahead 网络。 |
| **ROB / Issue Queue / LQ / SQ** | **中等风险**（故障在 Commit 前被依赖图/一致性检查捕获，可转为 DUE/Crash 或SDC）| 依赖图违例，导致流水线提前挂起或引发显性 Crash（如 Illegal Instruction / Segfault）；错误输出到寄存器后，导致寄存器消费者出现技术错误。 | 控制逻辑错误可间接导致其他结构产出 SDC 数据。 |
| **TLB / MMU** | 中低风险（Tag 错误可致错误页映射） | False Positive（错误命中）可能致虚拟地址映射至错误物理页，产生 SDC；False Negative 仅触发 Page Fault/Miss。 | 锁定 TLB/MMU 页表 Walk 逻辑。 |
| **主存数据（DRAM）** | SDC/Masked 主导 | 随机命中，HPC/PMC 几乎无痕迹（<0.3%，G27 盲区），极难靠崩溃察觉。 | 锁定主存/数据总线（必须依赖重执行/校验）。 |

### Step 3：假设驱动的自适应测试选择（Active Experiment Selection）

根据当前后验 $P(H \mid E)$，用目标函数动态挑下一个测试——信息增益要大，成本要低：

$$\text{Next Test}^* = \arg\max_{T_i} \frac{\text{EIG}(T_i \mid E)}{\text{Cost}_{\text{time}}(T_i) + \lambda_1 \text{Cost}_{\text{impact}}(T_i) + \lambda_2 \Delta \text{Env}(T_i)}$$

> **假阳性率的折入方式**：测试 $T_i$ 的假阳性率**不作为独立乘子**（曾经设计过的 $1 - P_{\text{FP}}$ 因子已弃用），而是通过观测模型 $P(\text{result} \mid H_j)$ 折入 EIG 计算本身——假阳性率越高的测试，各假设下的结果分布越趋同，EIG 自然往下掉。若再乘一个独立惩罚因子，同一份信息就被扣减两次，会系统性低估那些假阳性高但判别力也高的测试。

#### 三阶自适应测试阶梯：
* **Step 1（低成本 / 在线遥测）**：收集 G1–G9 RAS/SEL 日志、G27 PMC 性能计数器轨迹签名（开销 $<2\%$，作初筛触发器）。
* **Step 2（中成本 / 毫秒级微基准 SBST）**：在空闲窗口下发特定微架构指令序列（纯 FMA 翻转、memcpy、STLF CAM 匹配、x87 超越函数）。
  * **红线要求**：测试必须遵循**"执行上下文主导复现"**（红线约束 1，第十章），包含能够塑造局部 Vdroop 的前导指令 Context，严禁使用单指令轰炸。
* **Step 3（高成本 / 物理复现）**：执行 P4 跨核确定性重放、P5 跨天复现追踪、以及 G29 / SYN-5 变温压阶跃 Shmoo 扫频。

各证据的具体检测手段与采集要点见 3.4 节；测试族覆盖必须满足 ACT-3 全谱覆盖要求与红线约束 5（多指令族交叉验证）。

### Step 4：成本感知的自适应隔离与处置（Action Framework）

根据推导出的**诊断信心指数（Confidence Index）** 结合成本函数进行闭环处置（ACT-1–ACT-7 完整定义见第八章）。

**决策阈值的 Bayes risk 推导**（置信度阈值不是拍脑袋定的）：
设确诊动作（如 ACT-1 核级隔离/整机退役）的误报代价为 $C_{\text{FP}}$（误退健康 CPU 的 RMA 成本、算力损失），漏报代价为 $C_{\text{FN}}$（SDC 机器流入生产、数据损坏与业务风险）。对当前后验 $p = P(H_{\text{SDC}} \mid E)$，两个动作的期望风险：

$$R_{\text{处置}}(p) = (1 - p) \cdot C_{\text{FP}}, \qquad R_{\text{观察}}(p) = p \cdot C_{\text{FN}}$$

处置阈值取两者交点（风险最小化决策）：

$$p^* = \frac{C_{\text{FP}}}{C_{\text{FP}} + C_{\text{FN}}}$$

> **缺省示例**：对称代价假设（$C_{\text{FP}} = C_{\text{FN}}$）下 $p^* = 0.5$，即下图的 50% 阈值。若 SDC 流入生产的代价是误退一台机器的 9 倍（$C_{\text{FN}} = 9\,C_{\text{FP}}$，Fleet 数据损坏场景的保守估计），则 $p^* = 0.1$——后验到 10% 就该处置，不必等到 50%。90% 高置信档同理：适用于处置动作**不可逆且代价大**（整机 RMA）、误报难以回收的场景（$C_{\text{FP}} \gg C_{\text{FN}}$ 时的近似）。各 Fleet 应按自身业务代价比实例化 $C_{\text{FP}}, C_{\text{FN}}$，别沿用缺省数字。

```
                    [ 计算诊断置信度 Confidence Index ]
                                    │
       ┌────────────────────────────┼────────────────────────────┐
       ▼                            ▼                            ▼
置信度 < 50% (观察池)        置信度 50%~90% (候选池)       置信度 > 90% (确诊)
       │                            │                            │
       ▼                            ▼                            ▼
• 维持遥测观察                • 部署自适应变温/变压深度测试    • 评估故障域大小 (ACT-1)
• 提升采样频次 (ACT-2/4)     • 加跑 Active/Suspected 测试    ├── ≤2 坏核 ──► 核级 Masking 隔离
                                                               └── >2 坏核 ──► 整机退役 (RMA)
```

## 五、 证据组合与协同判定规则（SYN-1 ~ SYN-6）

> **定位**：本章定义**多条证据如何组合形成判定结论**。每条规则的输入为 P/G/N 证据编号，输出为确定/可疑/排除等判定结论。
> **与第四章的关系**：本章 SYN 规则是第四章因果图推理的**人工可执行近似**——每条规则对应因果图上的一个常见推理模式。全校准场景下以第四章似然引擎计算结果为准；未校准场景下 SYN 规则作为独立的判定逻辑使用（见第四章适用边界声明）。

* **SYN-1（硬件归因成立的最小证据组合）**：
  IF (命中 P4「跨核重执行不一致」 ∨ 命中 P5「跨天复现 + SMT 同败」)
  ∧ (命中 G1「RAS 静默」)
  ∧ (跨应用复现 / 绑定特定指令族)
  → **判定：硬件 SDC（高置信度）**

* **SYN-2（软件原因排除）**：
  在无直接证据（P1-P6）的情况下，命中 N11（软件确定性复现） → **判定为软件 Bug 或数据源损坏，排除本机硬件 SDC**。
  *注：若同时存在直接证据（如 P4）和 N11，直接证据优先级更高，无视 N11 定性为硬件故障（参见 2.4 节仲裁原则）。*

* **SYN-3（RAS 负证据定罪：嫌疑收窄，含延迟故障例外）**：
  应用层出现 SDC 症状 ∧ 全程零 RAS（EDAC/CE）记录（结合 G5）
  → **排除 ECC 保护阵列的瞬态/永久 stuck-at 故障，嫌疑收窄至无 ECC 保护单元（FU > 无 ECC 的 L1D > 流水线逻辑）**。
  ⚠️ **延迟故障例外**：字线延迟故障可导致 ECC 保护阵列产生 SDC 且不触发 EDAC 告警（第十章盲区 6），因此 SYN-3 的排除结论仅适用于 stuck-at 与瞬态故障模型，不覆盖延迟故障场景。当存在温度/频率相关性证据（G29）时，须保留 ECC 保护阵列延迟故障假设。

* **SYN-4（定位到物理核 → 隔离）**：
  命中 P5 → **判定为单物理核缺陷，执行核级 Masking 隔离（ACT-1）**。

* **SYN-5（温度/环境触发归因）**：
  命中 G29（温度相关性） → **判定为 Marginal/Aging 物理缺陷；复现采用加温/压制交替测试**。

* **SYN-6（PMC 轨迹偏移规则）**：
  命中 G27（PMC/HPC 签名偏差） → **判定为隐蔽执行轨迹异常，列入观察池**。但 PMC 正常不可排除主存值型 SDC（参见第十章盲区 3）。

## 六、 运行态协同判定流程与决策树

### 6.1 结论分级标准

| 结论等级 | 判定条件组合 | 运维处置动作 |
| :--- | :--- | :--- |
| **SDC（确定）** | 命中 P2–P6 直接证据之一（无视排除证据）；或 P1 命中且前置条件满足（2.4 节）；或 SYN-1 成立 $\land$ 跨天复现 $\land$ 定位至 Core/单元；或更换 CPU/主板后故障消失（G25）且伴有核级异常信号。 | 执行 ACT-1 细粒度隔离/退役。 |
| **SDC (高度可疑）** | 命中 1 条直接证据但环境扰动大；或**去重后间接证据似然权重压倒排除证据（2.4 节似然比判据）**；或多模块共现（G18）+ 核心集中（G17）+ RAS 静默/黑洞（G1/G2）；或 SYN-1 成立但复现轮次不足。 | 部署自适应变温/变压深度测试，隔离观察。 |
| **SDC (可疑 ** | 存在 $\ge 3$ 条间接证据（无直接证据）；或仅有单层证据（如仅 L4 输出异常，或仅 PMC 偏差 G27）。 | 列入观察池，提升测试频次（Cadence，ACT-2）。 |
| **观察** | 存在 1–2 条间接证据（含 CPU 核级信号 G7/G8/G9/G17），或仅有 RAS 静默/黑洞（G1/G2）且无排除/压倒性证据。 | 维持遥测观察（ACT-4）。 |
| **排除** | **命中 N1–N11 且无直接证据，去重后间接证据似然权重亦未压倒排除证据（2.4 节判据）**；或 SYN-2 成立（N11）。 | 转入非 SDC 故障处理流程（软件/内存/存储/DUE 流程）。 |

## 七、 SDC 定位（微架构级深入定位与物理归因）

> **触发条件**：当运行态诊断（第四-六章）判定结论为 **Confirmed** 或 **Highly Suspect** 时，将涉事硬件转入本章的离线深入定位流程。判定为 Candidate 或 Observe 的案例不触发本章，继续在运行态积累证据。
> **与第四章的关系**：第四章 Step 2 先验矩阵中的 SDC 敏感度/倾向数据来源于本章 L0/L1 层的 gem5-fi 故障注入统计。本章的规则用于在离线沙盒中进一步精确归因，其产出（如 Commit Trace Diff、输入位敏感指纹）可回馈至 Step 2 先验矩阵的持续校准。

### 7.1 L1 微架构结构归因探针与规则
* **Probe1-1（Commit-stage Trace Diff）**：逐条比对 Commit Cycle/PC/Opcode/Operands/物理寄存器内容，锁定首次架构可见故障点。
* **Probe1-2（PMC 性能计数器偏差）**：收集 20 个关键 HPC 指标的绝对百分比偏差。
* **Rule1-1（传播前提与掩蔽）**：若故障位落在 Invalid Entry、被覆写先于读取、位于 Wrong-path（Mis-speculation 被 Flush）、或命中后从未被 Committed 读 $\rightarrow$ **掩蔽，不判为 SDC**。
* **Rule1-2（un-ACE 九类掩蔽库）**：命中以下任一即掩蔽：Idle/Invalid 状态位；Wrong-path 指令；预测器结构（BTB/分支预测器 AVF=0）；Ex-ACE；NOP 非 Opcode 位；非绑定 Prefetch；Predicated-false 指令；动态死代码（FDD/TDD）；逻辑掩蔽位（OR 常数高位 Unused）。
* **Rule1-3 / Rule1-4（Cache & Tag 生命周期）**：写穿透 Cache 数据位仅在 Fill/Read 时为 ACE；写回 Cache 一旦被写，同行未写字节全程保持 ACE 直至 Evict。Tag 单 bit 错仅 False Positive（错误命中）可能致 SDC，False Negative 仅触发 Miss；写回 Cache 的 Tag 从数据首次修改到 Evict 全程为 ACE。
* **Rule1-5（HPC 偏差探针与盲区）**：输出正确但 PMC 偏差巨大（10³%～10⁵%）指示隐蔽轨迹异常（命中间接证据 G27）；**但主存数据值型 SDC 在 HPC 上几乎零痕迹（<0.3%），纯计数器检测对此类 SDC 失效**（参见第十章盲区 3）。
* **Rule1-6（驻留时长与永久缺陷）**：永久缺陷在 L1D 的 SDC 率（最高 70.8%）远高于瞬态缺陷（最高 43%），同一位置反复出错指示永久物理缺陷。

### 7.2 L0 电路/物理层根因定位探针与规则
* **Probe0-1（时序 Slack 前兆）**：Aging-aware STA 的 Slack/WNS 及 Cell 延迟退化百分比。
* **Probe0-2（环境遥测）**：核心温度、电压、频率阶跃特征（BMC/SEL）。
* **Rule0-1（前兆预警）**：若时序违例路径 Slack 持续下降且 BTI 退化模型预测违例 $\rightarrow$ 列入高危先验预警。
* **Rule0-2（触发条件归因）**：命中间接证据 G29（SDC 失败频率与核心温度呈 **Log-线性相关 Pearson > 0.75** 或存在显著的最小触发温度阈值，如某 Fleet 案例中的 $>59^\circ\text{C}$ 阶跃）$\rightarrow$ **判定为 Marginal/Aging 类物理延时缺陷，排除高能粒子软错误**。
* **Rule0-3（规格内出错）**：若出错均发生在正常规范内（95% 事件发生在 $<80\%$ 最大频率下）$\rightarrow$ **不可用"降频避险"处置，属设计/制造缺陷**。
* **Rule0-4（输入位敏感指纹）**：若特定输入位（如特定 bit 清零时必错、置位时正常）表现出极高敏感性 $\rightarrow$ 输入依赖型硬件缺陷，可作为微架构指纹。
* **Rule0-5（延迟故障判据）**：Wire 延迟故障导致 SDC 必须同时满足静态超时钟周期、信号实际 Toggle、错误值被锁存、锁存集合 GroupACE 四条件；**注意 ECC 对字线延迟故障不等价防护（延迟可致 Sense Amp 锁错行且 ECC 校验仍能通过）**（参见第十章盲区 6）。

## 八、 处置与运维规则（Action）

* **ACT-1（细粒度自适应退役）**：若缺陷物理核数量 **≤ 2 个**，且无 Mesh/L3 扩散特征，仅对故障物理核及其 SMT 兄弟核实施 **OS 级 Masking 软隔离（Core Offlining）**，复用其余算力；若缺陷核 **> 2 个** 或扩散至 Mesh 网格，退役整机（RMA）。
* **ACT-2（测试优先级动态划分）**：测试集划分为 Basic（日常必跑）、Active（候选机加跑）、Suspected（本机曾检出用例最高优先级）三级。
* **ACT-3（测试族覆盖多样性）**：测试族必须完整覆盖算术、向量、浮点、Cache 一致性、事务内存、加密、并发锁全谱，严禁仅覆盖算术指令（参见红线约束 5）。
* **ACT-4（双轨持续测试模式）**：部署 Out-of-production（分钟级、全负载、高覆盖）与 In-production（毫秒级、Co-located、快速收敛）双轨测试机制（参见红线约束 7）。
* **ACT-5（Corpus 语料库反哺）**：坏机快照、失败 Seed、前导 Context 自动回填 Fleet 诊断语料库，后续测试使用伪随机指令/数据序列扩大输入空间。
* **ACT-6（误报治理与假阳性剔除）**：持续识别并剔除高误报率测试（指示全核失败的测试为首要嫌疑，对应排除证据 N2 的多核均匀分散特征），排除故意崩溃的 Fuzzer 负载。
* **ACT-7（复现报告必备字段）**：定案复现报告必须包含：**用例或业务信息、Core ID、温/频/压快照、前导指令序列（Execution Context）、负载指纹、复现频率（次/分钟）**。

## 九、 典型诊断推演案例

看 CausalSDC 框架如何通过假设消除与自适应测试选择走完闭环推理：

1. **初始现象**：Core179 运行复杂 GEMM 浮点业务时突发输出偏离（应用层 ABFT Canary 捕获）。
2. **初始假设（$H_0$）**：Vector FPU 算术单元硬件损坏。
3. **主动测试 Step 1（遥测与零告警，SYN-3）**：近旁 SEL/EDAC 全程零告警。似然引擎由负证据定罪，**排除受 ECC 保护的 L2/L3/DRAM**，嫌疑收窄至无 ECC 保护逻辑。
4. **主动测试 Step 2（轻量微基准，红线约束 1）**：派发高浓度纯 FPU 算术微基准，结果 **全部 Pass**。
5. **假设更新**：$H_0$ 后验概率暴跌，提出新假设 $H_1$（LSU 数据搬运通路 / STLF 损坏）。
6. **主动测试 Step 2 续（定向 SBST）**：改派纯 memcpy 与整数 Load 测试，在 Core179 上 **稳定复现失败**（产生 $E^+$ 证据）。
7. **签名分析**：错误数据呈现"字节旋转（Byte Rotation）"特征。
8. **根因收敛与隔离（ACT-1）**：精准锁定故障位于 LSU 的 Load/Store 跨排线/多路选择器微架构结构。诊断置信度 $>95\%$，触发 ACT-1 执行 OS 级 Core179 物理核软隔离。

### 案例 2：诊断失败推演（一致性错误盲区）

1. **现象**：某物理核运行 AES 加密负载时输出偶发错误，ABFT Canary 未捕获（加密输出无冗余校验）。
2. **遥测**：RAS 全程静默（命中 G1），核心集中（命中 G17），30 天内重启 4 次（命中 G20）。
3. **P4 测试**：跨核重执行——验证核与原始核输出**一致但均错误**（一致性错误）。P4 原理性失效。
4. **P6 测试**：AES 为整数运算，标量路径无差分参考。P6 不适用。
5. **P5 测试**：跨天复现 + SMT 同败均满足，**命中 P5**。最终通过 P5 而非 P4 完成定性。
6. **教训**：确定性电路缺陷下，P4 的一致性错误盲区（第十章盲区 1）是系统性的，不是偶发运气——此类场景下 P5 的 Fleet 持续测试是唯一的直接证据路径。

## 十、 诊断方法论红线约束与结构性盲区

### 10.1 不可违反的方法论红线约束
1. **执行上下文主导复现**：SDC 错误显不显现，取决于前导指令序列塑造的微架构/电气 Context（如局部 Vdroop），跟指令使用频率关系不大。单指令轰炸脚本几乎全部复现失败，**必须构造包含前导 Context 的测试序列**。例外是 x87 legacy 超越函数指令（FSIN/FCOS/FPTAN）——它们在同一执行端口上的单指令错误率达 16%–77%（Veritas），单指令反复执行即可复现；但 x87 加减乘除等基本算术指令仍须构造前导 Context。
2. **"校验通过"不可作为排除证据**：若 EC/CRC 校验由向量/FMA 指令加速计算，校验逻辑与数据可能同时被同一硬件缺陷污染（同源污染），**必须引入物理隔离的校验路径**。
3. **OS/内核路径盲区**：OS 参与使 SDC 率相对裸机最高放大 6.7×（Demystifying SVS）。拆开看：内核指令只占总执行指令的 <10%，却对 L1I tag SDC 贡献 77%、对 L1D 数据 SDC 贡献 18.4%（Microarch Perspectives）——内核代码路径是 SDC 的不成比例放大器。Syscall/库路径内的 SDC 没有应用层防护兜底，**不能因为"应用自身校验通过"就排除**，必须由 L2 指令级插桩或 L5 专用测试补位。
4. **应用语义容差**：若输出偏差在应用语义容差内（如 PSNR、小数位舍入、AI 迭代收敛性），**不判为 SDC**。
5. **负载变更不排除故障**：负载变更后症状消失**不可据此排除硬件故障**（存在软件掩蔽或 Context 未触发），必须用原始 Seed 回放复现。
6. **多指令族交叉验证**：同一缺陷可以跨指令类型以相差 6 个数量级的速率致错，**禁止仅凭单一指令族测试锁定故障单元**（参见 ACT-3）。
7. **持续测试必要性**：一次性快照测试必漏间歇/晚发/磨损类缺陷（参见 G28），诊断体系必须内建双轨持续重测机制（ACT-4）。
8. **CRC 边界判据**：CRC 失配仅指示数据搬运途中被改（"数据变了"），无法发现计算过程算错（如哈希表映射计算算错）。**Checksum 类检测对计算型 SDC 存在原理性盲区。**
9. **ABFT 在线检测**：对于矩阵乘法等数值负载可部署 Checksum 类 ABFT（Algorithm-Based Fault Tolerance），使生产负载直接转化为在线检测器，作为上述 CRC 盲区的补充。
10. **沙盒排空原则（CP-2）**：在利用测试框架采集直接证据（特别是 P4 跨核比对）前，必须确保测试运行在纯粹且无软件副作用的沙盒环境中。任何**未隔离的软件状态残留**（如未禁用的中断、未排空的外部 IO、弱内存序残留）均可导致验证核产出同样的"错误"数据，造成硬件 SDC 的假阳性误判。

### 10.2 判定能力边界与结构性盲区
1. **一致性错误（Consistent Errors）**：若电路缺陷在相同输入与 Context 下导致两份副本**错得完全一致**，双执行差分比对（P4）原理性失效。（已登记为 P4 证据卡"假阴性来源"，见 3.1.1）
2. **ESC（输出驻留缓存）旁路**：坏数据直接击中 Modified L1D 中即将输出的数据，经 DMA 直接写回内存/网络，**不经后续程序流**，导致基于程序流的一切软件层检测彻底失效。
3. **主存数据值型 SDC**：PMC/HPC 偏差对主存数据值型 SDC 几乎无痕迹（$<0.3\%$），间接证据 G27 对此类 SDC 存在盲区。此为 SYN-6 的局限性声明。（已登记为 G27 证据卡"假阴性来源"，见 3.2.1）
4. **校验器自身同源污染**：向量/FMA 加速校验时，校验逻辑与数据同源受害导致校验和与坏数据自洽。
5. **PVF/SVF 与全栈 AVF 的失配**：纯软件/架构级评估模型（PVF/SVF）与全栈真实 AVF 结论相反率达 **27–50%**，依赖纯仿真注入矩阵会产生先验偏置。
6. **延迟故障导致 ECC 假性防护**：字线延迟故障可导致 Sense Amp 锁错行且 **ECC 校验仍能通过**（参见 Rule0-5），打破"有 ECC 即无 SDC"的假设，间接证据 G5（无 ECC 保护配置）的排查范围需相应扩展。（G5 证据卡待补，补齐时须将本盲区登记为其"假阴性来源"）
7. **"自愈"异例与晚发变数**：硬件存在"119 次失败后 59k+ 测试零失败"的自愈现象或首测 4 年后才爆发的晚发磨损（参见 G28），单次静态测试无法排除缺陷。

### 10.3 可验证性与校准检查

本框架的判定结论必须可回溯复算、概率输出必须可校准度量、规则集合必须可消融检验——三者构成"可验证性"的最低落地闭环：

1. **案例回溯复算（后验轨迹留痕）**：每个定案案例（确诊/排除）须留存完整后验轨迹——各阶段证据快照、所用证据卡的校准状态、每步测试选择依据（EIG 与成本取值）、后验 $P(H_j \mid E)$ 演化序列、最终阈值决策的 $C_{\text{FP}}/C_{\text{FN}}$ 取值。第九章 CPU179 案例为标准样例：后续案例须能以同格式回放其"Vector FPU 假设 → 零告警定罪 → FPU 全 Pass 后验暴跌 → LSU 假设 → Byte Rotation 签名收敛"的八步轨迹。回放结果与原始结论不一致即为框架缺陷报告。
2. **概率校准检查（可靠性图与 Brier 分数）**：似然引擎输出的后验概率须定期用定案案例集做校准度量——按后验概率分桶统计实际确诊率绘制**可靠性图（Reliability Diagram）**，并计算 **Brier 分数**；校准状态为 fleet-estimated 的证据卡，其贡献的 LR 数字在累积足够定案样本后须重估（升级为 calibrated 或修正数值）。后验 90% 的机器群实际确诊率显著偏离 90%，说明似然表失准而非运气。
3. **规则消融检验（Ablation）**：对 SYN-1–SYN-6 与 2.4 节仲裁规则逐一执行消融——从框架中移除某条规则后，重放历史定案案例集，统计判定结论的改变率。某条规则移除后结论零改变，说明其为纯冗余（可由因果结构推导，见 Step 1 补充节），应降级为说明性文字；某条规则移除后大量结论翻转，说明框架对该规则单点依赖，须评估其自身的假阳性率。
