# 鲲鹏 920 微架构级静默数据损坏注入与规律研究：成果报告

**研究类型**：微架构故障注入实证研究（仿真侧）
**对象平台**：鲲鹏 920（TaiShan V110，ARMv8.2-A，192 核）/ openEuler 24.03
**仿真平台**：gem5 v25.1.0.1（O3 CPU 模型，V110 代理参数）
**数据声明**：本报告每个数字均可溯源至仓库 `artifacts/<campaign>/` 下的 `cells.csv`/`summary.md` 或 commit message 中引用的真实 gem5 输出。全部 P_SDC 为仿真代理条件概率，不换算 FIT。

---

## 摘要

静默数据损坏（SDC）在规模化服务器集群中的发生率约为千分之一核量级，且天然逃逸处理器既有可靠性监控体系：出厂测试通过、部署后间歇发作、发作时不伴随任何架构级 RAS 告警。本研究从一台真实故障机（鲲鹏 920，16 份 vmcore 取证，异常事件 99.5% 收敛于单一物理核 CPU179）出发，回答一个现场无法回答的问题：处理器的哪个微架构单元坏了，以何种机制产生 SDC。

为此我们建成 gem5-fi 平台：19 个微架构注入器覆盖数据通路、地址通路、页表遍历、重命名/提交控制结构、缓存元数据、浮点通路、RAS 记录路径；故障模型覆盖单比特、多位、数据相关触发、驻留故障、合法域替换、相位偏移与校验后通路破坏（F1–F6+PCE）。在 n=384 的 formal 标准（总计约万次仿真运行）下，我们得到首批 ARM64 服务器核逐微架构单元的 SDC 条件概率分布，并落地一套 openEuler 诊断引擎与芯片保护优先级建议。

核心发现：(1) 存储层级存在清晰的掩蔽梯度——L1D 数据阵列 raw 注入 97.7% 转化为 SDC，加 SECDED 后降为 0%（风险反转实证），但校验后回填通路（post-check escape）仍达 90.9%，即 ECC 只保护了一半暴露面；(2) 控制与映射结构（RAT/freelist/IQ/ROB）的故障以崩溃形式响亮暴露（DUE 72–100%），SDC 转化接近零，不需要 SDC 代理保护；(3) 整数执行通路 0/768 阴性，与浮点通路（13.6–69.5%）相差至少 34 倍；(4) 转发相位错开一步以上必然产生 SDC（offset≥1 全部 100%），印证现场观察到的极端时序敏感性；(5) core179 现场的 ESR 0x960000xx 翻译故障家族与 TLB 活页替换注入的仿真分布精确同型。诊断引擎在 16 份真实 vmcore 上回放，输出高置信度判定与现场结论一致（P1–P5 规则全命中）。

**关键词**：静默数据损坏；微架构故障注入；鲲鹏 920；ARM64；gem5；openEuler 诊断；保护优先级

## 1. 研究背景

### 1.1 SDC 的判定困境

SDC 的破坏性体现在两个层面。第一层是直接后果：错误数据进入服务、运算结果静默出错。第二层更基础：在追究后果之前，"这台机器是否存在 SDC"本身长期缺乏可靠、可推广的判定依据。一线工程师面对一台行为异常的机器时，既没有统一标准，也没有足够时间去逐一排除软件缺陷的可能——疑似案例在规模化集群中每天都在产生，而个案经验判断既低效又不可复现。

我们对此的第一步回应是系统化诊断评估：从系统日志、硬件错误记录、核心异常分布等维度对案例做综合评估，用统一可复现的标准取代个案判断。在 100 余个疑似案例中确认出 20 个真实 SDC。

### 1.2 确认之后的深层问题

20 个已确认案例引出更深的问题：SDC 的根本原因是什么？发生在处理器哪个环节、以何种物理机制发生？这是后续能否从根源防范的关键。

具备完整故障现场的案例环境给出了三类与既有研究结论不同的发现（详细取证见 §1.3）：

1. **装载数据返回通路异常**：CPU 从 `__per_cpu_offset[]` 数组加载时，接收到的实际是数组头部槽位内容经字节旋转或错位后的结果（另有全零交付一例），导致 4 次致命崩溃。根因判定为 Fill-Buffer 陈旧条目与写回多路复用器字节通道错位共同作用——无法用传统单比特翻转模型解释。
2. **地址呈现通路异常**：5 次崩溃中 2 次可明确确认，计算出的虚拟地址最高字节（Byte 7）在送入 MMU 之前被硬件强制清零（比对寄存器计算值与 FAR_EL1 得出）。
3. **页表漫游读取通路异常**：73 次虚假翻译错误全部发生在早已建立、从未变动的静态内存映射区域，根因为页表漫游器读取页表描述符时的瞬态数据错误，且均被软件重试机制悄然掩盖。

三类发现有一个共同特征：故障指向处理器中枢与内存子系统的缓冲、队列、路由结构，而非现有 SDC 研究长期聚焦的后端执行单元。这一观察构成了本研究的动机：既然现场取证只能看到故障的"结局"，我们就用微架构级故障注入在仿真中系统性地"重演"各类根因，逐一衡量每个结构的 SDC 脆弱性。

### 1.3 core179 案例：本研究的现场锚点

16 份 vmcore 取证（单机，诚实标注未在第二台健康机复现）确立事实链：

- 异常事件按签名子集统计 216/217（99.5%）收敛于 CPU179，单核浓度远超 60% 判定阈值；
- 5/6 次致命崩溃命中同一指令 `find_busiest_group+0x140`（CFS 调度器负载均衡路径）；
- 寄存器-内存对照实验具有决定性：崩溃时 `x20 = 0xd93715ba0000ffff`（坏值），而 vmcore 中 `__per_cpu_offset[176]` 完好且符合全局等差规律——坏数据不存在于内存，是 CPU 179 在加载瞬间产生的；
- RAS 体系全静默：ghes_edac 32 DIMM 零 CE/UE、rasnode 192 核×5 ERR 节点全零差异；
- ESR 家族 0x96000004/0x96000044（DABT L0 翻译故障），呈现两个子族：零塌缩（x20 读成 0，地址塌缩，FSC=L3）与撕裂移位（字节错位，FSC=L0）。

根因判定为 CPU 179 核内数据通路间歇性硬故障。该案例的每一条签名（ESR 家族、同指令复发、单核浓度、RAS 静默、字节错位形态）都在后续仿真实验中被用作生态效度锚点。

## 2. 研究平台与方法

### 2.1 gem5-fi 注入平台

平台基于 gem5 v25.1.0.1 的 O3 乱序核模型，以 V110 代理参数运行（C2-KP 配置族：ROB 128、物理寄存器 160 int/192 fp、LQ 48、SQ 42、4 发射、2.6 GHz）。共 19 个注入器，按现场三通路与控制结构分组：

| 组 | 注入器 | 单元 | 模式 |
|---|---|---|---|
| core179 三通路 | CHAOSLSQFwd | 转发数据通路 | byte_lane_skew rol1/rol6、all_zero、bitflip、fwd_source_sub、stale_line_replay、phase_offset |
| | CHAOSAddrPath | 地址呈现通路 | byte7 清零（FS 模式） |
| | CHAOSPTW | 页表遍历 | bit_flip、clearValidBit × ptwEcc 开关 |
| 控制结构 | CHAOSRenameMap | RAT | map_bitflip、f5_substitute（合法域偷映射）、f4_field_stuck |
| | CHAOSFreeList | 物理寄存器空闲表 | mark_free、pop_wrong |
| | CHAOSROB | 重排序缓冲 | entry_bitflip、exc_suppress、spec_leak |
| | CHAOSIQ | 发射队列 | src_ready_bitflip、tag_sub、wake_omit/wake_phase |
| 数据结构 | CHAOSPhysReg | 物理寄存器堆 | phys/arch 三模式、F3 数据相关触发、NEON lane |
| | CHAOSCache | L1D/L1I/L2 | 字节级、指令编码位段、元数据字段（tag/valid/dirty/repl/coh）、victim 写回载荷、protectionModel ECC |
| | CHAOSMem | DRAM | 位翻转、地址映射替换、secded、ecc_logic_fault |
| | CHAOSArmTLB | D/i-TLB | 六字段级、pfn 偏移、pfn_to_mapped_page（活页替换）、parity_interleaved |
| 执行通路 | CHAOSFPU | 浮点通路 | 源读路径 IEEE754 位段翻转（sign/exp/mantissa） |
| | CHAOSExec | 整数 ALU | 结果位段（阴性对照） |
| | CHAOSL1DForward | PCE | load 结果校验后翻转 |
| 其他 | CHAOSArmSysReg / CHAOSBPU / CHAOSExMon / CHAOSReg | 系统寄存器/分支预测/独占监视器/架构寄存器 | 白名单注入、结果翻转等 |
| 逃逸元分析 | CHAOSRAS | RAS 记录路径 | ERR* 记录抑制（DUE 变无记录 SDC） |

每个注入器配备 read-trace 能力（注入后目标物理寄存器的消费者计数），用于区分"故障发生"与"故障被消费"两个阶段。

### 2.2 故障模型与逃逸机理

故障模型覆盖七个族系：F1 单比特、F2 局部多位、F3 数据相关触发（模拟欠压建立时间违例在特定位模式上的表现）、F4 驻留故障（write-path 掩码）、F5 合法域替换（指向另一个合法编号/指针/页框——现场"撕裂移位"与"历史残留"的机理模型）、F6 相位偏移（历史条目回退 N 步）、PCE 校验后通路破坏。

逃逸集合按六机理分解：A 无保护结构裸逃逸、B SED 对 2-bit 同奇偶静默、C 3-bit 以上超出 SECDED 能力、D 校验后通路盲区、E ECC 逻辑自身故障（漏检）、F 毒化传播丢失。

### 2.3 实验纪律

所有 formal 实验执行统一纪律：单故障（maxFaults=1）、确定性种子（G0 重放自检，≥5% 重跑校验一致性）、互斥六类/九类分类（SimulatorError > Hang > Crash > Inactive > Masked > SDC，protection-aware 分流 Corrected/DetectedContained/Latent）、Wilson 95% 置信区间。FS 模式实验走两阶段 checkpoint 流水线（boot → 存档 → 逐次恢复注入，单次 13 秒）。

### 2.4 工作负载

20 个定向 kernel 覆盖各注入器语义：矩阵乘（float/double）、迭代 SVD、FMA 归约链、SMULH/ADDS 整数链、间接跳转表、结构体字段、CRC 状态机、store-load 转发探针（movbe）、指针追逐、寄存器链等。每个 kernel 的 golden 均满足 native 与 gem5 无注入输出逐位一致。

## 3. 正式实验结果

### 3.1 存储层级掩蔽梯度与风险反转

L1D 数据阵列上的对照实验（l1d_reduce kernel，n=384 各组）给出完整的掩蔽梯度：

| 通路 | P_SDC [95% CI] | 机理归类 |
|---|---|---|
| raw（数据字节直接注入） | 97.7% [95.6, 98.8] | A（无保护基线） |
| + SECDED（secded_poison） | 0.0% [0.0, 1.0] | 1-bit 全部被纠正 |
| **post-check escape（load 回填段注入）** | **90.9% [87.6, 93.4]** | **D（校验后盲区）** |
| L2 数据注入 | 0.0% [0.0, 1.0] | 工作集驻留 L1，后备被掩盖 |
| DRAM 注入 | 0.0% [0.0, 1.0] | 同上 |

这组数据说明"给 L1D 数据阵列加 SECDED"对单比特翻转确实有效（97.7% 降为 0%，风险反转），但 ECC 校验通过之后到寄存器写回之间的数据段是完全盲区——同一量级的注入在此通路上 90.9% 直接转化为 SDC。保护投资若只覆盖阵列本体，只解决了问题的一半。

### 3.2 缓存元数据字段分化

12 组 × 96 的元数据字段实验（none 与 secded 双保护臂）：

| 字段 | P_SDC（none 臂） | P_SDC（secded 臂） |
|---|---|---|
| **tag** | **100%（70/70）** | **100%（71/71）** |
| valid / dirty / repl / coh / victim | 0%（96/96 各组） | 0%（96/96 各组） |

tag 翻转造成伪命中（false-hit），是唯一高传播的元数据字段；且数据 ECC 对其无效——错误命中的行根本不在数据 ECC 的校验域内。tag 行需要独立的 2-bit invalidate 策略，这是 §5 优先级建议的直接依据。其余元数据字段的破坏全部被掩蔽（valid 清位导致 miss 重取、dirty 翻转被后续写覆盖、替换指针污染被命中路径绕开）。

### 3.3 浮点通路：位段与精度效应

CHAOSFPU 源读 hook 下的 4 精度 × 4 位段 × n=384（共 6144 次）：

| workload | sign | exp | mantissa | all |
|---|---|---|---|---|
| gemm_double | 18.0% | 17.2% | 13.6% | 15.9% |
| gemm_float | 65.8% | 61.5% | 60.2% | 62.5% |
| fma_reduction | 53.9% | 52.3% | 47.3% | 52.9% |
| svd_iterative | 67.2% | 65.0% | 65.1% | 69.5% |

三条规律：其一，float 大约是 double 的四倍——FP32 尾数 23 位，同等位翻转在更窄的表示中占比更大。其二，链式归约（FMA 链每一步将既有误差乘以操作数量级）比矩阵累加高约三倍，归约放大系数得到实测。其三，位段间差异有限（sign ≥ exp ≥ mantissa），尾数低位误差常被累加舍入吸收——这提示窄校验（只覆盖符号与指数）可能已捕获大部分风险。

技术侧的关键发现值得记录：背靠背依赖链（fmadd d0 → fmadd d0）的中间值在旁路网络中流动，从不回读物理寄存器堆——对寄存器堆单元的注入被操作数转发完全击败（15 个种子全部掩蔽）。最终有效的注入点是源操作数读取路径（读即破坏）。这一发现本身说明：注入实验的效度取决于注入点与真实数据流的贴合程度，选错注入点会系统性低估通路的暴露面。

### 3.4 整数阴性对照

整数 ALU 结果位段注入在两个 kernel 上各 384 次：**0/768 全部掩蔽**（整数通路上界 0.4%）。与浮点通路（13.6–69.5%）、转发通路（37.6–90.9%）对比，差距至少 34 倍。"整数路径相对完好"这一现场经验判断在 formal 规模上得到量化确认。

### 3.5 控制与映射结构：DUE 主导

| 结构 | P_DUE | P_SDC |
|---|---|---|
| RAT（F5 偷映射，X3 目标） | 59.7% [54.7, 64.5] | 0.0% [0.0, 1.0] |
| freelist（X3/X9 目标） | 72.0% / 76.9% | 0.0% |
| IQ | 75.3% [70.7, 79.3] | 0.0% |
| ExMon（独占监视器） | 100% [99.0, 100] | 0.0% |

控制与映射类错误几乎全部以重命名不一致、队列状态破坏等形式引发崩溃（DUE），被软件重启与重试机制消化。这一组结构不需要 SDC 代理保护——保护投资应让位于数据通路。这同时修正了一个直觉：无保护结构不等于高 SDC 风险，关键在错误被发现的方式。

### 3.6 转发故障模式矩阵与相位敏感性

LSQ 转发五种故障模式（fp_fwd_kernel，n=64/cell）：

| 模式 | P_SDC | 说明 |
|---|---|---|
| bitflip | 100% | 单比特翻转 |
| structural（rol1 撕裂移位） | 100% | core179 D1 签名的机理模型 |
| phase（offset=2） | 100% | 相位偏移 |
| fwdsrc（错源替换） | 0% | 同址等值数据掩蔽（阴性有机理） |
| stale（陈旧行回放） | 0% | 同上 |

相位敏感性曲线（offset ∈ {1,2,4,8} × n=384，共 1536 次）：**全部 384/384 SDC = 100%**，而 offset=0（正常转发）对应健康 golden 的零失败。相位错开一步与错开八步没有差别——转发命中的历史窗口是剃刀般窄的，错开即必错。这从机理上解释了现场观察到的极端时序敏感：在复现实验中插入一条 no-op ALU 指令即可将触发率从 100% 打到 10–20%。

### 3.7 PRF 与 read-trace

X3（数据累加器角色）八个位段 cell 全部 96/96 SDC = 100%（饱和，补样无统计增益）；readtrace formal 同 100%，且 P(SDC | reads>0) = 1.000，注入值被读取的中位次数约 197.5 万次——状态泄漏窗口的实测跨度。RAT/ROB 的 read-trace API 已落地：RAT F5 注入后坏映射的消费者计数从 0 变为 1 的传播瞬间被直接观测到。

### 3.8 TLB 活页替换（FS 模式）

两阶段 checkpoint 流水线下的双模式实验（各 n=32）：

| 模式 | oops（DUE） | ESR 分布 |
|---|---|---|
| pfn→活页（F5） | 19/32（59.4%），13 次静默 | 86000004×12、96000005、96000006×3、96000047、9600004f |
| pfn→未映射 | 25/32（78.1%） | 主导 86000004（取指侧 L0） |

活页替换注入产生的 ESR 家族与 core179 现场分布精确同型（0x960000xx DABT 翻译故障族，L0/L1/L2/L3 层级混合）——这是"现场故障 ← → 仿真机理"对照中最强的一条锚点。合法域压力验证：8400 万次注入零次模拟器错误。parity_interleaved 保护对照：同种子同注入，无保护组 guest panic，保护组恢复原值并使条目失效重走，系统继续正常运行。

### 3.9 逃逸机理分解

| 机理 | 数据 |
|---|---|
| A（无保护裸逃逸） | 3282 事件（乱序后端确证） |
| B（SED 对 2-bit 静默） | 384/384 静默 |
| C（≥3-bit 超 SECDED） | 384/384 静默 |
| D（post-check 盲区） | 90.9% [87.6, 93.4] |
| E（ECC 逻辑自身故障） | 同种子同注入对照：secded 纠正（0x0→0x0）vs ecc_logic_fault 漏检（0x0→0x80） |
| F（毒化传播丢失） | 无 formal 数据（deferred，需 secded_poison × 多位档 campaign） |

E 机理的对照实验值得单独说明：同一种子、同一注入事件下，正常 SECDED 将 1-bit 错误恢复为原值，而 ECC 逻辑故障模式让同一错误原样通过。保护机制自身成为单点故障时，其危害不是保护失效，而是虚假的安全感。

### 3.10 假设表终态

研究预登记的假设体系（H0–H8+）判定：H1（消费者计数决定 AVF）PRF 侧确认；H5（字节相位复现现场签名）、H6（AGU byte7）、H7（PTW ECC 对照）已闭环；H0 部分确认并需拆分表述（数据结构裸逃逸成立，控制结构 DUE 化）；H2（窗口深度梯度）不可分辨——ROB 96/128/160 三档全部饱和，梯度为零，诚实标注需要未饱和 cell 重测；H3（RAT/PRF 同路径）机制就位待 formal；H4（大 L2 驻留）未检验（工作集驻留 L1，需更大 kernel）。

## 4. openEuler 诊断引擎

诊断引擎三件套加集成 CLI，全部落地为可执行工具：

**ESR_ELx 解码器**（esr_decode.py）：27 类异常类型解码 + DABT ISS 全解（WnR/ISV/SAS/SRT/FSC 翻译级别）+ SDC 相关性权重（1–5 星，按文献参考比率）。验证锚点：现场签名 0x96000044 解码为 DABT、WnR=1、FSC=L0 翻译故障，权重四星——与报告中的现场取证完全一致。pytest 7 用例全过。

**日志解析器**（logparse.py）：vmcore-dmesg / journalctl -k / rsyslog messages 三形态归一；提取事件类型、CPU 号、ESR、FAR、pc/lr 符号、寄存器组、调用栈。16 份真实 vmcore 全量解析：签名子集（spurious 翻译故障 + 致命 Oops）235 个事件，可归核事件 216/217 = 99.5% 收敛 CPU179，同指令 `find_busiest_group+0x140` 跨案复发 17 次。伪造均匀分布日志正确判为软件（N1 排除路径）。

**七步法判定引擎**（sdc_diagnose.py）：Top-N 筛选 → 重启异常 → RAS 静默验证 → 核心浓度 → 异常类型加权 → 维修历史 → FA 确认；P1–P11 正向规则与 N1–N10 负向规则（任一负向命中即排除）；四级置信度输出。core179 六案回放：输入 16 次非计划重启与 RAS 静默证据后，引擎输出高置信度（P1 91.9% 浓度、P2 多应用、P3 重启频率、P4 0x960000xx 类型命中、P5 RAS 静默，N3 未命中），处置建议为立即下线该核并送 FA 分析——与人工深度取证结论一致。

**指纹库集成 CLI**（spectrum_triage.py）：现场位谱 → Top-K 候选微架构单元（附各单元 P_SDC 先验与特征日志签名建议）→ 联动日志侧裁决。指纹库留一法验证：76 事件 Top-3 命中率 100%（验收线 60%），Top-1 34.2%（单比特注入多位落于尾数区，区分度有限，如实呈现）。

**method2 三根因打分表**：现场观察到垃圾指针 + 翻译故障形态时，用三个高区分力判据区分候选根因——损坏值模式（随机多位指向寄存器堆、结构性 byte7=0 指向地址通路、值域落在合法页框指向 TLB）、FAR 规范性（非规范指向地址通路；规范但走表失败指向 TLB；寄存器算术派生且源坏指向寄存器堆）、DFSC 层级分布（恒 L0 指向前两者；L0/L1/L2/L3 混合指向 TLB——此预测已被活页替换实验的 ESR 分布证实）。

规则库版本化（rules/flight-rules.md v1.0.0）：正向/负向规则与置信度分级同引擎实现严格一致；formal 先验（浮点位段四组、LSQ、PRF）回填为规则依据。

## 5. 芯片设计建议

### 5.1 保护优先级排序

按风险 = 可达性 × P_SDC 降序的八级排序（数据驱动版）：

1. **L1D load 回填通路**（90.9%）：校验后数据段完全盲区，代理保护表中无对应行——建议回填段端到端重校验或 load 数据 CRC 预测；
2. **L1D 数据阵列**（raw 97.7%，SECDED 实测反转至 0%）：阵列 SECDED 有效，维持；
3. **store→load 转发错源**（37.6%）：转发命中 ID 比对（CAM 冗余）+ 转发数据 parity；
4. **浮点通路**（13.6–18.0%）：结果 parity 或仅覆盖符号+指数的窄校验；
5. LSQ 转发（4.7%）、PRF（~10%，cell parity 可选）；
6. DRAM（SED 家族对 2/3-bit 静默——SDEC/ChipKill 升级评估 + ECC 逻辑 BIST）；
7. 控制结构组（RAT/freelist/IQ/ROB，DUE 主导）：免 SDC 代理保护，交由重试与 RAS 上报。

### 5.2 保护表差距分析

与 Neoverse N1 TRM Table 9-1 代理表逐结构对比后的结论：最大盲区不在保护强度而在覆盖范围——回填通路与转发通路在表中没有对应行；ECC 逻辑自身故障是所有 secded 行的共同横向风险（BIST 建议）；五项依赖 V110 RTL 细节的推断（E4 级）全部归入待校准清单，不进入设计建议正文。

### 5.3 DFT 向量包

五个向量（RAT 历史残留、地址通路 byte7、LSQ 位谱、撕裂移位 rol1、ECC 逻辑故障）连同触发条件、健康/次品签名对照打包为可执行测试套件（dft/ 目录）。端到端批跑验证：基线 golden 一致，四个可执行向量全部复现次品签名。向量包面向产线与现场筛查，签名全部来自真实仿真输出。

### 5.4 机制级建议

抗状态泄漏（空闲表归还前活性校验）；抗相位竞争（转发决策与数据组装分列不同流水级）；抗校验后逃逸（check-after-path parity）；抗合法域替换（指针/编号字段 range-check）。每条建议都对应本平台中可复现的注入实验证据。

## 6. 生态效度

仿真结论与现场证据之间建立了 18 个以上的对照锚点，全部通过：golden 基线逐位一致；GPR 注入产生与现场同型的状态泄漏窗口（读取 12.5 万次未覆写）；F5 偷映射在长存活累加器上产生失败计数（Fisher 精确检验 p = 1.19e-71，numeric 与 compute-both 两臂分离显著）；撕裂移位 rol1 的 XOR 多位散布形态与现场汉明重量方向一致；PTW clearValidBit 产生 BecameInvalid 记录；TLB pfn 偏移产生预期翻译故障等。

最强的两条锚点：其一，TLB 活页替换的 ESR 家族分布与 core179 现场精确同型（§3.8）；其二，转发相位敏感性解释了现场复现实验的时序脆弱性（§3.6）。指纹库（LSQ 转发 mantissa 份额 0.7121）与现场位谱方向（浮点尾数占比 85–93%）一致。

## 7. 诚实边界

1. gem5 O3 是行为级代理，不是 V110 RTL——统一 IQ 与分布式调度器、无分区 L3、无片间互连的周期精确模型，绝对值标 E3 证据等级；
2. 全部 P_SDC 为条件概率（给定故障发生的条件下转化为 SDC 的比例），无原始器件故障率，不换算 FIT；
3. 现场证据来自单一故障机，未在第二台健康机复现（"单机结果，未确认"）；
4. SE 模式无 MMU 翻译，TLB/PTW/AGU 实验依赖 FS checkpoint 流水线覆盖；
5. 阴性结果如实呈现：整数通路 0/768、fwdsrc/stale 的有机理阴性、H2 窗口梯度不可分辨、指纹库 Top-1 区分度有限；
6. 环境门控项显式登记：系统级片间互连注入（约 20 个补丁的独立子项目）、健康机复现、实机 RAS 校准、毒化传播机理（F）formal 等，各带原因与解锁条件。

---

## 8. 结论

本研究以一台真实故障机为起点，建成 19 注入器的微架构故障注入平台，以万次量级 formal 实验产出首批 ARM64 服务器核逐微架构单元的 SDC 条件概率分布。三条设计规律最为突出：数据通路三件套（回填段、阵列、转发）构成最大暴露面且 ECC 只覆盖其中一半；控制与映射结构虽然无保护但其故障以崩溃形式自暴露，不需要 SDC 代理投入；ECC 家族的边界（多位静默、逻辑自身单点故障）与保护表覆盖范围盲区，是比保护强度更值得优先解决的问题。

产业侧产出：openEuler 诊断引擎（16 份真实 vmcore 回放与人工结论一致）、指纹库与三根因打分表（现场位谱反推候选单元）、DFT 向量包（产线筛查）。研究闭环由此形成：现场取证定位故障形态，仿真注入复现机理并量化规律，规律反哺现场诊断与芯片设计。
