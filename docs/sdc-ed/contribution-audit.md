## 一、六维度设计合理性审计

### 1.1 平台（论文：FPGA+gem5 双轨 / 本仓库：gem5+合成网表）——**部分合理**
- 合理：网表三层等值验证（1700 万向量+全程序）弥补无 RTL；19 注入器
  全谱超论文六点
- 弱点：P1-E1 的「仿真↔硬件 transferability」是论文的**立论基础**，
  本仓库只能引用不能复现（无 FPGA，环境门控登记）——我们全部结论的
  适用域因此限定在 gem5 层，向真硬件外推依赖论文已证的前提
- **判定：可接受的降级，但必须在贡献声明中显式承认**

### 1.2 故障模型（论文：6 注入点 / 7 结构 / 本仓库：19 注入器+双面）——**强，超出论文**
- **L2C tag/data 双面分账**是论文没有的洞察：tag 面 ECC 盲
  （ρ=0.50 [0.36,0.64]）vs 数据面 SECDED 全修（ρ=0.00）——CI 无重叠
  （6.1 标定，271425de）。「同一个缓存两张脸」直接改写了覆盖目标的
  优先级（tag 面才是 SDC 高危面）
- µop（P1-i）无对应——登记

### 1.3 度量设计（论文：结构内标量 / 本仓库：ED 聚合）——**ED 聚合层设计有实证缺陷**
- CE-1 正面对比（18 序列×3 臂）：论文 ACE AUC 0.60-0.67 **>
  ED 0.51-0.55**（27238030）——ED 的连续排序能力被自己的对比实验证伪
- 四个度量层缺陷全部定位并登记：wrapper 底噪、max(l1d,l2c) 钝化、
  **足迹盲区**（conflict_seq ED 中游但 tag 检测 0.41 全场最高）、
  evolve 分母耦合
- **但 ED 作为定向生成目标有效**：R2 J1（ED 定向组 24 倍于对照组，
  CI 零重叠）+ J3（lift 集中在 ED 预测的 L2C 轴）——ED 的正确角色
  是「下一步生成什么」的决策变量，不是「这条序列排第几」的排序度量
- **判定：设计意图（聚合加权）合理，实现层四个缺陷是真实的工程债；
  贡献叙事必须按"定向有效/排序未证"重写**

### 1.4 实验协议（论文：K×N / 本仓库：预注册+双口径+Wilson）——**强，方法论超越**
- 预注册判据纪律：R1 三判据失败不改判据（负结果入档）→ 归因 →
  R2 按归因补齐（N=400+定向池+l2c 臂）→ J1/J3 显著通过。
  **「归因驱动的两轮实验闭环」是论文没有的方法论贡献**
- 负对照实验（dead_read：写后读但读喂死链）驱动度量设计修正两轮
  ——论文无此严格性实践

### 1.5 序列池（论文：MuSeqGen fuzzing / 本仓库：模板+定向）——**弱项，如实**
- CE-3：臂间 Spearman 0.86-0.92——**池多样性不足**，无法复现论文
  P1-E3 的互补剖面结构；H 组同质（tag 0.23-0.26 窄带）
- 根因：定向生成能力单一（l2c 窗口模板）；evolve 的 advice 规则
  有起点敏感性
- **判定：这是当前对论文贡献差距最大的一维——生成器多样性是
  Round 3 的第一优先**

### 1.6 验证闭环（论文：相关性+对比曲线 / 本仓库：+三判据+AUC 正面对比）——**超越**
- 论文只验证自己的度量与检测相关；本仓库把**自己的度量与论文度量
  放进同一池正面对比并接受落败结果**——这是对论文方法的独立验证
  （ACE 标量在第三方的 AArch64/鲲鹏配置上仍然成立，本身就是对
  论文可复现性的新证据）

## 三、与论文的最终定位

```
雅典大学 Harpocrates（P1+P2）     本仓库（SDC-ED 工程）
─────────────────────────      ─────────────────────────
方法论根基：                   独立验证+扩展：
  HIL 程序生成合法性（FPGA）      ✓ ACE 在 AArch64 成立（C6）
  覆盖度量（ACE/IBR）            ✓ 全复现+更强处（种子/截断）
  advice 进化                    ✓ 复现 18.8×
                                新贡献层：
                                  数据流可达（C1）
                                  故障物理标定（C2）
                                  配置驱动（C3）
                                  部署口径（C4）
                                  实验方法论（C5）
                                待修层（诚实）：
                                  ED 排序（CE-1 FAIL）
                                  池多样性（CE-3 FAIL）
```

**一句话定位**：本仓库站在论文的方法论根基上（复现全过+独立验证），
在论文未覆盖的四个维度（数据流可达/故障物理/配置驱动/部署口径）
做出了实证成立的贡献；ED 聚合度量作为排序器的失败由我们自己的
对比实验发现并如实报告——这本身是 C5 方法论的实践。

## 四、Round 3 路线（由本审计导出，按贡献修复杠杆排序）

1. **ED 排序修复**（补 C7→C1 档）：l2cAvf 独立归并（去 max）+
   wrapper-only 基线差分 + 足迹分量（活跃页数>L1D 跨度）入 L2C 轴 +
   evolve 绝对量 fitness——四缺陷逐一修，重跑 CE-1
2. **池多样性**（补 CE-3）：多模板生成器（int/FP/mem/分支/前转五轴
   独立定向）→ 重测互补性
3. 修好后重跑 R2 裁决 + CE-1（预期 J2/AUC 双过）
