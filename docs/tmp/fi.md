1. SDC 问题根因分析与案例研究
	会议重点讨论了在特定故障环境（第179核）下复现的静默数据损坏（SDC）问题，目前通过三种测试用例稳定复现，并初步归纳了错误特征与潜在根因：
	•	Case 1：访存读取异常（主要关注点）
	o	现象：程序从只读原始数组读取数据，经字节交换写入结果数组后，再次读取原始数组同一位置，发现数据不一致。
	o	特征：读出的错误值并非随机比特翻转，而是历史数据残留。9次复现中，5次为完整32位数据被替换为历史值，4次为字节级别的拼接异常。
	o	排查进展：已排除“Store-to-Load Forwarding”（存储到加载前递）错误，因为错误数据均源自原始数组的历史位置，而非刚写入的结果数组。
	o	潜在根因假设：
		1.	缓存/缓冲区残留：缓存中保留了旧数据，导致读取到历史值。
		2.	寄存器重命名错误：在高压乱序执行下，寄存器重命名机制出错，导致多个变量共享寄存器，引发读写异常。
	•	Case 2：数值精度偏移
	o	现象：稀疏矩阵乔列斯基分解测试中，256个解向量元素同时出现偏差。
	o	特征：符号位和指数位基本不变，变化集中在尾数低位，表现为计算精度轻微偏移，而非数据被无关数据替换。
	•	Case 3：寄存器非法值
	o	现象：STL压测中，特定寄存器（如x10, d0）出现非法大值，导致Panic。
2. 技术路线与对比分析
	•	ARM vs x86 架构差异：
	o	ARM采用精简指令集（RISC），指令定长，前端解码压力小，但中枢（Out-of-Order Engine）面积大、复杂度高。
	o	ARM具有弱内存序特性，乱序执行压力约为x86的1.5-2倍，寄存器文件更大，映射更复杂。
	o	推测：SDC问题更可能出在ARM架构中更复杂的中枢部分（如乱序执行缓冲区、寄存器重命名逻辑），而非前端。

		o	目标：验证上述根因假设，形成“猜想-验证”闭环。
