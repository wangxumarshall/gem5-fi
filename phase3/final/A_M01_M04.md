## 4. M04 — the REAL committed wrong-PA consumer

From `runs/TEST-M04-FR01/Trace/prop_evt.txt.gz` and
`workloads/mmu/W12/mmu_w12.c` (+ disassembly):

1. Fault activation happens on a **warm-loop** target load at
   `pc=0x400d00` (the `sink += pt[0]` loop, source line 183): EV 629 activates
   on dtb entry 82 gen3276, EV 631 returns PA 0x83557000 (decoy PFN 0x83557),
   EV 632 consumes it, EV 634 result, EV 635 lsu, EV 645 memory_response,
   **EV 646 squash**. That instruction is the speculative next-iteration load
   after the loop-exit branch mispredict; it never commits.
2. The earlier target load `seq=105378213` at the same PC committed with the
   **correct** PA 0x8353e000 (EV 641 commit).
3. After the loop exits, the context-specific access executes:
   R01 `ldrb w0,[x25]` @**pc 0x400d3c**, R02 @0x400de4, R03 @0x400dbc,
   R04 @0x400e10 (then a second load @0x400e18), R05 the JIT call path.
   These are **warm DTB hits** on the mutated entry 82/3276, so they read
   the decoy frame and produce `observed=0x51` (MARKER_D). That is the REAL
   committed wrong-PA consumer.
4. It is invisible to the trace: `TLB::lookup()` only opens a translation
   transaction for misses/activation; a plain DTB hit has no txn for its
   `seq`, and `CHAOSPropagation::mmuNoteLookup` returns 0 without a txn, while
   `mmuNoteMemResponse`/`mmuNoteCommit` require the seq in `mmu_traced_seqs`.
   Consequently `_cross_dynamic_wrong_commit()` is false and summary EV 686
   says `writeback_event_id=0 commit_event_id=0`. There is no target-VA event
   after EV 646.
5. The alias path is the same decoy frame: `mprotect`/`mmap` of the decoy VA
   0x400a000000 maps PFN 0x83557 (MARKER_D 0x51); EV 630 records the
   cross-layer `corrupted_entry_alias` (old_pa 0x8353e000 → new_pa 0x83557000).
   The legitimate decoy-VA load (seq 105378218, commit EV 649) is not the
   wrong-PA consumer.

### Decision: (b) C++ observability join, not (a) workload restructuring
(a) is not applicable: the architectural consumer **does** commit on its
first architectural execution; the defect is that a warm-hit commit is not
traceable. Forcing a re-translation (DTLB eviction) would change the M04
model from "warm hit" to "cold miss" and is therefore not allowed. The
minimal fix is an observability join for hits on a registered fault entry.
