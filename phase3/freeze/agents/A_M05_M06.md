### 1.5 Admissibility of the stored terminal

**Not admissible.** Authoritative `MMU_Terminal_Oracle.csv`:
`ACTIVATED_MASKED,"Faulted state consumed but overwritten/unused/equal value with
proof", activation + overwrite/consumer + oracle equal`. Consumption is mandatory; here
the entry is invalidated before any consumer. Record it as an activated-not-consumed
coverage gap (no exact 10-state entry; `INJECTION_NOT_ACTIVATED` is factually wrong since
the state change happened), or redesign W13 so it is consumed.

### 1.6 Minimal workload change that yields real consumption (no C++)

* Map a second 4 KiB page in each 2 MiB region: target alias `0x4010001000` (L3 index
  1) and decoy alias `0x4010201000` (index 1 of decoy L3 table `0x81c1f000`), filled
  `MARKER_T`/`MARKER_D`. MAP_POPULATE creates PTEs but no TLB entries.
* After warm-up (activation done) and **before** the mprotect, run the context's
  consumer access on the alias page with **no TLBI**: it misses the complete entry,
  hits the corrupted partial (`0x81c1f000`), resumes L3 at index 1, reads the decoy
  leaf → `0x51` → real consume → SDC. R05 needs code aliases and `ft_alias()`.
* Instruction forms are unchanged; only the consumer VA moves one page inside the same
  region. The validator's M05 proof only needs a later partial hit `pfn==after` plus
  `pte_read/decode` at `after`'s 4K page (`mmu_formal_validate.py:658-712`). Riskier
  alternative: evict only the complete 4K entries while keeping the partial
  (dtb=32, l2_shared=1280/5-way) — not deterministic.

## 4. Genuinely impossible vs fixable

**Impossible without changing fault-model/context text**: M05 consumption in R01–R05
"after leaf-only TLBI" (no last-level TLBI is emitted; all observed TLBIs match partial
entries, `tlbi_op.cc:239…`); making the substitution hit the origin walk. **Fixable by
workload (Agent C)**: M05 fresh alias-page consumer without a TLBI (1.6) plus code
aliases for R05; M06 R02 printf-after-store and/or pre-store PROT_NONE→RW mprotect
(2.3). M06 R03/R04/R05 already pass.

**Fixable by harness/trace C++ (no injection semantics)**: M05 R05 Execute-mode
transactions/fault tagging (1.7); validator `consumption_event_id=0` when NOT_CONSUMED;
runner waits for trace close before validating (M06 R05B race). **Not fixable by
flush/timeout tuning**: M05 R04 is a squashed wrong-path origin; R05's entry dies under
the guest's TLBIMVA/TLBIASID before any fetch.
