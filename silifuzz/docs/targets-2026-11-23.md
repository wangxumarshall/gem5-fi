# 目标驱动的 SiliFuzz 生成（ARM64，2026-11-23）

第三套配对方法：**先给每个模板定义代理覆盖目标，再让代理朝目标生成，优先流长**。
与前两套的区别：

| 方法 | 生成端 | 定向方式 | 产出 |
| --- | --- | --- | --- |
| `tools/pairgen.py` | 限制词表 + 寄存器分区 | 生成时 | 类覆盖 100%，但分布不是 SiliFuzz |
| `tools/pairgen_paper.py` | 零定向（原文） | 事后选流 | 2–4 条指令的区域内碎片 |
| `tools/pairgen_target.py` | 零约束，但按目标重播种 | **目标 + 轮次进化** | 20 条流中 18 条 60–256 条指令 |

## 1. 目标怎么定义

```
Target_cap(T) = ( ∪_{w∈T} F_cap(w) ) \ F_cap(nop)
Target_uc(T,S) = ( ∪_{w∈T} F_uc(w | S) ) \ F_uc(nop | S)
```

- `F` 是代理二进制内部被置位的 SanitizerCoverage 计数器集合，由 `tools/covfingerprint/`
  直接读回（与 libFuzzer 同一套插桩）。
- `F_cap`：插桩 Capstone 解码单条指令（对应论文的 XED 代理）。
- `F_uc`：插桩 Unicorn 在**场景初态** `S` 下执行单条指令（`covdrv_unicorn_one.cc`）。
- 场景按模板族指定：`c/l → centered`、`e/o → small`、`f → fp1`（1.0）、`i → branch`、
  `m → mem_unmapped`（触发缺页路径）、`v → vec_sat`（全 1）。

规模：Capstone 目标 38–103 个块，Unicorn 目标 112–362 个块（逐模板见
`evidence/targets-2026-11-23/targets/*.json`）。

## 2. 生成机制（诚实描述）

不是"掩码式覆盖"，而是**目标驱动的轮次式语料进化**：

1. 种子：Capstone 侧用模板的每条指令（4 字节），Unicorn 侧用模板 `.text` 及其 1×/2×/4×/8×
   重复体（给 fuzzer 一个长起点，`-len_control=0 -reduce_inputs=0` 保持长度）；
2. 每轮跑 Capstone 45 s + Unicorn 180 s（10 路并行）；
3. 每轮结束后按 (目标达成, 纯度, 长度) 打分，把最好的 400 个作为下一轮种子；
4. 共 3 轮。

libFuzzer 自身的覆盖率反馈**未改动**；"定向"来自目标定义 + 重播种 + 事后筛选。

两道防作弊闸门（否则会交付种子而不是生成物）：

- 排除"模板本体或其无限重复的前缀"（`seed_like`）；
- 要求流里至少有一个模板中不存在的编码（确实被变异过）。

## 4. 差距：c1 与 v5

`status=gap` 的两条无法产出"长 + 区域内 + 能跑完"的流。可执行前沿（纯度≥0.8 且跑到末尾的
最长流）只有 **1** 条指令，原因是代理词表的操作数把 **x0 同时当数据寄存器与基址寄存器**：
模板自身的 `movk/add` 一旦写坏基址，后续访存立即缺页，长流必然早崩。

这也正是第一轮 `pairgen.py` 必须做寄存器分区（`Rn` 固定 x18–x25、且不写这 8 个寄存器）的原因：
不分区就没有长流。若允许这一条扩展，这两个模板可以补上；本轮按"只做目标定向、不改词表"的口径，
所以如实留空。

## 5. 复现

```bash
cd silifuzz
python3 tools/pairgen_target.py targets --work work/target-YYYYMMDD
python3 tools/pairgen_target.py fuzz    --work work/target-YYYYMMDD --rounds 3 \
        --cap-seconds 45 --uc-seconds 180 --keep 400 --jobs 10
python3 tools/pairgen_target.py fix     --work work/target-YYYYMMDD --fix-candidates 900
python3 tools/pairgen_target.py select  --work work/target-YYYYMMDD --min-hit 0.6 --min-purity 0.8
python3 tools/pairgen_target.py verify  --work work/target-YYYYMMDD --cores 0-127
python3 tools/pairgen_target.py report  --work work/target-YYYYMMDD --copy-to <dir>
```

## 6. 边界

- 目标口径是**代理代码区域**（Capstone 解码路径 / Unicorn 执行路径），不是硬件结构；
  Unicorn 侧覆盖率被 TCG/派遣代码主导，信号弱（命中率普遍 1.00 是因为流很长、覆盖了目标全集）。
- 重播种属启发式定向，不保证单调收敛；每轮的目标达成数字见 `work/.../pool.jsonl`。
- 内存族（c/l/m）的修复用 `--centered-data --data-pages 16`（快照初态的场景化），其余族用默认初态。
- 与原文的距离：目标是本项目定义的、生成靠重播种，不是论文方案。
