# 指令流 vs 模板：ACE / IBR 结构指标（gem5-CHAOS O3，kp920 proxy）

两份语料用同一套测量工具、同一套初态约定，只有指令序列不同：

- **定向流**：`work/target-20261123`，20 条流（1–256 条指令，中位 251）
- **原文口径流**：`work/paper-20261123`，20 条流（2–4 条指令，中位 2）

## 1. 怎么量的（不读这节，数字会被误读）

SiliFuzz 快照是裸指令字节，不是程序。工具 `tools/aceibr_compare.py` 把一条指令序列编成一个 gem5 SE guest：

```
m5_work_begin(7,0) → [ 寄存器装载; N × (指令块) ] → m5_work_end(7,0)
```

`m5_work_begin` 复位统计、`m5_work_end` 落一次 dump，所以 **`stats.txt` 的第一个 dump 就是 ROI 窗口**（第二个 dump 是 printf/exit 的尾声，已排除）。两侧都跑约 6 万条动态指令，并用**同迭代数的空块 guest 作基线相减**，扣掉 34 条/迭代的骨架。

**归一化（逐条记录在 `guests.json`）**：

| 规则 | 处理 | 为什么 |
| --- | --- | --- |
| 控制流（b/bl/cbz/ret/brk…） | → `b .+4` | 不离开测量块，且保留分支端口占用（换成 nop 会把这些搬进 intAlu，污染 IBR） |
| 特权/用户态非法（svc/msr/mrs/dc/ic…） | → `b .+4` | EL0 执行即故障，gem5 SE 会整场中止 |
| 写 SP | → `b .+4` | 测量循环需要活栈 |
| 访存基址寄存器 | → x19（64 MiB 数据窗口） | 否则模板算出来的地址立刻缺页，长访存流根本测不了 |
| 宿主仍判未分配的编码 | 按位剔除并记录 | 不可执行的字只会得到 SIGILL |

寄存器初态两侧完全一致：x0–x29 指向 64 MiB 零页、4 KiB 步长居中；d0–d7 = 1.0/2.0/0.5/−1.0/3.0/1e−8/1e8/1+1e−7。每次迭代重新装载，等于「同一初态下的重复回放」，不让一次执行的状态漂移污染后续。

**指标定义（这就是本仓库 gem5 模型里的定义）**

- ACE = 物理寄存器堆/L1 中被访问值的**生命周期占用**：`intAceRatio = ACE bit-cycles / (物理寄存器数 × 位宽 × 窗口周期数)`。表中「RF 条目」「L1D 行」分别是 `ΔregCycles/窗口周期` 与 `ΔlineCycles/窗口周期`，即**平均被覆盖的寄存器条目数 / cache line 数**，与窗口长度无关；「ACE(净)」= 模型比例 × `ΔbitCycles/bitCycles`，扣掉骨架后的份额。
- IBR = `ports[FU] × 操作数位宽`（`src/cpu/o3/fu_ibr.cc:136`），即**每条发射指令的结构性输入端口位宽**，**不是数据相关翻转率**：intAlu 2×64=128、madd 3×64=192、标量 fpAdd/fpMult 2×32 或 2×64。所以 IBR 的判别力在**单元占用分布**，`bits/op` 只反映源数与位宽构成。

读法：

- **定向流的结构占用超过模板本身**（RF 条目 3.0→6.8，L1D 行 5.0→7.9）：因为一条流把模板的指令混入了更多样的寄存器与地址，构造上就比模板「压得更满」。
- **原文口径流只有模板的零头**（RF 条目 3.0→0.6，L1D 行 5.2→1.2）：2–4 条指令能碰到的东西本来就少——这与上一轮「区域覆盖 0.13–0.50」的结论一致，只是这里换成了硬件结构口径。
- 注意方向：ACE/IBR 高 **不等于** 更容易检出 SDC。它只说明结构被压得更狠；能否变成 SDC 还要看故障注入与传播（Phase 2 的结论：FP 累加流上 H1–H3 未获支持）。

## 6. 边界与已知偏差

- **c1 / v5 的流只有 1 条指令**（gap 模板）：RF 条目 3.0→0.0 / 33.1→0.0，IBR 128→64.4 / 128→106.7，是单指令与 26/42 条模板的结构差异，不能读成「流更差」。
- **e1 的流有 38%（69/180）编码被宿主反汇编器判为未分配**：它出自 Capstone 语料（字节级变异），此前按「可解码指令」算的纯度 0.80 并不覆盖这 38%。剔除后测的是剩余 111 条有效指令。
- **访存基址改写会压低地址多样性**：所有访存都落在 x19 附近 64 KiB 窗口内，所以 L1D 行数反映的是「不同偏移」而非快照原本的 7 个数据页；对模板和流是同一处理，横向可比，但不能当作快照原貌。
- **ACE 的减法只是份额缩放**：模型的分母（物理寄存器数×位宽）在 stats 里不可见，净比例按 bit-cycles 份额折算，属近似，故主指标用「条目/行」而不是比例。
- **IBR 不是翻转率**：本仓库 fuIbr 计的是端口×位宽的结构量，与 Harpocrates++ 的「输入位翻转占比」不是同一个量，不能与文献数值直接对比。
- 单线程、SE 模式、kp920 proxy、2 GHz；不含功耗与频率维度。
