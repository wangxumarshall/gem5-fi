# 限制与偏差（诚实记录）

本文件列出 `silifuzz/` 相对论文的真实差距。所有“已实现/已测量”的陈述以
`evidence/` 中的命令输出为准；没有真实缺陷检出，也没有生产机群数据。

## 1. 环境规模

- 只有 **1 台** aarch64 主机（Kunpeng 920，128 核，4 NUMA 节点，无 SMT），
  没有 Google 生产机群、没有第二台机器。`sdc-0102` 在本会话内 SSH 不可达。
- 论文 §2.5.2 的“机群中随机选机器、预留 4 核（2 个 HT 对）、最多 2 分钟、
  窗口最终覆盖所有核”在本机只验证机制：`fleet.py` 用 4 个物理核、120 秒、
  轮转 32 个窗口。没有生产作业调度器集成，也没有跨机器结果汇总。
- 论文 §2.6 的“同一核多日复现”用同一会话内多次独立复测代替；没有隔离机、
  没有变频/变压/变温测试。

## 2. ISA 与缺陷模式

- 论文目标是 x86-64：XED、SDE、`0xCC` 陷阱、x87/向量指令、附录 A–D 的
  F2XM1 / illegal-instruction overshoot / FCOS / x87 data pointer 缺陷。
  本实现按 `AGENTS.md` 改为 **ARM64**（Capstone、Unicorn ARM64、`BRK #0`），
  附录 A–D 的 x86 缺陷**没有复现**。
- 没有 SDE（Intel 软件模拟器）作为独立参考；差分只在真实 ARM64 核之间做。
- 本机没有 SMT（`thread_siblings_list=0`），无法复现论文“70% 缺陷影响同一
  物理核的两个逻辑核”的归属统计。

## 3. 代理与语料

- 代理映射：XED→Capstone、x86 ifuzz→syzkaller ifuzz ARM64、x86 Unicorn→
  Unicorn ARM64。代理的覆盖率含义不同，**不能**把本实现的覆盖率与论文的
  XED/Unicorn 覆盖率直接比较。
- 语料规模：见 `docs/measurements.md`；未能证明达到论文的约 500,000 条
  同等质量语料。ifuzz 序列可批量生成，但代理 fuzz 时间有限（每个目标数分钟）。
- 没有做论文 §5 提到的语料蒸馏（corpus distillation）与跨代理交叉授粉的
  系统评估；只有按内容哈希去重。
- 快照初态由内容哈希生成，不是从真实程序捕获；数据页为零填充。这与“测试
  真实程序状态”的快照在覆盖的行为上有差距。
- 端态只在同一台机器的 4 个 NUMA 核上比对，没有跨微架构验证；“端态完全
  一致才收录”会丢弃论文所述最多约 20% 的多端态快照。

## 4. Player 实现偏差

- 论文命令序列 Map/Write/Protect/Execute/Checksum 全部实现；为了规模化，
  另加 `kOpRunAll` 把一次执行的命令合并为一个往返，并对标准 7 页布局使用
  固定地址 arena 复用映射（避免每次 mmap/munmap 的系统开销）。非标准布局
  回退到逐条映射，语义与论文一致。
- 快照入口使用内核信号帧（`rt_sigreturn`）恢复全部寄存器；glibc
  `getcontext/setcontext` 只恢复调用者保存子集，已在文档与代码注释说明。
- harness 编译为 PIE 并关闭 ASLR：否则非 PIE 二进制的 0x400000 段会与快照
  的任意地址（如 0x415135）冲突，导致端态依赖 driver 二进制大小——这是
  实现过程中实际发现并修复的缺陷。快照地址窗口（0x10000000/0x20000000/
  0x30000000）之外仍可能有 harness 自身的高地址映射，理论上极小概率被
  快照访问到；未做进一步地址空间隔离。
- 超时是 3 秒墙钟时间，不是论文的 3 秒 CPU 时间；单线程快照两者接近，但
  高负载下墙钟更保守。
- `pstate` 比较包含全部位。一次 128 核采样中出现过 1 次不可复现的 `pstate`
  差异（约 27 万次执行中 1 次），复测 400 次未复现；未确认根因，未把它当作
  缺陷。

## 5. 检测与反馈

- **没有发现真实硬件缺陷**。所有“检出”都来自 `--inject` 合成注入，仅用于
  验证 checker→隔离→复测→入语料闭环；不能表述为硬件缺陷。
- 合成注入修改的是 harness 返回的观测值，不修改真实 CPU 行为；它验证的是
  检测/隔离管线，不是故障模型。
- 没有与其他 SDC 工具对比，也没有论文 §2.6 的“已知坏机器”池。

## 6. 性能口径

- 单核回放约 9,000 快照/秒（2000 条 0.22 秒）；128 核 sampled 实测约
  100,000 次/秒（约 790 次/核/秒），即 128 核相对单核只有约 11 倍扩展。
  原因是每核一个 driver 线程 + 一个 harness 进程、每页校验和与零填充的
  内存带宽，以及调度竞争。论文没有给出吞吐数字，无法直接比较。
- 4 核窗口实测约 22,000–45,000 次/秒（随语料/模式变化），2 分钟约 260–540
  万次执行；论文的 50/1000 批处理在 I/O 摊薄上成立（实测每次执行读取约
  110–240 字节，而单条快照约 1–2 KiB）。

## 7. 结论

与论文一致的：snapshot 数据模型、driver/harness 双进程 player、三类代理的
“fuzzing by proxy”、缺页补映射/去不确定性/跨核端态录制、50/1000 批处理、
4 核 2 分钟窗口、隔离反馈闭环。

与论文不一致的：ISA（ARM64 vs x86-64）、代理、真实机群与缺陷数据、语料规模
与覆盖度、附录缺陷模式、真实缺陷检出。任何对外表述都不得跳过这些差距。
